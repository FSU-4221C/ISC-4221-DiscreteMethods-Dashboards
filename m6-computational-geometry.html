    Key idea

    Every algorithm in this module reduces a hard shape to a bag of triangles, does something easy to each triangle, and adds the answers up. Area, containment, distance, centroid and integration all follow that one pattern. The only genuinely new machinery is how you choose the triangles.

    6.1 Points and Lines

    Nine topics that build one small coordinate system. Given two points you get a line; given a line you get an s axis along it and a t axis across it; and with those two numbers you can answer distance, containment, nearness and orientation questions for any point in the plane. Final Exam Question 1 is exactly this section.

    6.1.1 Representing points

    # Permalink to topic 6.1.1, Representing points
    • ● Slides
    • ✚ New for 2026

    Points are the atoms of geometry: every geometric object is a collection of points that satisfy some property. Unless you are working on a special surface such as a sphere, you describe a point by its Cartesian coordinates — (x, y) in the plane, (x, y, z) in space, and as many numbers as you like in higher dimensions.

    When several points are in play, subscript them: z2 is the z coordinate of the second point. Computationally you keep the coordinates of one point together in a single variable rather than as loose scalars, because every formula in this module is written as vector arithmetic and every one of them then works unchanged in any dimension.

    Python One point, one variable 
    p = np.array([x, y, z])     # a single 3-D point
P = np.array([[0, 4],       # several 2-D points, one per row
              [3, 1],
              [7, 2]])

    6.1.2 Representing lines (parametric form)

    # Permalink to topic 6.1.2, Representing lines in parametric form
    • ● Slides
    • ★ Final, Question 1(a)
    • ✚ New for 2026

    “A line is the infinite set of points which…” — we all know one when we see one, and that is not good enough for a computer. Two points p1 and p2 determine a line: start at p1 and travel in the direction of p2. A geometric direction is a mathematical vector, and the obvious vector here is the difference of the two points.

    Parametric form of a line

    v12 = p2 − p1
    p(s) = p1 + s v12 = p1 + s (p2 − p1) = (1 − s) p1 + s p2

    p1, p2
    the two points that define the line; neither is special except that p1 is the origin of the parameter
    v12
    the direction vector of the line, pointing from p1 toward p2
    s
    the parameter: how far to travel along v12, in units of v12

    Five things this formula buys you, in the slides’ own order. It can be taken as the definition of the line. You can compute points on the line. You can solve for s given a desired x or y. You can guess immediately what a line looks like in one, three or any number of dimensions — nothing above changes. And s behaves like a coordinate: in any dimension, one number locates a point on the line.

    Definition

    Parameter
    An index that keeps track of all the points of an object in an orderly way. Here s indexes the line; in 6.2.8 the barycentric weights α, β, γ index a triangle the same way.

    6.1.3 The s coordinate along a line

    # Permalink to topic 6.1.3, The s coordinate along a line
    • ● Slides
    • ★ Final, Question 1(b)
    • ✚ New for 2026

    A line is really a one-dimensional object, because a single number indexes all of its points. That number is s, and its value tells you where you are:

    • s = 0 is p1 and s = 1 is p2, always.
    • 0 ≤ s ≤ 1 covers the points between them. Restricting to that range turns the line into a line segment.
    • s < 0 and s > 1 are the points off each end.
    • If you know ‖p2 − p1‖, then s measures the signed distance from p1 in units of that basic distance.

    The worked example the slides use throughout is the line through p1 = (0, 4) and p2 = (3, 1), so v12 = (3, −3).

    6.1.4 Distance via the dot product

    # Permalink to topic 6.1.4, Distance via the dot product
    • ● Slides
    • ★ Final, Question 1(b)
    • ✚ New for 2026

    Going forward is easy: given p1, p2 and s you get p(s). The inverse question is the useful one. Given the (x, y) of a point known to be on the line, what is its s?

    Route one, distances. s is the signed ratio of the distance from p1 to p against the distance from p1 to p2.

    Distance method

    d(p1, p2) = √(x2−x1)2 + (y2−y1)2     s = ± d(p1, p) ⁄ d(p1, p2)

    d(∗, ∗)
    ordinary Euclidean distance between two points
    ±
    the sign has to be recovered separately — this is the method’s weakness, and 6.1.5 deals with it

    Route two, the dot product. Better, because it produces the sign for free and it never needs a square root.

    Dot-product method

    v1 · v2 = ‖v1‖ ‖v2‖ cos α   ⇒   s = (v1 · v2) ⁄ (v1 · v1) = ‖v2‖ cos α ⁄ ‖v1‖

    v1
    p2 − p1, the direction of the line
    v2
    p − p1, the offset of the query point
    α
    the angle between the two vectors
    v1 · v1
    equals ‖v1‖2, which is why the square roots cancel

    The slides’ worked example takes p1 = (0, 4), p2 = (3, 1) and p = (−2, 6). The distance method gives d(p1, p2) = √18 = 3√2 and d(p1, p) = √8 = 2√2, so |s| = 2/3. The dot product gives v1 = (3, −3), v2 = (−2, 2), and s = −12 / 18 = −2/3 — including the sign.

    Python line_parameter_s, from P1 frame 23 
    def line_parameter_s(p1, p2, p):
    v1 = p2 - p1
    v2 = p  - p1
    return np.dot(v2, v1) / np.dot(v1, v1)

    Common mistake

    The listing on the slide ends with a stray end, which is MATLAB and is a syntax error in Python. The version above is the same arithmetic with the artefact removed. Two more listings in this module have the same problem — see 6.2.4 and 6.2.6.

    Step through both routes, with a point you place yourself, in the s and t coordinates demo under 6.1.8.

    6.1.5 Sign and interpretation of s

    # Permalink to topic 6.1.5, Sign and interpretation of s
    • ● Slides
    • ★ Final, Question 1(b)
    • ✚ New for 2026

    The dot product carries the sign because cos α does. If p lies on the p2 side of p1, then v1 and v2 point the same way, cos α = +1 and s is positive. If p lies on the far side of p1, the two vectors oppose, cos α = −1 and s is negative.

    Key idea

    s is not the distance of p from p1, for two reasons. Scale: the s coordinate of p2 is 1 no matter how far away p2 is. Sign: some points have negative s, and a distance is never negative. s is a signed relative distance.

    Recovering a true distance from s

    d(p, p1) = |s(p)| ⋅ d(p2, p1)

    |s(p)|
    the magnitude of the parameter, discarding which side it is on
    d(p2, p1)
    the length of the defining segment — the “unit” the parameter counts in

    Of course, if you already have the coordinates of p1 and p, you would just compute the distance directly. The point of the formula is that it tells you what s means.

    6.1.6 Vectorized computation

    # Permalink to topic 6.1.6, Vectorized computation
    • ● Slides
    • ✚ New for 2026

    Nothing in line_parameter_s says the points are two-dimensional, because nothing needs to. NumPy infers the shape. Feed it three-dimensional points and it still answers, and the answer is still right:

    Python The same function in three dimensions, and on a batch 
    >>> line_parameter_s(np.array([1,5,3]), np.array([4,2,9]), np.array([2,4,5]))
0.3333333333333333

# A whole batch of query points at once. This works only because the
# points are one per ROW and v1 is 1-D, so the contraction lands on the
# coordinate axis. Store the points as COLUMNS instead — the MATLAB
# convention the original deck uses — and the same expression contracts
# the wrong axis and returns the wrong shape without complaining.
def line_parameter_s_batch(p1, p2, P):
    v1 = p2 - p1                       # shape (d,)
    V2 = P - p1                        # shape (n, d)
    return (V2 @ v1) / np.dot(v1, v1)  # shape (n,)

    Note

    The original MATLAB deck spends three frames on the same idea from the other side: it insists p1 and p2 be column vectors, shows the scalar version failing on a batch of points, and rewrites it with repmat. The pedagogical point survives the change of language — a formula written in vector arithmetic scales to a whole array only if you are explicit about which axis is being contracted.

    The obvious way to break the function is not a dimension mismatch at all. It is to hand it a point that is not on the line — which is 6.1.7, and turns out to be a feature.

    6.1.7 Points off lines

    # Permalink to topic 6.1.7, Points off lines
    • ● Slides
    • ★ Final, Question 1(c)
    • ✚ New for 2026

    Take the same line through (0, 4) and (3, 1), and hand each method the point q = (7, 2), which is nowhere near it. Both methods return a number. The numbers are different, and the difference is the whole lesson.

    What each method returns for a point off the line

    Two methods, one off-line point q = (7, 2), against the line through (0, 4) and (3, 1)
    Method Value returned What that value actually is
    Distance ratio √53 ⁄ 3√2 ≈ 1.716 the s of a point on the line that happens to be the same distance from p1 as q is — they lie on a common circle centred at p1. Not useful.
    Dot product 27 ⁄ 18 = 1.5 the s of the point on the line nearest to q, reached by dropping a perpendicular. Very useful.

    So the dot product quietly assigns an s coordinate to every point of the plane, not just to points on the line — it is the projection onto the line’s direction. Knowing only s still leaves a whole perpendicular line of candidates, which is why a second coordinate is needed.

    6.1.8 Distance from a point to a line

    # Permalink to topic 6.1.8, Distance from a point to a line
    • ● Slides
    • ★ Final, Question 1(d)
    • ✚ New for 2026

    We want a coordinate t that is 0 when the point is on the line, 1 when it is one unit away, and so on. One route is mechanical: compute s, form the nearest point p(s), and measure. The slides give it as three lines:

    Pseudocode t the long way round 
    s = line_parameter_s(p1, p2, q)
p = p1 + s * (p2 - p1)
t = norm(p - q)

    The better route computes t directly, with a second dot product. Two vectors are perpendicular exactly when their dot product is zero, and for a non-zero v = (vx, vy) in the plane a perpendicular is w = (−vy, +vx), because v · w = −vxvy + vyvx = 0.

    The perpendicular coordinate

    w = (−vy, vx) ⁄ ‖v‖,   r = q − p1   ⇒   t = w · r = ‖q − p1‖ cos α

    v
    the direction of the line, p2 − p1
    w
    the unit normal: v rotated a quarter turn and scaled to length 1
    r
    the offset of the query point from p1
    t
    the signed perpendicular distance; |t| is the distance from q to the line

    If q is on the line, t = 0. Otherwise |t| is the side of a right triangle with vertex p1, hypotenuse q − p1, and adjacent side running along the line. The slides verify both routes agree on the running example:

    6.1.9 Perpendicular axis, decomposition

    # Permalink to topic 6.1.9, Perpendicular axis and decomposition
    • ● Slides
    • ✚ New for 2026

    Scale v to unit length as well and you have an orthonormal frame with origin at p1: a pair of perpendicular unit vectors that behave exactly like x and y axes, but aligned with the line instead of with the page.

    Decomposition and composition

    ‖v‖ = ‖w‖ = 1,  v · w = 0
    decompose:  ŝ = r · v,  t = r · w
    compose:  r = ŝ v + t w,  ‖r‖2 = ŝ2 + t2

    r
    q − p1, for any point q in the plane
    v
    the unit direction along the line — the “x axis”
    w
    the unit normal — the “y axis”
    ŝ
    the along-line coordinate in true length units: ŝ = s ⋅ ‖p2 − p1‖

    Common mistake

    The module uses two different normalisations of the along-line coordinate and switches between them without warning. Up to the perpendicular-axis frames it is the unnormalised s, for which s(p2) = 1 whatever the length of the segment. From the orthonormal frame onward it is ŝ = s ⋅ ‖p2 − p1‖, measured in true length. The triangle-distance material in 6.2.9 then goes back to the unnormalised one, because its test is “is 0 < s < 1?”. Check which one a formula wants before you substitute.

    The sign of t is arbitrary in the sense that choosing −w instead of w flips every value; the usual choice is the right-hand rule. What is not arbitrary is that the sign partitions the plane into three classes — left of the line, on the line, right of the line. Adapting line_parameter_t to return just that classification gives line_side(p1, p2, p), an orientation test, and orientation is the engine of nearly everything in 6.2, 6.3 and 6.4.

    6.2 Triangles

    You are given the coordinates of three vertices. Everything else — the sides, the angles, the area, the centroid, whether a point is inside, how far away it is, and how to drop random points in evenly — has to be computed from those six numbers. The triangle is the workhorse: once a shape is cut into triangles, every one of these formulas applies to the pieces.

    A side length is just the distance between two vertices, so Pythagoras does it — and that is the same distance formula as 6.1.4, not a new idea.

    Side length

    AB2 = (xa − xb)2 + (yb − ya)2

    A, B
    two vertices, at (xa, ya) and (xb, yb)
    AB
    the length of the side joining them

    The angles need the law of cosines. Write α, β, γ for the interior angles at A, B, C.

    Law of cosines, solved for the angle at A

    BC2 = AB2 + AC2 − 2 AB AC cos α   ⇒   α = cos−1 ( (AB2 + AC2 − BC2) ⁄ (2 AB AC) )

    α
    the interior angle at vertex A, between sides AB and AC
    BC
    the side opposite A — the one the angle “opens onto”

    Common mistake

    Floating-point error can push the argument of arccos a hair outside [−1, 1] for a very thin triangle, and NumPy returns nan rather than complaining. Clip it: np.arccos(np.clip(c, -1.0, 1.0)).     6.2.2 Centroid

    # Permalink to topic 6.2.2, Centroid
    • ● Slides
    • ▣ Lab 12
    • ✚ New for 2026

    Join each edge midpoint to the opposite vertex. The three lines — the medians — meet at a single point, the centroid. Constructing it that way sounds like work: three line formulas and an intersection. It is not.

    Centroid of a triangle

    CM = (A + B + C) ⁄ 3 = ( (xa+xb+xc) ⁄ 3,  (ya+yb+yc) ⁄ 3 )

    A, B, C
    the three vertices, as coordinate pairs
    CM
    the centroid — the average of the vertices, coordinate by coordinate

    Worked example from P2 frame 7: for A = (0, 0), B = (10, 2), C = (3, 8) the centroid is (13/3, 10/3) ≈ (4.33, 3.33), and the three edge midpoints are mid(AB) = (5, 1), mid(BC) = (13/2, 5) and mid(CA) = (3/2, 4).

    Common mistake

    The slide says “any line through the centroid divides the triangle into two pieces of equal area”. That is true of the three medians only. A general line through the centroid splits a triangle somewhere between 4/9 and 5/9 of the area — never worse than that, which is the actual, and rather nicer, theorem. Do not quote the stronger claim on an exam.

    The centroid comes back twice: as the check point of the quadrature map in 6.5.9, and as the single evaluation point of the centroid rule in 6.5.10.

    6.2.3 Area

    # Permalink to topic 6.2.3, Area
    • ● Slides
    • ▣ Lab 12
    • ✚ New for 2026

    “Half base times height” needs a ruler and a protractor. With coordinates you want the area to fall out of arithmetic, and it does: the area is half the magnitude of the cross product of any two sides.

    Area from coordinates

    area = ½ |AB × AC| = ½ | det [ xa xb xc ; ya yb yc ; 1 1 1 ] |
    = ½ | xa(yb−yc) + xb(yc−ya) + xc(ya−yb) |

    AB, AC
    the side vectors B − A and C − A
    ×
    the vector cross product; in general its result is a vector and the area is its magnitude
    det […]
    the 3×3 determinant whose first two rows are the x and y coordinates and whose third row is all ones

    The first form is independent of dimension: it works unchanged for a triangle sitting in three-dimensional space. The determinant form is two-dimensional only. Both give 20 for the running example [xa, xb, xc] = [4, 8, 0], [ya, yb, yc] = [1, 3, 9].

    np.cross(u, v) takes the cross product of two three-dimensional vectors and np.linalg.norm(u) gives a magnitude. A plane triangle is promoted to three dimensions by appending a zero z coordinate.

    Two errors in the slide’s own listing, both corrected above. It calls cross(AC, BC), but BC is never defined — the intended expression is cross(AB, AC). And it says the magnitude of a vector is np.norm(u); there is no such function. It is np.linalg.norm(u). The listing also uses % for comments, which is MATLAB; Python uses #.

    6.2.5 Orientation (clockwise / counter-clockwise)

    # Permalink to topic 6.2.5, Orientation, clockwise or counter-clockwise
    • ● Slides
    • ✚ New for 2026

    Why did the area formulas need absolute values? Because the determinant already knows something the area does not: the order you listed the vertices in. List them clockwise and the result is negative; list them counter-clockwise and it is positive.

    Orientation

    orientation(A, B, C) = sign(AB × AC)

    +1
    counter-clockwise, the mathematical convention; the absolute values in 6.2.3 can then be dropped
    −1
    clockwise
    0
    degenerate — the three points are collinear

    Key idea

    Orientation is not bookkeeping, it is the primitive. Point-in-triangle (6.2.6), the ear test (6.3.6) and gift wrapping (6.4.3) are all built from nothing but the sign of a cross product. Get the vertex order wrong and all three invert silently.

    6.2.6 Inside or outside a triangle

    # Permalink to topic 6.2.6, Inside or outside a triangle
    • ● Slides
    • ▣ Lab 12
    • ✚ New for 2026

    Is point P inside triangle T? You can answer by looking at a picture. You cannot look at a million cases, and you cannot look at all in four dimensions — so you need an algorithm that never draws anything.

    Definition

    Triangle Contains Point
    A point P is inside a triangle T if, and only if, it is “to the left of” all three sides of T, where the sides are walked in counter-clockwise vertex order.

    “To the left of” is the sign of t from 6.1.9, and the test needs no square roots and no normalising: only the sign matters, so the normal need not be a unit vector.

    Python line_side and triangle_contains 
    def line_side(p1, p2, p):
    """1 if p is on or to the left of the ray p1 -> p2, else 0."""
    v1 = p2 - p1
    v2 = p  - p1
    nv = np.array([-v1[1], v1[0]])   # rotate v1 a quarter turn: counterclockwise!
    t  = np.dot(nv, v2)              # no need to normalise nv
    return int(t >= 0)

def triangle_contains(tri, p):
    return (line_side(tri[0], tri[1], p)
            and line_side(tri[1], tri[2], p)
            and line_side(tri[2], tri[0], p))

    Common mistake

    6.2.7 Walking along vertices

    # Permalink to topic 6.2.7, Walking along vertices
    • ● Slides
    • ✚ New for 2026

    Here is the argument behind the theorem, in the slides’ own image. List the vertices counter-clockwise and walk the boundary: A to B, then B to C, then C back to A. Your left hand always points into the triangle. So any point inside is on your left the whole way round — all three tests return 1.

    The converse is the useful half. A point outside might still be to the left of one side, or even of two. But it will always be to the right of at least one. That single failing test is what the region codes in 6.2.10 record, and it is also what tells you which edge to measure to in 6.2.9.

    Walking the boundary is worth internalising because it generalises. In 6.3.6 you walk a polygon’s vertices testing for ears; in 6.4.3 you walk the hull of a point cloud. Same motion, same left-hand rule.

    6.3.2 Convex polygons

    # Permalink to topic 6.3.2, Convex polygons
    • ● Slides
    • ✚ New for 2026

    Informally, a convex polygon has no dents. The strict definition does not mention dents at all, and it is the one that generalises to any shape in any dimension.

    Definition

    Convex
    An object C is convex if and only if, whenever two points p1 and p2 are elements of C, so is every point p = tp1 + (1−t)p2 for 0 ≤ t ≤ 1 — that is, the whole segment joining them.

    That expression is the parametric line of 6.1.2 written with the parameter running the other way. Triangles, circles, squares and regular pentagons are convex. A star is not, and neither are most letters of the alphabet — the exceptions worth arguing about are the ones with no enclosed hole and no notch.

    Convexity matters here for one practical reason: if a polygon is convex, every three consecutive vertices form an ear, so ear clipping never has to search. See 6.3.5.

    Every well-behaved polygon — no holes, no crossing edges — can be triangulated, and the count is fixed no matter how you do it.

    diagonal

    6.3.5 “Polygons have ears” theorem

    # Permalink to topic 6.3.5, the Polygons have ears theorem
    • ● Slides
    • ✚ New for 2026

    Definition

    Ear of a polygon
    A triangle formed by three consecutive vertices of the polygon, such that two of its edges are edges of the polygon and the third edge lies completely inside the polygon. An ear can be sliced off, reducing the vertex count by one.

    Theorem (Meisters, 1975)

    If P is a simple polygon — no internal holes and no edge crossings — with at least 4 vertices, then P is guaranteed to have at least two distinct ears.

    That guarantee is what makes decrease and conquer terminate: there is always something to cut. It also answers the other half of the question — yes, there can be vertices you cannot cut off, namely reflex ones and ones whose closing diagonal would have to cross the interior. And if P is convex, every three consecutive vertices form an ear, so the search is trivial.

    The algorithm is five lines, and the ear theorem is what proves it terminates.

    Pseudocode Ear slicing, from P2 frame 34 
    start with a polygon of N vertices and 0 diagonals
while N > 3:
    locate an ear: three consecutive vertices B, C, D
    add the diagonal B-D to the list
    remove C from the polygon; N = N - 1
# after N-3 ears, 3 vertices remain: the last ear

    “Locate an ear” is the only line that needs unpacking. Suppose A, B, C, D, E are consecutive in counter-clockwise order. Then B, C, D form an ear if all four of these hold:

    1. triangle BCD has positive area — equivalently, it is counter-clockwise, so C is a convex vertex;
    2. the open segment BD does not intersect any edge of the polygon;
    3. the segment BD lies “between” BA and BC;
    4. the segment DB lies “between” DC and DE.

    Conditions 2 to 4 are all saying one thing: the closing diagonal must stay inside. For a simple polygon they collapse into a single test that is far easier to implement — no other polygon vertex may lie inside or on triangle BCD. That is the test the demo below uses, and it is why vertex 2 of the exam polygon is rejected: the diagonal 1–3 runs exactly through vertex 4, so vertex 4 lies on the candidate triangle.     6.3.9 Sampling polygons

    # Permalink to topic 6.3.9, Sampling polygons

    If the polygon is triangulated you can sample it by sampling one of its triangles. The only subtlety is which one: a triangle with twice the area must be picked twice as often, or the samples pile up in the small triangles.

    Pseudocode Area-weighted polygon sampling, from P2 frame 42 
    ATOTAL = sum of A(I) over all triangles I
r1 = rand()
B  = r1 * ATOTAL
find the smallest J such that A(1) + ... + A(J) >= B
pick a random point from triangle J   # by 6.2.8

    Step three is a cumulative-sum search, and it is exactly inverse-transform sampling of a discrete distribution — the same trick as M2. Using no triangles gives 0 area and using them all gives ATOTAL, so some J must be the first to reach B.

    Both halves have to be right. Choose the triangle uniformly instead of by area and the samples clump; choose the triangle correctly but sample inside it with Lab 12’s Algorithm 1 and they clump toward every triangle’s centroid instead. The triangle sampler demo quantifies the second failure mode.

    6.4.2 Convex hull definition and convexity

    # Permalink to topic 6.4.2, Convex hull definition and convexity
    • ● Slides
    • ✚ New for 2026

    Definition

    The convex hull problem
    Find the convex polygon of smallest perimeter which contains a given set of points.

    Two observations turn that into something computable. First, the fence posts always sit at data points — bending anywhere else wastes fence. Second, the smallest-perimeter requirement forces the result to be convex, because any dent could be cut across for a shorter boundary. So for a finite point set the convex hull is a polygon: every vertex is a data point and every edge is a straight segment.

    An equivalent definition, and the one that generalises: the convex hull of a set of points is the smallest convex shape that contains them. Convex here is the definition from 6.3.2 — if p and q are in the shape, so is every point on the segment between them. Note that the hull is not just its boundary; it is all the points inside as well.

    Key idea

    The wrapping picture is the algorithm in disguise. Put a rope around a group of trees and pull it tight: it touches some trees, skips others, and ends up convex without anyone deciding it should. Gift wrapping in 6.4.3 is that rope, one tree at a time.

    6.4.3 The gift-wrapping algorithm (step by step)

    # Permalink to topic 6.4.3, The gift-wrapping algorithm step by step
    • ● Slides
    • ✚ New for 2026

    You can always name one hull vertex for free: the point with the smallest x coordinate, ties broken by the smallest y. Nothing lies to its left, so it cannot be interior. Call it H1.

    Now find the next one. Build the polygon counter-clockwise, so there are N − 1 candidate edges out of H1, one to each remaining point.

    The wrapping test

    The correct edge (H1, H2) is the unique line through H1 to some vertex V with the property that all data points lie to the left of it. Repeat from H2, and stop when the wrap returns to H1.

    “To the left of” is line_side from 6.2.6 again — the entire algorithm is one orientation test in a double loop. That also tells you its cost: for each of the h hull vertices you test N candidates against N points, so gift wrapping runs in O(h N) if you keep the count and O(h N2) written naively as above. It is fast when the hull is small and slow when nearly every point is on it.

    Nothing in the definition of the convex hull mentions two dimensions. It is the smallest convex set containing the data, whatever the data are, and the algorithms generalise — in higher dimensions the boundary is made of facets rather than edges, which is what MATLAB’s convhulln and SciPy’s ConvexHull both handle.

    Three uses that are not about shape at all:

    • A description of a dataset’s support. The hull is the region your data actually occupy. A prediction made outside it is extrapolation, whatever the model says.
    • Synthesising realistic data. Sample inside the hull of the real observations, by the polygon method of 6.3.9, and every synthetic point is a plausible combination of things you have actually seen.
    • A cheap containment test. Checking a point against a hull is far cheaper than against the raw data, so hulls are used as a first pass before an exact test — the same role a bounding box plays for the hull itself.

    6.5 Delaunay Triangulation & Quadrature

    Two halves that turn out to be one thing. First: given a bare set of points, how do you triangulate them, and what makes one triangulation better than another? Second: given a triangulation, how do you integrate a function over the region it covers? Lab 13 runs both halves end to end on a network of air-quality sensors, and the answer it gets is wrong in an instructive way.

    6.5.1 The point-set problem

    # Permalink to topic 6.5.1, The point-set problem
    • ● Slides
    • ▣ Lab 13
    • ✚ New for 2026

    Draw some points on the plane. Connect two of them with a line. Connect two more — but you are not allowed to cross a line you have already drawn. Keep going until no further line can be added.

    Two facts about where you end up, and both are surprising the first time. Whatever choices you made, when no more lines can be drawn every point is a vertex of triangles — you always finish with a triangulation. And a second run, drawing the lines in a different order, gives a different picture. There are many triangulations of the same point set.

    How many triangles you always get

    number of triangles = 2n − 2 − h

    n
    the number of points, all of which end up as vertices
    h
    how many of them lie on the convex hull

    That count follows from Euler’s formula and does not depend on which triangulation you built — the same invariance you saw for polygons in 6.3.4. Lab 13 asks you to predict it before you run Delaunay, which is a good check that your mesh is a mesh.

    6.5.2 What makes a “good” triangulation

    # Permalink to topic 6.5.2, What makes a good triangulation
    • ● Slides
    • ▣ Lab 13
    • ✚ New for 2026

    “Better” depends entirely on what the triangulation is for.

    • If the connecting lines are roads, you want the triangulation with the shortest total length.
    • If the triangles are patches of territory, or elements in a simulation, you dislike triangles with a very small angle.

    Definition

    Sliver
    A triangle with a very small minimum angle — long and thin. Slivers are bad for interpolation because a small change in one vertex value produces an enormous gradient (6.5.12), and they are numerically unstable because the 3×3 system that defines the linear interpolant becomes nearly singular.

    For graphics and most computational applications, avoiding small angles is the common criterion, and that single choice pins the triangulation down almost uniquely — which is 6.5.3.

    6.5.3 Delaunay triangulation

    # Permalink to topic 6.5.3, Delaunay triangulation
    • ● Slides
    • ▣ Lab 13
    • ◐ Also taught in M5
    • ✚ New for 2026

    The Delaunay triangulation of a set of points is the (usually unique) triangulation that does the best job of avoiding small angles. Stated strictly, it is a maximin condition.

    The Delaunay condition

    θ(T) ≤ θ(T∗)   for every triangulation T of the same points

    T
    any triangulation of the point set
    θ(T)
    the smallest angle occurring in any triangle of T
    T∗
    a Delaunay triangulation: the one whose worst angle is as large as it can be made

    There is an equivalent local test that is much easier to compute, and it is what the demo below uses. A triangulation is Delaunay exactly when the circumcircle of every triangle is empty — contains no other point of the set. Where that fails for two adjacent triangles, swapping their shared diagonal fixes it locally and can never make the smallest angle worse. Repeat until nothing fails: this is Lawson’s flip algorithm, and it converges to T∗.

    Python Delaunay and its plot, from P3 frame 25 
    from scipy.spatial import Delaunay

triangulation = Delaunay(points)

plt.triplot(points[:, 0], points[:, 1], triangulation.simplices)
plt.plot(points[:, 0], points[:, 1], 'ro')   # the points themselves

    Common mistake

    Delaunay does not promise you well-shaped triangles. It maximises the minimum angle among triangulations of the same points, which is a much weaker statement than “no slivers”. On Lab 13’s 120 random sensors the smallest angle in the Delaunay mesh is under a tenth of a degree, and roughly half the triangles have a minimum angle below 30°. If you need well-shaped triangles you have to move or add points, not re-triangulate them. The demo reports both numbers so you can see it happen.

    The same object appears in M5 as the dual of the Voronoi diagram: each Delaunay edge joins the two generators whose Voronoi cells share a boundary. Same construction, two names, depending on whether you care about the cells or about the triangles.

    6.5.4 Integration over irregular domains

    # Permalink to topic 6.5.4, Integration over irregular domains
    • ● Slides
    • ▣ Lab 13
    • ✚ New for 2026

    In a calculus course the functions get exotic and the region stays simple: an interval, or a box. Real problems are the other way round. The slides’ example is the outline of a hand, captured as about sixty boundary points joined by straight segments.

    Computing the area of that hand is the same thing as integrating the constant function:

    Two integrals over the same awkward region

    area = ∫∫hand 1  dx dy      volume = ∫∫hand f(x, y)  dx dy

    f(x, y)
    the thickness of the hand at each point, if you are after its volume; the constant 1 if you are after its area
    hand
    the region — a polygon with about sixty vertices and no formula

    The difficulty comes not from the function but from the region. And the fix is the one from 6.3.3: triangulate, do something easy on each triangle, add up. For the area, “something easy” is 6.2.3 and you are finished. For a varying f you need 6.5.5 onwards.

    6.5.5 Approximate integration over triangles

    # Permalink to topic 6.5.5, Approximate integration over triangles
    • ● Slides
    • ▣ Lab 12, Lab 13
    • ✚ New for 2026

    Breaking the region into triangles reduces complicated geometry to a sum of simple geometries, and leaves exactly one problem: approximate the integral of a function over one general triangle.

    For the special case where two sides align with the x and y axes you can get exact formulas by nested integration. For the hand — or for 227 arbitrary Delaunay triangles — that is not realistic. Instead you estimate the integral as a weighted average of the function’s value at a few prescribed points. That technique is called quadrature.

    There is a second, cruder route that you already have: Monte Carlo. Sample N points uniformly in the triangle by 6.2.8, average the function values, multiply by the area. It is Lab 12 Problem 2, and it converges like 1 / √N — so to gain one decimal digit you need a hundred times the work. A six-point quadrature rule beats ten thousand random samples on a smooth function, which is why the rest of this section exists.

    Note

    Monte Carlo is not obsolete — it is the method that survives into high dimensions, where the number of quadrature points a tensor rule needs explodes. In two dimensions, on a smooth function, quadrature wins comfortably. Compare the two yourself: the triangle sampler demo reports the Monte Carlo estimate of the integral of x2, and the quadrature demo reports the rule-based one for the same function.

    6.5.6 Quadrature rules

    # Permalink to topic 6.5.6, Quadrature rules
    • ● Slides
    • ▣ Lab 12
    • ✚ New for 2026

    Definition

    Quadrature rule
    A set of n points (xi, yi) and weights wi, used to estimate the integral of f over the unit triangle T01.
    Precision
    The largest degree p such that the rule is exact for every polynomial of degree p or less.
    A quadrature rule on the unit triangle

    ∫∫T01 f(x, y)  dx dy ≈ area(T01) ⋅ ∑i=1n wi f(xi, yi)

    T01
    the unit triangle with vertices (1, 0), (0, 1) and (0, 0); its area is ½
    n
    how many function evaluations the rule costs
    wi
    the weights; they sum to 1, so the bracket is a weighted average of function values and the area factor turns it into an integral

    Everything is defined once on T01 and then carried to whatever triangle you actually have by the linear map of 6.5.9. That is the whole design: one table of numbers, reused for every triangle in the mesh.

    6.5.7 Rule of precision 1

    # Permalink to topic 6.5.7, Rule of precision 1
    • ● Slides

    • ✚ New for 2026

    The simplest useful rule averages the function at the three vertices. It is exactly right if f is a constant or a linear function, and it has the pleasant property that it is obvious how to use it on a general triangle — the vertices map to the vertices.

    Points and weights of the precision-1 vertex rule

    The vertex rule on T01: three points, equal weights, precision 1
    Point xi yi wi
    1101/3
    2011/3
    3001/3

    Because it is only precise for constants and linears, it is natural to look for rules that are “more precise” — that get the exact answer for any polynomial up to some higher degree. That is 6.5.8.

    Note

    There is a second precision-1 rule that costs only one evaluation: put a single point at the centroid with weight 1. Both are exact for linear f, and on a curved function they usually err in opposite directions — the vertex rule high where the function is convex, the centroid rule low. Lab 13 uses the centroid version; 6.5.10 explains why the choice matters there.

    1 of degree 0, 2 of degree 1, 3 of degree 2, 4 of degree 3 and 5 of degree 4
    6 evaluations

    6.5.10 Piecewise-linear quadrature

    # Permalink to topic 6.5.10, Piecewise-linear quadrature
    • ◐ Slides, partial
    • ▣ Lab 13, Problem 3
    • ✚ New for 2026

    Now suppose you do not have a formula for f at all — only its value at each mesh vertex, because each vertex is a sensor. Over each triangle, fit the unique linear function through the three vertex values and integrate that. Because the fit is linear, its integral has a closed form and needs no quadrature points beyond the vertices you already have.

    Two rules that are easy to confuse

    ∫T fP1 = area(T) ⋅ (f0 + f1 + f2) ⁄ 3      ∫T f ≈ area(T) ⋅ f(centroid of T)

    f0, f1, f2
    the measured values at the three vertices — all you have, in a sensor problem
    fP1
    the piecewise-linear (first-order finite-element) interpolant of those three values
    f(centroid)
    the true function evaluated at a new point — which requires the analytic formula, and is therefore not available in a genuine sensor problem

    Common mistake

    Lab 13 Problem 3(a) is headed “Piecewise-Linear Quadrature” but its stated method evaluates the true f at the centroid. Those are two different rules, they give different answers, and only the vertex-average one is physically available in the scenario the lab describes, where all you have is 120 sensor readings. Both are exact for a linear f, so on a smooth field they agree to a few per cent — which is how the discrepancy goes unnoticed.

    Neither rule is where the real error in Lab 13 comes from. See 6.5.11.

    6.5.11 Constructing a field from scattered sensor data

    # Permalink to topic 6.5.11, Constructing a field from scattered sensor data
    • ○ Not in the slides

    • ✚ New for 2026

    This topic and the next appear in no deck in the module. Lab 13 is the only place in the course where they are taught, which makes this page the only written account of them.

    The scenario: a network of air-quality sensors is deployed in a non-uniform pattern across a region Ω = [0, 10] × [0, 6]. Each sensor reports a pollutant concentration. From 120 scattered readings, construct a continuous field over the whole region.

    The Lab 13 pollutant field

    f(x, y) = 20 exp( −((x−5)2 + (y−3)2) ⁄ 3 ) + 4 sin(1.5x) + 3 cos(2y)

    the exponential term
    a pollution plume — a Gaussian bump centred at (5, 3)
    the sine and cosine terms
    smaller-scale oscillatory variation standing in for regional atmospheric conditions

    The construction is three steps, and every one of them is a topic you already have. Triangulate the sensors by Delaunay (6.5.3). Over each triangle, fit the linear function through its three vertex readings — the P1 interpolant of 6.5.10. The pieces agree along shared edges, because two triangles sharing an edge share the two vertex values that determine the fit there, so the result is continuous across the whole mesh.

    Key idea — where Lab 13’s error actually comes from

    The mesh covers the convex hull of the sensors, not the region Ω. For 120 uniformly random sensors the hull covers roughly 90% of Ω, so an integral computed over the mesh is short by about 10% before any quadrature error is considered. Refining the quadrature rule cannot recover it: the missing corners of Ω carry no triangle at all. Adding four sensors at the corners of Ω would fix it in one line. Lab 13’s shipped solution reports a 9.8% relative error and concludes “the relative error is small, indicating good approximation quality” — read your own coverage number before you accept that.

    6.5.12 Gradient estimation on a triangulation

    # Permalink to topic 6.5.12, Gradient estimation on a triangulation
    • ○ Not in the slides
    • ▣ Lab 13, Problem 2(b)
    • ✚ New for 2026

    Once each triangle carries a linear function f = a + bx + cy, its gradient is (b, c) — constant inside the triangle, and generally discontinuous across edges. Recovering a, b, c is one 3×3 solve per triangle.

    The P1 gradient of one triangle

    [ 1 x0 y0 ; 1 x1 y1 ; 1 x2 y2 ] (a, b, c)T = (f0, f1, f2)T   ⇒   ∇f = (b, c)

    (xk, yk)
    the three vertices of the triangle
    fk
    the measured value at each vertex
    ∇f
    the gradient: constant over the triangle, so the field is piecewise linear and the gradient field is piecewise constant

    Written out, with D = twice the signed area:

    Closed form, which is what to implement

    D = (x1−x0)(y2−y0) − (x2−x0)(y1−y0)
    b = [ (f1−f0)(y2−y0) − (f2−f0)(y1−y0) ] ⁄ D
    c = [ (f2−f0)(x1−x0) − (f1−f0)(x2−x0) ] ⁄ D

    D
    twice the signed area of the triangle — the determinant of the 3×3 system. It vanishes for a degenerate triangle, which is why slivers are dangerous here

    Common mistake

    The gradient magnitude on a sliver is huge and means nothing: dividing a normal difference in readings by a nearly zero D manufactures a hotspot out of mesh quality, not out of the data. On Lab 13’s field the largest |∇f| is in the hundreds while the true gradient peaks around 10. Guard the solve, and read the minimum-angle histogram before you believe any “hotspot requiring refinement”.
