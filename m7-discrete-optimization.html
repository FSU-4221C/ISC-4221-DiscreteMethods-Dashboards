    7.1 Framing

    7.1.1 What is discrete optimization?

    # Permalink to topic 7.1.1, What is discrete optimization?
    • ● Slides
    • ◐ LP Visualizer, partial

    Optimization problems split into two families by the kind of value a variable is allowed to take. In continuous optimization you maximize or minimize a function of real variables; the function may not be differentiable, and constraints are optional. In discrete optimization — also called combinatorial optimization — you maximize or minimize over a finite set. The variables are usually integers, and are often restricted to just 0 or 1.

    Key idea

    The algorithms for the two families are typically vastly different. You cannot differentiate your way to the answer when the feasible set is a finite list of options, so discrete optimization is about searching that list cleverly instead of following a gradient.

    Definition

    Continuous optimization
    Maximize or minimize a function whose variables range over the real numbers. Constraints may or may not be present.
    Discrete (combinatorial) optimization
    Maximize or minimize a function whose variables range over a finite set — commonly the integers, and often only the values zero or one{0, 1}.

    This module concentrates on the case where the function to be maximized is linear in its unknowns and the constraints are also linear. That is linear programming, and it is the one large family of optimization problems that has a complete, reliable and fast algorithm — the simplex method of §7.5.

    7.1.3 Example problem catalog

    # Permalink to topic 7.1.3, Example problem catalog
    • ● Slides
    • ✚ New for 2026

    Three problems motivate the whole module.

    1. The knapsack problem

    There are n objects. Object i has value pi and weight wi. A hitchhiker's bag holds at most weight W. Which objects should go in the bag to maximize the value carried?

    Decision variable

    xi = 1 if object i is selected, xi = 0 otherwise

    i
    index of an object, 1 to n
    Knapsack problem

    max  p1x1 + p2x2 + ⋯ + pnxn
    subject to  w1x1 + w2x2 + ⋯ + wnxn ≤ W

    pi
    value of object i
    wi
    weight of object i
    W
    the capacity of the bag

    The scientific-computing version in the slides: you have run n simulations and can keep only W bytes of results. Let pi be the cost of recomputing simulation i and wi the storage it needs. Maximizing the sum of p i x iΣpixi keeps the results that would be most expensive to produce again.

    2. The travelling salesman problem

    A company sends a salesman to clients in several cities and knows every inter-city distance. Find the route that starts and ends at one particular city, visits every other city exactly once, and travels the shortest total distance.

    Distances behind figure 7.1.1

    Distances for figure 7.1.1: five cities, ten pairs. Every pair is joined, so the graph is complete.
    From To Distance
    AB3
    AC4
    AD2
    AE7
    BC4
    BD6
    BE3
    CD5
    CE8
    DE6

    With five cities and a fixed start there are 4! / 2 = 12 distinct tours, so this instance can be settled by listing them. That is exactly the trap the module is about: the count grows as (n − 1)! / 2 and enumeration stops being possible almost immediately. The travelling salesman problem is treated in full in M3 §3.6.

    3. The crew-scheduling problem

    Given a weekly flight schedule for one aircraft type, build the crew rosters. Each day a crew is assigned a duty period made of one or more linking flights, subject to limits on total flying time and to a minimum rest interval between flights. Daily schedules are then combined into weekly ones, subject to overnight rest and to every crew returning to base. The objective is to minimize crew pay, which is a function of flying time, duty-period length, guaranteed hours and so on.

    Key idea

    All three problems have the same shape: a linear quantity to optimize, a set of linear restrictions, and variables that are whole numbers or 0/1 choices. That shape is what the rest of the module formalises.

    Common mistake

    Counting the constraints. The slides count nine: the three nutrition inequalities plus the six upper bounds on servings. The six non-negativity conditions xi ≥ 0 are listed separately, because standard form treats them separately — see §7.2.6.

    7.2.5 General LP problem

    # Permalink to topic 7.2.5, General LP problem
    • ● Slides
    • ▣ Lab 14
    • ● LP Visualizer
    The general linear programming problem

    find x1, …, xn maximizing (or minimizing)
    z = c1x1 + c2x2 + ⋯ + cnxn
    subject to ai1x1 + ai2x2 + ⋯ + ainxn ≤ (≥, =) bi, i = 1, …, m

    n
    number of unknowns
    m
    number of constraints
    cj
    cost or profit coefficient of unknown j
    aij
    coefficient of unknown j in constraint i
    bi
    right-hand side of constraint i

    Definition

    Objective function
    The quantity z that is being maximized or minimized.
    Constraints
    The m linear restrictions the unknowns must satisfy. Each may be an inequality in either direction, or an equation.

    7.2.6 Standard form

    # Permalink to topic 7.2.6, Standard form
    • ● Slides
    • ▣ Lab 14
    • ● LP Visualizer

    An algorithm should not have to cope with four kinds of problem. Every LP is first rewritten into one shape.

    Definition

    Standard form
    An LP is in standard form when (i) the objective is being maximized, (ii) every unknown satisfies xi ≥ 0, and (iii) every other constraint is written with ≤.
    Conversion 1 — minimize becomes maximize

    min (c1x1 + ⋯ + cnxn)  ⟶  max (−(c1x1 + ⋯ + cnxn))

    Why
    The point that makes a quantity smallest makes its negative largest, so the location of the optimum does not move. Only the sign of the reported value changes.
    Conversion 2 — a ≥ constraint becomes ≤

    ai1x1 + ⋯ ≥ bi  ⟶  −ai1x1 − ⋯ ≤ −bi

    Why
    Multiplying an inequality by −1 reverses its direction.
    Standard form

    max z = c1x1 + ⋯ + cnxn
    subject to ai1x1 + ⋯ + ainxn ≤ bi, i = 1, …, m
    xj ≥ 0, j = 1, …, n

    z
    the objective function
    m
    number of constraints other than the non-negativity conditions
    n
    number of unknowns

    Common mistake

    Converting a minimization by negating the constraints instead of the objective. Only the objective is negated; the constraints define which points are allowed and must not move.

    7.3.1 LP with two unknowns (graphical solution)

    # Permalink to topic 7.3.1, LP with two unknowns, graphical solution

    With only two unknowns an LP can be solved by drawing. Graph each constraint as an equality: the lines bound a polyhedron, and every feasible solution lies inside it. Because z is linear it has no interior maximum, so the maximum must occur on the boundary of the polyhedron — and, as §7.3.2 makes precise, at a corner of it.

    The worked example of the slides

    max z = x + 2y
    subject to x ≤ 1,  y ≤ 1,  x + y ≤ 1.5,  x ≥ 0,  y ≥ 0

    Feasible region
    the unit square with its top-right corner cut off by the line x + y = 1.5
    Answer
    z = 2.5 at the vertex (0.5, 1)

    The slides walk the boundary edge by edge: along y = 0, z rises from 0 to 1 at (1, 0); along x = 1 it rises from 1 to 2 at (1, 0.5); along x + y = 1.5 it rises from 2 to 2.5 at (0.5, 1); along y = 1 it falls back to 2 at (0, 1). The largest value is at a corner.

    7.3.2 Feasible region

    # Permalink to topic 7.3.2, Feasible region
    • ● Slides
    • ▣ Lab 14
    • ● LP Visualizer

    The feasible region is the set of every point that satisfies every constraint. Each linear constraint keeps one side of a line, so the region is an intersection of half-planes — and an intersection of half-planes is always convex.

    Key idea

    The set of all feasible solutions to a linear programming problem is a convex polyhedron. Convex means that the straight segment between any two points of the set stays inside the set.

    The convexity test applied to each shape in figure 7.3.1

    The convexity test for figure 7.3.1: pick two points of the shape and ask whether every point of the segment joining them is also in the shape.
    Shape Outline in the figure Chord stays inside? Convex?
    RectangleSolidYesConvex
    HexagonSolidYesConvex
    Notched shapeDashedNo — it crosses the notchNot convex
    Five-point starDashedNo — it crosses between two pointsNot convex

    Extreme-point theorem

    For any bounded, feasible LP there exists an optimal solution that corresponds to an extreme point (a vertex) of the polyhedron containing all feasible solutions.

    This is the result the whole module rests on. It converts a search over infinitely many feasible points into a search over a finite list of vertices — and the simplex method of §7.5 is a disciplined way of walking that list without visiting all of it.

    Common mistake

    Assuming every constraint you were given does something. A redundant constraint costs work — in the brute-force method of §7.4.9 it adds a slack variable and multiplies the number of systems to solve — while removing no feasible point at all. The slack column is where you spot it: a constraint whose slack is strictly positive at every vertex is doing nothing.

    7.3.4 Empty feasible set / no feasible solution

    # Permalink to topic 7.3.4, Empty feasible set, no feasible solution
    • ● Slides
    • ◐ LP Visualizer, partial
    Example with an empty feasible set

    max z = 2x + 5y
    subject to −2x − 3y ≤ −12,  3x + 4y ≤ 12,  x ≥ 0, y ≥ 0

    First constraint, read the other way
    2x + 3y ≥ 12
    Answer
    No feasible solution exists, so there is no optimal solution either

    The two constraints pull in opposite directions. The first demands 2x + 3y ≥ 12; the second caps 3x + 4y at 12. In the first quadrant the largest 2x + 3y can get while obeying the second constraint is 9, at (0, 3) — short of the 12 the first constraint demands. The two half-planes never overlap.

    Why no point satisfies both constraints

    The three corners of 3x + 4y ≤ 12 in the first quadrant. None reaches the 12 that 2x + 3y ≥ 12 requires, so the feasible set is empty.
    Corner of 3x + 4y ≤ 12 2x + 3y Needed Satisfies both?
    (0, 0)012No
    (4, 0)812No
    (0, 3)912No

    Key idea

    Some linear programming problems have an empty feasible set. Such problems have no solution — and no algorithm can invent one. An infeasible LP is nearly always a modelling error: two of your requirements cannot both be met.

    7.3.5 Unbounded feasible region

    # Permalink to topic 7.3.5, Unbounded feasible region
    • ● Slides
    • ◐ LP Visualizer, partial
    Example with an unbounded feasible region

    objective z = x + 4y
    subject to x − y ≤ 1,  −2x − y ≤ −8,  x ≥ 0, y ≥ 0

    Second constraint, read the other way
    2x + y ≥ 8
    Maximizing
    no optimal solution — z grows without limit
    Minimizing
    z = 11 at the vertex (3, 2)

    The two constraint lines meet at (3, 2) and the feasible set opens upward forever. Maximizing x + 4y over it has no answer: pick any feasible point and you can always move further up and do better. The same region with the same constraints has a perfectly good minimum, at the vertex (3, 2), where z = 3 + 8 = 11. Every other feasible point gives a larger value.

    Objective values on the unbounded region

    The unbounded region has two vertices, and z climbs without limit as you travel up the boundary; minimizing is well posed, maximizing is not.
    Point x y z = x + 4y Kind of point
    P13211Vertex — the minimum
    P20832Vertex on the y axis
    P332083Interior of the wedge
    P43200803Same wedge, further up

    Summary of the four cases

    A feasible set may be bounded, unbounded, or empty. If it is empty there is no feasible and hence no optimal solution. If it is unbounded there may be no optimal solution, exactly one, or several. If it is bounded there is an optimal solution, unique or not.

    7.3.6 Uniqueness of the optimum

    # Permalink to topic 7.3.6, Uniqueness of the optimum
    • ● Slides
    • ◐ LP Visualizer, partial
    Example with many optimal solutions

    max z = 3x1 + 2x2
    subject to x1 + x2 ≤ 5,  3x1 + 2x2 ≤ 12,  x1 ≥ 0, x2 ≥ 0

    Observation
    the objective is the left-hand side of the second constraint, so z can never exceed 12
    Answer
    z = 12 at every point of the segment from (4, 0) to (2, 3)

    Is the optimal solution unique? Here, no. Every point on the line 3x1 + 2x2 = 12 that also satisfies x1 + x2 ≤ 5 gives z = 12 — for example (2, 3) and (2.5, 2.25). The objective line lies flat along an edge of the feasible region instead of touching it at a single corner.

    Points on the optimal edge

    Four points on the optimal edge and one off it: the whole edge from (4, 0) to (2, 3) attains z = 12, while an interior point does not.
    Point x₁ x₂ x₁ + x₂ z = 3x₁ + 2x₂ On the optimal edge?
    Vertex A40412Yes — endpoint
    Interior of edge2.52.254.7512Yes
    Vertex B23512Yes — endpoint
    Vertex C05510No
    Origin0000No

    Key idea

    Non-uniqueness does not break the extreme-point theorem. When a whole edge is optimal, its two endpoints are vertices and are optimal too — so an algorithm that only ever looks at vertices still finds the optimal value. It just cannot tell you, on its own, that there were others.

    7.4 Slack Variables & Basic Solutions

    7.4.1 Slack variables

    # Permalink to topic 7.4.1, Slack variables
    • ● Slides
    • ▣ Lab 14
    • ✚ New for 2026

    Return to the running example: max z = 120x + 100y subject to 2x + 2y ≤ 8 and 5x + 3y ≤ 15. Its feasible region is a quadrilateral with vertices (0, 0), (3, 0), (1.5, 2.5) and (0, 4), and evaluating z at all four settles the problem.

    Objective at the four vertices of the running example

    The running example solved by inspecting its four vertices: the largest z is 430 at (1.5, 2.5), matching the graphical answer.
    Vertex x y z = 120x + 100y
    V1000
    V204400
    V330360
    V41.52.5430

    That trick does not generalise past two unknowns, because you cannot draw the region. What does generalise is linear algebra — but linear algebra solves equations, and the constraints are inequalities. Slack variables buy the conversion, at the price of extra unknowns.

    Converting the two constraints

    2x + 2y + u = 8
    5x + 3y + v = 15
    u ≥ 0, v ≥ 0

    u
    the unused part of the first resource, 8 − 2x − 2y
    v
    the unused part of the second resource, 15 − 5x − 3y

    Definition

    Slack variable
    A non-negative variable added to the smaller side of a ≤ constraint to turn it into an equation. It "takes up the slack" between the two sides: the amount of that resource left over.
    The slack form of the running example

    max z = [120  100  0  0] [x, y, u, v]T

    7.4.2 Slack variables and the optimal solution

    # Permalink to topic 7.4.2, Slack variables and the optimal solution
    • ● Slides
    • ▣ Lab 14
    • ✚ New for 2026

    Adding variables is only legitimate if it does not change the answer. The slides prove the two problems are equivalent, in both directions.

    The two directions of the equivalence proof

    Why the inequality LP and the slack LP have the same feasible points: each direction of the argument is one line of algebra.
    Direction Start from Argument Conclusion
    Slack form ⟶ original A solution of the equality system with u ≥ 0, v ≥ 0 u = 8 − 2x − 2y ≥ 0 gives 2x + 2y ≤ 8; v = 15 − 5x − 3y ≥ 0 gives 5x + 3y ≤ 15 (x, y) satisfies the original constraints
    Original ⟶ slack form (x, y) satisfying the two inequalities Define u and v by those same two formulas; each is a non-negative number because the inequality holds (x, y, u, v) satisfies the equality system with all four components non-negative

    Key idea

    The objective does not involve u or v, so the two problems have the same feasible points and the same objective value at each. Solving the slack form solves the original. What you gain is that the constraints are now equations, which linear algebra can handle in any number of dimensions.

    The slack values also carry information at the end: a slack of zero means the constraint is tight — that resource is fully used and the solution sits on that boundary line. A positive slack means the constraint is not binding at the optimum. In the running example the optimum (1.5, 2.5) has u = v = 0, so both resources are exhausted.

    7.4.3 Handling ≥ constraints

    # Permalink to topic 7.4.3, Handling greater-than-or-equal constraints
    • ● Slides
    • ✚ New for 2026

    If the original constraint points the other way, the slack is subtracted rather than added.

    A ≥ constraint

    2x + 2y ≥ 8 ⟶  u = 2x + 2y − 8 ⟶  2x + 2y − u = 8, u ≥ 0

    Why subtract
    the quantity that is non-negative is now the excess of the left-hand side over the right-hand side, so it must be taken away to restore the equation
    Other name
    such a variable is often called a surplus variable; the slides call both kinds slack variables

    Key idea

    One slack variable per inequality constraint, whichever way it points. With m inequality constraints — not counting the non-negativity conditions on x — you add exactly m slack variables. Solving the slack system is equivalent to solving the original problem in standard form.

    The transportation problem of §7.2.2 is the case that needs both: two supply constraints with ≤ that gain x7 and x8, and three demand constraints with ≥ that lose x9, x10 and x11. Its constraint matrix is in §7.4.9. Try the reversed constraint in the slack variable explorer to watch the sign flip.

    Scalar form

    max z = c1x1 + ⋯ + cnxn

    Three degrees of freedom means three components of x can be chosen freely. Full generality is more work than the problem needs: since only x ≥ 0 matters, the slides simply set three components to zero and solve for the rest. Zeroing x2, x3, x5 leaves a 3 × 3 system in x1, x4, x6 that is invertible, giving

    One basic solution

    x = ( b1, 0, 0, b3 − b1 + b2, 0, −b2 )T

    Reduced system
    rows (1, 0, 0), (0, 0, −1) and (1, 1, 1) acting on (x1, x4, x6)
    From row 1
    x1 = b1
    From row 2
    −x6 = b2, so x6 = −b2
    From row 3
    x1 + x4 + x6 = b3, so x4 = b3 − b1 + b2

    Note on the source

    The slides read the same reduced system as x4 = −b2 and x6 = b3 − b1 + b2. The two values belong the other way round: row 2 of the reduced matrix is (0, 0, −1), so it is x6 — not x4 — that equals −b2. The point being made is unaffected: a basic solution exists here because the reduced matrix is invertible.

    Common mistake

    Assuming any three components may be zeroed. Zero x1, x3, x5 instead and the remaining 3 × 3 coefficient matrix is singular — there is no unique solution. The reason is visible in the original matrix: column 6 + column 4 = column 2, so those columns are not independent. Any implementation must test for this, because a linear solver will raise an error rather than return an answer.

    7.4.6 Basic feasible solutions

    # Permalink to topic 7.4.6, Basic feasible solutions
    • ● Slides
    • ▣ Lab 14
    • ✚ New for 2026

    Definition

    Basic solution
    A solution of Ax = b (with A of size m × s and rank m) obtained by setting s − m components of x to zero.
    Basic variables
    The m components that were not set to zero.
    Basic feasible solution
    A basic solution that is also feasible, i.e. every component is non-negative.

    The theorem that makes the method work

    For this LP problem, every basic feasible solution is an extreme point, and every extreme point is a basic feasible solution. Moreover there are only finitely many basic feasible solutions.

    Put that beside the extreme-point theorem of §7.3.2 and an algorithm falls out: find every basic feasible solution, evaluate z at each, and report the largest. The vertices you could see in two dimensions are exactly the basic feasible solutions you can compute in any number of dimensions.

    Note

    "Basic" refers to a basis: the m columns of A belonging to the basic variables must be linearly independent, or the reduced system has no unique solution. That is the singular case of §7.4.5, and a combination that hits it produces no basic solution at all.

    Three-constraint example

    Python Generating the candidates, Lab 14 exercise 3

    7.4.9 Brute-force LP method

    # Permalink to topic 7.4.9, Brute-force LP method
    • ● Slides
    • ▣ Lab 14
    • ✚ New for 2026

    Putting §7.4.4 to §7.4.8 together gives a complete algorithm. It is not the most efficient method, but it is easy to implement and effective when the number of constraints is small. This is the algorithm you write in Lab 14.

    1. Read in the m × s constraint matrix A, the right-hand side b, and the objective coefficients c; initialise the incumbent z.
    2. Determine how many variables must be set to zero: s − m.
    3. Loop over every combination of that many variables.
      • Delete the corresponding columns of A to form the m × m matrix Ã.
      • Solve Ãy = b for the remaining variables.
      • Test feasibility: is every component non-negative?
      • If feasible, evaluate z and keep it if it beats the incumbent.

    The linear solve is one library call, so the only routine you actually have to write is the one that forms Ã from A. In MATLAB that is a setdiff away, and in NumPy it is a fancy-index.

    7.5 The Simplex Method

    7.5.1 Simplex strategy outline

    # Permalink to topic 7.5.1, Simplex strategy outline
    • ● Slides
    • ✚ New for 2026

    The brute-force method of §7.4.9 does three things: solve every one of the m+nCm m plus n choose m m × m systems, throw away the infeasible answers, and take the best of what is left. Each solve costs on the order of m3 operations, so the total work is the product of a combinatorial count and a cubic cost.

    Cost of brute force

    work ≈ (m+n)Cm × O(m3)

    n
    number of original variables
    m
    number of constraints, and so the size of each linear system
    Slides' first case
    8 variables in total with 4 constraints: 70 systems of size 4
    Slides' second case
    16 variables in total with 8 constraints: 12 870 systems of size 8
    Growth between them
    (12 870 / 70) × (8 / 4)3 ≈ 1500 times more work

    The strategy

    Two objectives fix the waste. First, only ever generate feasible solutions, so no work is spent on systems whose answers get discarded.     7.5.2 Simplex requirements

    # Permalink to topic 7.5.2, Simplex requirements
    • ● Slides
    • ✚ New for 2026

    To carry out that strategy the method needs three pieces of machinery, and the rest of §7.5 supplies them one at a time.

    1. A way to find an initial basic feasible solution — §7.5.3.
    2. A way to move to an adjacent basic feasible solution with a larger z — §7.5.5 to §7.5.8.
    3. A way to decide that a basic feasible solution is optimal, i.e. a termination test — §7.5.9.

    Definition

    Adjacent basic feasible solutions
    Two basic feasible solutions that have a basic variable in common.

    The four feasible basic solutions of the running example and their basic variables

    The four feasible rows of the running example's enumeration, with the basic variables of each. Points 1 and 4 share nothing, and nor do points 2 and 3; every other pair is adjacent.

    Key idea

    The simplex method was developed by George Dantzig in 1947. Instead of enumerating every basic feasible solution, it starts at one and repeatedly jumps to an adjacent one chosen so that the objective increases.

    7.5.3 Initial basic feasible solution

    # Permalink to topic 7.5.3, Initial basic feasible solution
    • ● Slides
    • ✚ New for 2026

    In general, finding a starting vertex is itself a hard problem. One assumption makes it trivial.

    The assumption

    Assume bi ≥ 0 for every component of b. Then setting all n original variables to zero leaves the slacks equal to b, and that is a basic feasible solution.

    The starting vertex

    x1 = x2 = ⋯ = xn = 0,  xn+1 = b1,  xn+2 = b2, …,  xn+m = bm

    Why it is basic
    n = s − m variables were set to zero, and the columns left are the identity block
    Why it is feasible
    every bi ≥ 0, so every component is non-negative
    Geometrically
    it is the origin: produce nothing, use nothing, earn nothing

    Common mistake

    Using this start when some bk < 0. Then xn+k = bk < 0 and the point is basic but not feasible, so the method has nowhere to start. That case needs a different technique — in practice a two-phase method, which is beyond this course.

    For the running example every bi is positive, so x = [0, 0, 8, 15]T with z = 0 starts the process.

    Definition

    Canonical form
    The system is in canonical form with respect to a set of basic variables when each basic variable (i) appears in exactly one constraint row, with coefficient +1, and (ii) has 0 in every other entry of its column.     7.5.5 Moving to an adjacent vertex

    # Permalink to topic 7.5.5, Moving to an adjacent vertex
    • ● Slides
    • ✚ New for 2026

    At the starting point (0, 0, 8, 15) the objective is

    The objective at the start

    z = 120x1 + 100x2 + 0x3 + 0x4 = 0

    Reading it
    both non-basic variables have a positive coefficient, so raising either of them above zero increases z

    Key idea

    To move to an adjacent basic feasible solution, take one non-basic variable — currently zero — and increase it. In the tableau the objective row holds the negated coefficients, so "positive coefficient in z" appears as a negative entry in the objective row.

    Increasing one variable forces others to change, because Ax = b must keep holding. That is what limits the move, and it is how the next vertex is identified — §7.5.7.

    7.5.6 Entering variable

    # Permalink to topic 7.5.6, Entering variable
    • ● Slides
    • ✚ New for 2026

    Definition

    Entering variable
    The non-basic variable chosen to be increased. At the next iteration it becomes basic — it "enters the set of basic variables".

    Two criteria are offered in the slides:

    1. Take the first variable with a negative coefficient in the objective row.
    2. Take the variable with the largest negative coefficient in the objective row.

    The course adopts criterion 2, Dantzig's rule. In the initial tableau the objective row is (−120, −100, 0, 0), the most negative entry is −120, so x1 enters. The intuition is that each unit of x1 buys 120 of objective and each unit of x2 only 100 — though that is a greedy choice about the rate of improvement, not the total, so it is not guaranteed to reach the optimum in the fewest iterations.

    Common mistake

    Reading the sign backwards. The objective row stores z − 120x1 − 100x2 = 0, so its entries are the negatives of the objective coefficients. A negative entry marks a variable worth increasing; a non-negative entry marks one that is not.

    Criterion 1 is not merely a lazier version of criterion 2 — it is Bland's rule, and it has a guarantee that Dantzig's rule lacks. Both are available in the tableau step-through.

    7.5.7 Departing variable

    # Permalink to topic 7.5.7, Departing variable
    • ● Slides
    • ✚ New for 2026

    How far can the entering variable rise? Hold the other non-basic variable at zero and read the constraints:

    The limit on the entering variable

    x3 = 8 − 2x1 ≥ 0 ⟹ x1 ≤ 4
    x4 = 15 − 5x1 ≥ 0 ⟹ x1 ≤ 3

    Binding limit
    the smaller one: x1 = 3
    Result
    x3 = 2, x4 = 0, so the new point is (3, 0, 2, 0) with z = 360
    Adjacent?
    yes — the new point shares the basic variable x3 with the old one

    In the tableau those two bounds are just ratios of the right-hand side to the entry in the entering column: 8 / 2 = 4 in the x3 row, 15 / 5 = 3 in the x4 row. The row with the smallest positive ratio is the one that hits zero first.

    Definition

    Departing variable
    The basic variable driven to zero by the move. It leaves the set of basic variables.
    Pivotal column
    The column of the entering variable.
    Pivotal row
    The row of the departing variable.
    Pivot
    The entry where the pivotal row and pivotal column meet — here the 5 in the x4 row of the x1 column.

    Common mistake

    Taking the smallest ratio rather than the smallest positive ratio. A zero or negative entry in the pivotal column places no upper bound on the entering variable — that row's basic variable grows rather than shrinks — so those rows are skipped. If every entry in the pivotal column is zero or negative, no row bounds the move and the problem is unbounded.

    7.5.8 The simplex tableau

    # Permalink to topic 7.5.8, The simplex tableau
    • ● Slides
    • ✚ New for 2026

    The move is carried out by elementary row operations, exactly as in Gauss elimination: make the pivot +1, then clear every other entry in the pivotal column, objective row included.

    Definition

    Pivoting
    Dividing the pivotal row by the pivot, then adding multiples of that row to every other row so the rest of the pivotal column becomes zero. It restores canonical form for the new set of basic variables.
    Pseudocode One pivot on the tableau T with pivot at row r, column c 
    p = T[r][c]                       # the pivot, guaranteed > 0
T[r] = T[r] / p                   # step 1: make the pivot +1
for each row i != r:
    T[i] = T[i] - T[i][c] * T[r]  # step 2: clear the rest of the column
objective = objective - objective[c] * T[r]
basic[r] = c                      # x_c is now the basic variable of row r

    Applied to the running example: the pivot is the 5 in the x4 row, so that row is multiplied by 1/5 to give x1 + (3/5)x2 + (1/5)x4 = 3. Then row 1 becomes row 1 − 2 × (new row 2), giving (4/5)x2 + x3 − (2/5)x4 = 2. Finally the objective row gains 120 × (new row 2), and the second tableau is complete with z = 360.

    7.5.9 Optimality test

    # Permalink to topic 7.5.9, Optimality test
    • ● Slides
    • ✚ New for 2026

    Optimality test

    If the objective row of a tableau has zero entries in the columns labelled by the basic variables and no negative entries in the columns labelled by the non-basic variables, then the solution that tableau represents is optimal.

    The reason is the one from §7.5.5 read backwards: a negative entry in the objective row marks a variable that would increase z if raised. No negative entries means no such variable exists, so no adjacent vertex is better — and by the extreme-point theorem no point at all is better.

    Worked example: three variables, three constraints

    The eight-step example of the slides

    max z = 2x1 + 3x2 + 3x3
    subject to 3x1 + 2x2 ≤ 60,  −x1 + x2 + 4x3 ≤ 10,  2x1 − 2x2 + 5x3 ≤ 50,  x1, x2, x3 ≥ 0

    Step 1
    add slacks x4, x5, x6
    Steps 2–3
    matrix form; since b ≥ 0 start at (0, 0, 0, 60, 10, 50)
    Steps 4–7
    tableau, entering variable, departing variable, pivot — twice
    Step 8
    optimality test
    Answer
    x = (8, 18, 0) with z = 70

    The three tableaus of the three-variable example

    The three-variable example: z climbs 0 → 30 → 70, and the third tableau passes the optimality test because its objective row has no negative entry.
    Tableau Basic variables Solution (x₁ … x₆) z Objective row negatives
    1x₄, x₅, x₆(0, 0, 0, 60, 10, 50)0x₁ (−2), x₂ (−3), x₃ (−3)
    2x₄, x₂, x₆(0, 10, 0, 40, 0, 70)30x₁ (−5)
    3x₁, x₂, x₆(8, 18, 0, 0, 0, 70)70none — optimal

    Step through every tableau of this example, and of the unbounded one below, in the tableau step-through in §7.5.8.

    When there is no departing variable: an unbounded objective

    The second worked example is max 2x2 + x3 subject to x1 + x2 − 2x3 ≤ 7 and −3x1 + x2 + 2x3 ≤ 3. Two pivots take z from 0 to 6 to 12. In the third tableau x3 still has a negative objective entry (−3), so it should enter — but its whole column is negative, so no row limits it. Both x1 = 1 + x3 and x2 = 6 + x3 stay non-negative however large x3 grows. The objective is unbounded.

    Key idea

    An all-non-positive pivotal column is how an unbounded LP announces itself. It is not a bug and not a failure of the method — it is the method reporting, correctly, that no optimal solution exists.

    7.5.10 Bland's rule (anti-cycling)

    # Permalink to topic 7.5.10, Bland's rule, anti-cycling
    • ● Slides
    • ✚ New for 2026

    Will the simplex method always find an optimal solution when the feasible set is bounded? Not on its own. There are pathological problems on which the method cycles: it pivots away from a basic feasible solution and later returns to the same one, with the objective never improving, and it never stops.

    Bland's rule

    The simplex method will not cycle if the entering and departing variables are chosen by the smallest subscript rule: among the eligible candidates, always take the one with the lowest index.

    Cycling requires a degenerate vertex — one where a basic variable is already zero, so a pivot moves nowhere and z does not change. Bland's rule breaks the tie deterministically and provably prevents the method from revisiting a basis.

    The two pivoting rules compared

    The two entering-variable rules on the three-variable example of §7.5.9. Both reach z = 70 in three tableaus, but by different vertices.
    Rule Choose First entering variable Objective at each tableau Cycling guarantee
    Dantzig Most negative objective entry x₂ (−3, tied with x₃, lowest index wins) 0, 30, 70 None — can cycle
    Bland Lowest index with a negative entry x₁ (−2) 0, 40, 70 Provably terminates

    Switch between the two in the tableau step-through and watch the path change while the answer does not.

    Practice exercise

    The slides close with an unworked exercise: maximize z = x1 + 2x2 subject to x1 + x2 ≤ 1.5, x1 ≤ 1, x2 ≤ 1, x1, x2 ≥ 0. It is the problem solved graphically in §7.3.1, so you already know the answer is (0.5, 1) with z = 2.5 — work the tableaus by hand first, then check them against the Practice exercise preset of the step-through.

    7.5.11 Quadratic programming (preview)

    # Permalink to topic 7.5.11, Quadratic programming preview
    • ● Slides

    Definition

    Quadratic programming
    A specialized optimization problem in which the unknown appears quadratically in the objective function, while the constraints remain linear.
    General quadratic program

    max z = xTQx + cTx
    subject to Ax ≤ b and/or Bx = d

    Q
    a symmetric matrix of quadratic coefficients
    c
    the vector of linear coefficients
    Special case
    if Q = 0 the problem reduces to a linear program

    The geometry changes in one important way: the objective is no longer flat, so its optimum need not sit at a vertex of the feasible region. It can sit in the middle of an edge or in the interior. The extreme-point theorem of §7.3.2 does not apply, and the simplex method does not solve these problems.

    Note

    This is one slide frame in the course, offered as an orientation rather than as assessed material. Least-squares fitting with constraints is the quadratic program you are most likely to meet first.
