    0.1 Git: repositories, cloning

    # Permalink to topic 0.1, Git: repositories, cloning
    • ● Taught in full
    • ▣ Lab 01
    • ✚ New for 2026

    Git keeps a complete history of a project so that you can go back to any earlier version, and so that several people can work on the same files without overwriting one another. A repository is the unit it tracks: a folder of files plus every version of every one of them. Cloning copies a repository from GitHub onto your own machine so you can work on it locally.

    Definition

    Git
    A distributed version control system: a tool for tracking changes to your code, collaborating, and sharing. Distributed means every clone holds the whole history, not just the latest files.
    GitHub
    A way to use the same power of Git online, with an interface on top of it. Git is the tool; GitHub is a place to keep repositories and talk about them.
    Repository
    Where your project work happens — think of it as your project folder. It contains all of your project's files and their revision history.
    Cloning
    Making a local copy of a repository on your computer, which you then use Git to keep in sync with the copy on GitHub.

    A clone is not a download of the current files. It pulls down all the repository data GitHub has at that point in time, including every version of every file and folder. That is why you can go offline straight after cloning and still inspect the whole history.

    Bash Lab 01, step 1 — clone the dashboards repository 
    git clone https://github.com/FSU-4221C/ISC-4221-DiscreteMethods-Dashboards.git
cd ISC-4221-DiscreteMethods-Dashboards
git log --oneline          # the history you just downloaded
git remote -v              # the URL this clone is linked back to, named "origin"

    What a clone contains

    What git clone brings down, and what it is for
    What you get Where it lives Why it matters
    The current files The new folder Git creates This is the copy you edit. Git calls it the working tree.
    Every earlier version The hidden .git folder Lets you revert to an older version of a file without asking anybody.
    Every branch The hidden .git folder You can switch to any line of work that existed when you cloned.
    A link named origin Repository configuration The address Git pushes to and pulls from, so you never retype the URL.

    Note

    Every repository should carry a README. Lab 01 puts it this way: a README tells other people why your project is useful, what they can do with it, and how they can use it. Half of the Lab 01 mark is your own repository plus its README.

    0.2 Git: committing and pushing

    # Permalink to topic 0.2, Git: committing and pushing
    • ● Taught in full
    • ▣ Lab 01
    • ✚ New for 2026

    Committing and pushing are how the changes you made on your own machine get added to the remote repository on GitHub. They are two separate steps, and confusing them is the single most common thing that goes wrong in Lab 01.

    Definition

    Commit
    A checkpoint in your local repository. It records a set of changes together with a message describing them, and it can always be returned to later.
    Commit message
    A short sentence saying what this checkpoint changed — for example, Added a README with information about our project.
    Push
    Sending the commits that exist only on your machine up to the remote repository on GitHub, so that other people — and the autograder — can see them.

    Common mistake

    A commit does not upload anything. If you commit and stop there, your work exists on exactly one computer, and a marker looking at GitHub sees nothing. Run git status: if it says your branch is ahead of origin, you have not pushed.

    Bash The commit and push cycle 
    git status                 # what has changed, and whether you are ahead of origin
git add README.md          # choose which changes go into the next checkpoint
git commit -m "Added a README with information about our project"
git push                   # now, and only now, GitHub has it

    0.3 The GitHub flow

    # Permalink to topic 0.3, The GitHub flow
    • ● Taught in full
    • ▣ Lab 01
    • ✚ New for 2026

    The GitHub flow is a lightweight workflow that lets you experiment and collaborate on your projects without the risk of losing your previous work. It is the same six moves every time, and it is worth learning as a sequence rather than as a set of buttons.

    Key idea

    Nothing you do in the flow changes main until the merge. That is the whole point: main stays working code while your experiment happens somewhere else.

    1. Start from main, the default branch, which should always be in a working state.
    2. Create a branch for the change you want to make.
    3. Make commits on that branch. main is untouched.
    4. Open a pull request to tell others about the changes and ask for feedback.
    5. Discuss and review; push more commits to the same branch until it is ready to go.
    6. Merge the pull request into main, then delete the branch.

    The GitHub flow, step by step — interactive version not running. JavaScript is switched off, or a script file is missing. The default run — one review round, branch deleted afterwards — is below.

    0.4 Branches, forks, pull requests

    # Permalink to topic 0.4, Branches, forks, pull requests
    • ● Taught in full
    • ▣ Lab 01
    • ✚ New for 2026

    Branches and forks are both ways of getting a copy you can safely break. The difference is who owns the copy. A pull request is how either kind of copy asks to come back in.

    Definition

    Branch
    A line of work inside one repository, used to isolate work you do not want merged into your final project just yet. You typically create a new branch from the default branch, main, and merge it back once it has been reviewed.
    Fork
    Another way to copy a repository, usually used when you want to contribute to someone else's project. It lets you freely experiment with changes without affecting the original project.
    Pull request
    A request to merge your changes, used to tell others about the changes you want to make and ask for their feedback. Once a pull request is ready to go, it can be merged into the main branch.

    Branch compared with fork

    Branch compared with fork: same idea, different owner
    Question Branch Fork
    Where does the copy live? Inside the same repository In a new repository under your own account
    Who can create one? Anybody with write access to that repository Anybody who can see the repository
    Typical use Your own project, or a team project you belong to Contributing to someone else's project
    How does the work come back? A pull request from the branch into main A pull request from your fork into the original repository
    Who decides whether it is merged? Whoever reviews the pull request The maintainer of the original project
    Bash Creating a branch and pushing it for review 
    git switch -c add-readme   # create a branch from main and move onto it
git add README.md
git commit -m "Added a README with information about our project"
git push -u origin add-readme
# then open the pull request on GitHub and ask for a review

    The step-through in topic 0.3, the GitHub flow walks the same branch through a pull request and a merge, and reports how many commits sit on each line at every step.

    0.5 Issues and project boards

    # Permalink to topic 0.5, Issues and project boards
    • ● Taught in full

    An issue is a way to track enhancements, tasks, or bugs for your work on GitHub. A project board collects issues into columns so you can see what is waiting, what is being worked on, and what is done. Issues and pull requests can be linked, so that merging the pull request closes the issue automatically.

    Key idea

    An issue is a conversation with a state. Writing one before you start is how a question that would otherwise live in your head becomes something a TA can answer without being in the room with you.

    0.7 Python environments with uv

    # Permalink to topic 0.7, Python environments with uv
    • ● Taught in full
    • ▣ Lab 01
    • ▣ Lab 02

    A virtual environment is a private copy of Python and its packages that belongs to one project. Without one, installing NumPy for this course can break a different project on the same machine, and it works on mine becomes impossible to debug. uv is the tool this course uses to create and manage those environments.

    Definition

    Virtual environment
    A folder — conventionally .venv/ — holding a Python interpreter and the packages for one project only. Nothing outside the folder is affected.
    Lock file
    uv.lock: the exact version of every package that was installed. It is what makes your environment reproducible on another machine.
    uv sync
    Reads the project's declared dependencies and its lock file and makes .venv/ match them exactly, installing or removing packages as needed.

    The uv commands behind figure 0.7.1

    The four uv commands used in this course, and what each one changes
    Command What it does What it changes on disk When you run it
    uv venv Creates an empty virtual environment Creates .venv/ Starting a project that has none
    uv sync Installs exactly the declared and locked dependencies Fills or corrects .venv/ Straight after cloning, and whenever dependencies change
    uv run Runs a command inside the environment Nothing Every time you run your code
    uv pip install Adds a package to the environment Adds to .venv/ Only when you genuinely need a new dependency
    Bash Installing uv and running the Lab 01 dashboard 
    # Install uv, if it is not already installed
curl -LsSf https://astral.sh/uv/install.sh | sh

# Inside a cloned project: create and fill the environment
uv venv
uv sync

# Run something inside that environment, without activating anything
cd Algorithms
uv run python interactive_algorithms_dashboards.py

    Key idea

    Prefer uv run over activating the environment by hand. uv run cannot be forgotten and cannot be run in the wrong shell, so the command you paste into a report is the command a marker can reproduce.

    Common mistake

    Two things go wrong most often. A port conflict: the dashboard says the address is already in use, because an earlier run is still going — close it, or start on a different port. And a dependency error: almost always uv sync was never run, or was run in the wrong folder. Check you are in the folder that holds pyproject.toml.

    Note

    The Lab 02 repository is not a model layout: it ships a committed .venv/ and a uv.lock but no pyproject.toml. A virtual environment is machine-specific and should be in .gitignore; the lock file is the thing that belongs in the repository.

    0.8 Loops, conditionals, recursion

    # Permalink to topic 0.8, Loops, conditionals, recursion
    • ● Taught in full
    • ▣ Lab 02
    • ✚ New for 2026

    Loops and recursion are two ways of saying do this again with something smaller. A loop keeps one running total and changes it repeatedly. A recursive function calls itself on a smaller input and combines the answer it gets back. Both need a stopping condition, and both are wrong without one.

    Definition

    Conditional
    A test that chooses between two paths — if and else.
    Loop
    A block repeated a number of times fixed in advance (for) or until a condition stops being true (while).
    Accumulator
    A variable initialised before the loop and updated inside it, carrying the running answer. In the factorial below, factorial is the accumulator.
    Recursion
    A function that calls itself on a smaller input, together with a base case that returns without calling again.
    Base case
    The input a recursive function answers directly. Without one the recursion never stops and Python raises a recursion-depth error.
    Guard clause
    A check at the very top of a function that rejects input the rest of the body cannot handle, usually by raising an exception.

    The course's own loop example is the factorial. This is the pseudocode from the overview lecture — pseudocode is a language-independent description of an algorithm, so the syntax deliberately does not have to be valid in any language.

    Factorial

    n! = 1 × 2 × … × (n − 1) × n

    n
    a non-negative whole number, the input
    n!
    the product of every whole number from 1 up to n; 0! is defined to be 1
    Pseudocode Factorial, as the overview lecture writes it 
    input n, factorial = 1
for i = 2, n
    factorial = factorial * i
end for
    Python The same loop in Python, with a conditional 
    def factorial(n: int) -> int:
    if n < 0:                      # guard clause
        raise ValueError("n must be non-negative")
    result = 1                     # the accumulator
    for i in range(2, n + 1):      # range stops BEFORE n + 1, so this reaches n
        result = result * i
    return result

    Recursion is the other route, and it is what Lab 02 question 1 grades. The function is defined by a recurrence and a base case:

    Lab 02, question 1

    f(x) = 2x − f(x − 1)   for x > 0,   with f(0) = 0

    x
    a non-negative whole number; negative input must raise an exception
    f(x − 1)
    the answer for the next smaller input, obtained by calling the function again
    f(0) = 0
    the base case, answered without any further call
    Python myrec, the Lab 02 reference solution 
    def myrec(x: int) -> int:
    """Compute f(x) = 2*x - f(x-1) for x > 0, with f(0) = 0."""
    if x < 0:
        raise Exception("Input must be non-negative")
    if x == 0:
        return 0
    return 2 * x - myrec(x - 1)

    Every frame of myrec(6), listed in the order the calls are made, with the value each one eventually returns

    myrec(5)562 × 5 − myrec(4) = 10 − 4

    Common mistake

    myrec does not compute f(x) = x. The closed form is f(x) = 2 × ceil(x / 2): equal to x when x is even, and x + 1 when x is odd. myrec(5) returns 6. The Lab 02 tests only ever assert even inputs — 0, 6 and 532 — so the asymmetry never shows up unless you look for it. This is a good reminder that passing tests is not the same as being correct.

    0.9 File I/O and path handling

    # Permalink to topic 0.9, File I/O and path handling
    • ● Taught in full
    • ▣ Lab 02
    • ▣ Lab 03

    Almost every lab after this one reads a data file. Lab 02 question 2 is the exercise that teaches the pieces: check a path exists, list what is inside it, and decide for each entry whether it is a file or a folder. The tip in the handout is simply look at os and os.path.

    The path functions used in Lab 02

    The four path functions basic_io needs
    Call Returns Why it is used here
    os.path.exists(path)True or FalseFail politely instead of raising when the folder is missing
    os.listdir(path)A list of names, in no guaranteed orderThe names inside the folder — names only, not full paths
    os.path.join(path, item)A path stringJoins with the right separator on Windows, macOS and Linux
    os.path.isdir(full_path)True or FalseTells a folder from a file — and needs the full path, not the bare name
    Python basic_io, the Lab 02 reference solution 
    import os
from typing import Dict, List, Union

def basic_io(path: str) -> Dict[str, Union[int, List[str]]]:
    if not os.path.exists(path):
        print("Folder does not exist.")
        return {}

    files = []
    file_or_folder = []

    for item in sorted(os.listdir(path)):
        item_path = os.path.join(path, item)
        files.append(item)
        if os.path.isdir(item_path):
            file_or_folder.append('folder')
        else:
            file_or_folder.append('file')

    return {
        'number_files': len(files),
        'files': files,
        'file_or_folder': file_or_folder
    }

    Expected output of basic_io on the test folder

    What basic_io('test_folder') must return — the exact values the Lab 02 test asserts
    Position Entry in files Entry in file_or_folder
    0f1.txtfile
    1f2folder
    2f3.txtfile
    3f4.pyfile

    number_files is 6 for this folder. Note that f2 has no extension and is a folder, while f4.py and f5.csv are files: you cannot decide from the name, which is exactly why os.path.isdir exists.

    Common mistake

    Three that cost marks. Forgetting sorted() — os.listdir returns entries in whatever order the file system hands over, so an unsorted answer passes on your machine and fails on the grader's. Passing the bare name to os.path.isdir instead of the joined path, which makes every entry look like a file. And building paths by gluing strings with a slash, which breaks on Windows.

    Note

    The missing-folder case is checked by capturing what your function prints. The test calls basic_io('../test_folder3') and asserts that the words Folder does not exist. appear in standard output — so the message has to be printed, not returned, and not raised.

    0.10 NumPy arrays and vectorization

    # Permalink to topic 0.10, NumPy arrays and vectorization
    • ● Taught in full
    • ▣ Lab 02
    • ✚ New for 2026

    A NumPy array is a grid of numbers with a fixed shape, and it is the data structure the rest of this course runs on — images in M4, point clouds in M5 and M6, tableaus in M7. Two ideas matter here: slicing, which selects part of an array without copying it out by hand, and vectorization, which applies an operation to every element at once instead of writing a loop.

    NumPy slicing and vectorization reference

    Slicing and vectorization on an array A with shape (3, 5) — 3 rows, 5 columns
    Expression What it selects or produces Shape of the result
    A.shapeThe size in each dimension: rows first, then columnsA tuple, (3, 5)
    A[1, 2]One element: row index 1, column index 2A single number
    A[1, :]All of row index 1 — the second row(5,)
    A[:, 2]All of column index 2 — the third column(3,)
    np.sum(A[1, :])The total of that rowA single number
    A ** 2Every element squared, with no loop written(3, 5)
    Python add2and3 and squareme, the Lab 02 reference solutions 
    import numpy as np

def add2and3(matrix: np.ndarray) -> float:
    if matrix.shape[0] < 2 or matrix.shape[1] < 3:
        print("Matrix too small.")
        return 0
    return np.sum(matrix[1, :]) + np.sum(matrix[:, 2])


def squareme(matrix: np.ndarray, row: int) -> np.ndarray:
    if row < 1 or row > matrix.shape[0]:
        print("Row not found.")
        return np.array([])
    return matrix[row - 1] ** 2

    NumPy slicing — interactive version not running. JavaScript is switched off, or a script file is missing. The default matrix — 3 rows, 5 columns, seed 42 — and the three numbers add2and3 produces from it are below.

    The 3 by 5 matrix from seed 42. Row 1 sums to 25, column 2 sums to 21, and add2and3 returns 46
    Row Col 0 Col 1 Col 2 Col 3 Col 4
    Row 064861
    Row 152684
    Row 228731

    The element at row 1, column 2 is 6, and it belongs to both slices, so the answer 46 counts it twice.

    Key idea

    A[1, :] and A[:, 2] overlap in exactly one element, A[1, 2]. Adding the two sums therefore counts that element twice. That is what the reference solution does, so it is what the autograder expects — but it is a deliberate quirk of the exercise, not a general fact about summing rows and columns.

    Common mistake

    Mixing up index bases. NumPy indexes from 0, so row index 1 is the second row, but squareme's row parameter is documented as 1-indexed, which is why its body says matrix[row - 1]. Whenever a function takes a row or column number, check which base it means before you use it.

    Note

    The Lab 02 handout says add2and3 needs at least 3 rows and 4 columns, but the reference solution guards on at least 2 rows and 3 columns, and the test passes a 3 by 5 array. If your report states the precondition, state the one the code enforces, and say that the two disagree.

    0.12 Classes and functions

    # Permalink to topic 0.12, Classes and functions
    • ◐ During-class examples, partial

    This topic has no lab of its own; it is the live-coding material from the PythonOverview/ session. Four things get demonstrated there: default parameters, type hints, the mutable-argument trap, and classes with exception handling in the constructor.

    Definition

    Function
    A named block of code that takes parameters and returns a value.
    Default parameter
    A parameter with a value used when the caller does not supply one, written def add(a, b=1).
    Type hint
    An annotation such as a: int that says what a parameter is meant to be. Python does not enforce it at run time.
    Class
    A template for objects: attributes that hold data, and methods that act on them. __init__ is the method that runs when an object is created.
    Composition
    An object holding other objects — here, a Class that holds a list of Student objects.
    Python Functions, defaults, and type hints that are not enforced 
    def add(a, b):
    return a + b

print(add(1, 2))       # 3

# default parameter
def add(a, b=1):
    return a + b

print(add(1))          # 2
print(add(1, 2))       # 3

# a type hint is documentation, not a check
def addwithhints(a: int, b: int) -> int:
    return a + b

print(addwithhints(1.3, 2.34))   # 3.64 — two floats pass straight through

    Common mistake

    Passing a dictionary or a list into a function and changing it there changes the caller's object too, because the argument is a reference and not a copy. Copy it first if the caller should not see the change.

    Python Copying before mutating 
    my_dict = {"name": "John", "age": 30, "city": "New York"}

def change_dict(my_dict):
    new_dict = my_dict.copy()      # without this, the caller's dict changes too
    new_dict["name"] = "Jane"
    return new_dict

new_dict = change_dict(my_dict)
print(my_dict)     # unchanged: {'name': 'John', 'age': 30, 'city': 'New York'}

    The class example puts a try / except inside a constructor, which is where the ordering of exception handlers becomes visible. A specific handler is written before a general one; whichever matches first wins, and the rest are skipped.

    Python Classes, composition and exception handling 
    class Class:
    def __init__(self, name, students):
        self.name = name
        self.students = students

    def add_student(self, student):
        self.students.append(student)

    def get_students(self):
        return self.students


class Student:
    def __init__(self, name, age, hobbies, luckynumber):
        self.name = name
        try:
            self.age = age / luckynumber
            raise ValueError("Very bad text here")   # deliberately thrown
        except ZeroDivisionError:
            print("You have a very unlucky number")
            self.age = 50
        except Exception as e:
            print("It caught our value error")
            print(e)
        self.hobbies = hobbies

    def get_name(self):
        return self.name

    def set_name(self, name):
        self.name = name
    Python The driver that exercises it 
    from classclass import Student, Class

student1 = Student("John", 20, ["reading", "writing"], 1)
student2 = Student("Jane", 21, ["reading", "writing"], 0)
class1 = Class("Class 1", [student1, student2])

class1.add_student(Student("Jim", 22, ["reading", "writing"], 3))

print(class1.get_students())

student1.set_name("Zeus")
print(student1.get_name())     # Zeus

    Jim 22 3 except Exception It caught our value error / Very bad text here 7.333…

    Key idea

    The division is attempted first, so a lucky number of 0 never reaches the raise — ZeroDivisionError is thrown on the previous line and the first handler catches it. Any other lucky number lets the division succeed, the deliberate ValueError is thrown, and the broad handler catches that instead. Order the handlers specific first, general last, or the general one swallows everything.
