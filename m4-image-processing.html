    Image Processing

    4.1 Representation

    4.1.1 From scene to pixels

    # Permalink to topic 4.1.1, From scene to pixels
    • ● Slides
    • ● Tutorial

    A camera cannot store a scene. It can only store numbers, so the scene is simplified in four steps, and each step throws something away. A three-dimensional world is projected onto a two-dimensional view; the view is cropped to a rectangle; the rectangle is cut into a grid of small squares; and each square is assigned one colour, written as one number (grayscale) or three (RGB). That chain of simplifications is called discretization.

    Definition

    Discretization
    Representing a complicated “continuous” object by an orderly array of “discrete” numbers.
    Pixel
    One cell of that grid — a picture element. It has exactly one colour, no matter what was really there.
    Image (the working definition used all module)
    An M × N array of integers between 0 and MAXINT.

    The course states two goals for image processing, and it is worth keeping them apart because they pull in opposite directions: create a more satisfactory image for a human to look at, and extract hidden information for a program to act on. A filter that makes a photograph prettier can easily destroy the measurement you were trying to make.

    Stage-by-stage data for figure 4.1.1

    Figure 4.1.1 as text: what each stage of discretization produces and what it destroys
    Stage Produces Information destroyed
    1. ProjectionA perspective view of the sceneDepth: two objects at different distances can land on the same spot
    2. FramingA rectangle of that viewEverything outside the frame
    3. SamplingAn M by N grid of cellsEvery detail smaller than one cell
    4. QuantizationOne integer (or three) per cellEvery colour variation inside a cell, and every shade between two representable levels

    4.1.2 Pixels must disappear for realism

    # Permalink to topic 4.1.2, Pixels must disappear for realism
    • ● Slides
    • ● Tutorial

    Our picture elements are squares of colour. The eye is disturbed by them unless they are small enough to stop being visible individually, and the first thing that gives a coarse image away is not a face or a texture — it is a line, or an edge, which turns into a staircase.

    The slides use a 541 × 200 pixel night photograph: at normal size it reads as a smooth photograph, and the identical file zoomed in breaks into visible coloured squares. The rule of thumb given in class is that about 500 pixels in each direction are enough for a small image.

    Key idea

    Resolution is not a property of the file, it is a relationship between the file and the viewing distance. The same 541 × 200 array is “realistic” on a page and “pixelated” on a projector, without a single number changing.

    4.1.3 Colour as an RGB setting

    # Permalink to topic 4.1.3, Colour as an RGB setting
    • ● Slides
    • ● Tutorial

    A displayed colour is stored as three numbers: a red, a green and a blue setting. The values might be real numbers in [0, 1] or integers between 0 and 255. The model is additive — the three lights add up, so (0, 0, 0) is black (no light at all) and (255, 255, 255) is white.

    RGB triples and the colours they name

    The RGB triples named in the slides and the tutorial. No colour is used to convey the answer here: the name is the answer.
    Colour R G B Why
    Black000No light emitted
    Red25500Red channel only
    Green02550Green channel only
    Yellow2552550Red plus green; there is no yellow lamp
    Mid gray128128128All three equal — see 4.1.4
    White255255255All three at full intensity

    Common mistake

    RGB is not “all colour”. Plot the visible colours on the CIE chromaticity diagram and they fill a horseshoe; the colours a screen can make fill a triangle inside it. Some colours visible to the human eye cannot be represented by the RGB system at all, which is why matching a real colour to a displayed one is hard.

    4.1.4 Grayscale encoding, and where gray comes from

    # Permalink to topic 4.1.4, Grayscale encoding, and where gray comes from
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial

    A screen has no gray lamp. It has a red one, a green one and a blue one. The reason you see gray is a fact about the eye rather than about the hardware:

    Key idea

    As long as R = G = B, your eyes register the displayed colour as gray. At R = G = B = 0 you get black; at full intensity you get white light, not a colour.

    That is what makes grayscale worth a format of its own. If the three channels are always equal you are writing the same number three times, so a grayscale image needs one third of the data of the colour image that would display identically. Almost every format offers a grayscale mode for exactly this reason.

    The slides work the storage arithmetic out loud. One byte per grayscale pixel means a single large photograph can be 100 MB of pixels; a 90-minute film at 30 frames per second is about 5,000 seconds, so roughly 150,000 frames — of the order of 15 terabytes uncompressed. “So now you know one huge area of image compression.”

    4.1.5 Image bit representation and colour depth

    # Permalink to topic 4.1.5, Image bit representation and colour depth
    • ● Slides
    • ● Tutorial

    The number of bits per pixel decides how many distinct shades exist. FEEP uses the 16 integers 0 to 15, so each pixel needs 4 bits: it is a 4-bit grayscale image. A 1-bit image is a true black-and-white picture, with no gray at all. The common choice is 8-bit grayscale, values 0 to 255.

    Definition

    Colour depth
    The available range of grays or colours in an image — that is, the number of distinct values one pixel can take.

    Bits per pixel and the number of levels each gives

    A question the instructor asks directly: how many bits do I need to represent 256 numbers? Eight, because 28 = 256 — and that is exactly why 8-bit is the default.

    4.1.6 Unsigned short integers, and integers becoming reals

    # Permalink to topic 4.1.6, Unsigned short integers, and integers becoming reals
    • ● Slides
    • ● Tutorial

    Images are data-intensive, so cut the storage wherever you can. In most languages a plain int is 32 bits, and we only need 8. A signed 8-bit type spends one bit on the sign and covers −128 to +127 — but integers in images are always positive, so the right type is the unsigned one, uint8, covering 0 to 255.

    For arithmetic it is more convenient to think of a shade as a real number between 0 and 1, so that black is always 0.0 and white always 1.0 regardless of the bit depth:

    Shade from gray value

    S = G ÷ MAXINT

    S
    the shade, a real number in [0, 1]; 0.0 is black, 1.0 is white
    G
    the stored integer gray value of the pixel
    MAXINT
    the largest gray value the image declares — 15 for FEEP, 255 for 8-bit gray

    Common mistake

    Two uint8 traps, both of which cost students marks in Lab 09. First, a value above 255 wraps or clips when it is converted back to uint8: the slides call this “Procrustes”, after the innkeeper whose bed fitted every guest, and the fix is to rescale rather than truncate (see 4.4.2). Second, subtracting two uint8 arrays in NumPy wraps modulo 256, so A - B on unsigned data produces nonsense differences; cast to a signed or floating type first.

    Rescaling to the full range instead of clipping

    P ← 255 × ( P − pmin ) ÷ ( pmax − pmin )

    P
    the array of computed pixel values, before conversion back to uint8
    pmin, pmax
    the smallest and largest values actually present in P

    The two exercises set on this slide

    What happens if the data stays the same but MAXINT changes from 15 to 31? Nothing changes in the file’s pixel values, but every shade halves: S = G ÷ 31, so the value 15 that used to be white is now mid gray, and the whole picture goes dark. To keep the appearance you must rescale the data, not just the header.

    How do you make a negative? Replace every pixel by MAXINT − P. For 8-bit gray that is 255 − P, which is exactly the reverse video operation used on edge maps in 4.5.6. Both effects can be switched on in the PGM file reader.

    4.2 File Formats

    4.2.1 Images vs. formats

    # Permalink to topic 4.2.1, Images vs. formats
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial

    Keep two things separate. The image is an abstract mathematical object: an M × N matrix of pixel values. The format is a set of decisions about how to write that matrix into a file — row order, where the dimensions go, the maximum entry, integer or real arithmetic, the order of R, G and B, and what compression is applied.

    Key idea

    The image is the maths; the format is the filing. Once the array is inside the computer, the computer knows how to display it — everything else was a storage decision made by whoever wrote the file.

    Why can everyone not just agree on rows-then-columns, (R, G, B), 0 to 255? Because images serve photographers, animators, book publishers, mathematicians and medical technicians, and their needs differ vastly. Underneath all of them sits one hard fact: the raw information in a typical image is both enormous and redundant. Every format is a different bet about which redundancy is worth exploiting.

    Definition

    Lossless format
    Decoding the file returns exactly the original array. PNG, PGM, BMP and TIFF (in its usual modes) are lossless.
    Lossy format
    Decoding returns an array that only looks like the original. JPEG discards detail the eye is bad at noticing, and it cannot be recovered.

    This distinction is what Lab 09 Question 1 measures: convert a PNG to JPEG, subtract the two arrays, and check whether the total difference is zero. It is not.

    4.2.4 Run-length encoding

    # Permalink to topic 4.2.4, Run-length encoding
    • ● Slides

    Run-length encoding is the simplest compression there is, and it is the direct answer to reason 2 in 4.2.2 — images contain huge areas of the same colour.

    Definition

    Run-length encoding (RLE)
    Given a vector of pixel data, create a new array of pairs. The first item of a pair is a pixel value; the second is the number of times to repeat that value.

    The worked example in the slides takes the first three lines of the FEEP file. As raw data that is 72 values. Encoded as runs it is 42 numbers — 21 pairs.

    Two traps in Lab 09 Question 1

    Many PNG files downloaded from the web are RGBA — they carry an alpha channel. Image.save(..., 'JPEG') raises OSError: cannot write mode RGBA as JPEG, because JPEG has no alpha. Convert to RGB first.

    4.3 Global Operations

    Global means the rule is the same everywhere and depends only on a pixel’s own value, never on where it sits or who its neighbours are. Move every pixel of the image to a new position at random and a global operation gives exactly the same answer. That is the whole limitation of this section, and the reason section 4.4 exists.

    4.3.1 Image histograms

    # Permalink to topic 4.3.1, Image histograms
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial

    Before doing anything to an image, get statistics from it. The maximum and minimum are a start; the histogram is the whole story. It is the population census of the image’s pixel values.

    Definition

    Image histogram
    H(i) is the number of pixels in the image whose intensity is exactly i. Plotted, the x-axis is the value (0 = black, 255 = white) and the y-axis is the frequency.

    Four readings, from the tutorial:

    • Counts clustered to the left — the image is dark.
    • Counts clustered to the right — the image is bright.
    • Counts spread across the range — good contrast.
    • Counts crammed into a narrow band — low contrast, washed out.

    Common mistake

    The histogram throws away every bit of geometry. A square that is white on top and black on the bottom, and a checkerboard of the same white and black, have identical histograms. Anything you conclude from a histogram alone is a conclusion about the population of values, not about the picture.

    4.3.3 Contrast stretching

    # Permalink to topic 4.3.3, Contrast stretching
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial

    If the histogram says the image only uses values 50 to 100, then 60 per cent of the available shades are going unused and every difference in the picture is smaller than it needs to be. Contrast stretching is the technique of spreading the gray scale out over the range containing most of the information.

    Linear contrast stretch to the full 8-bit range

    Pnew = 255 × ( Pold − pmin ) ÷ ( pmax − pmin )

    Pold
    the pixel’s current value
    Pnew
    the value it is replaced by
    pmin, pmax
    the smallest and largest values found anywhere in the image
    255
    L − 1, where L is the number of intensity levels; use MAXINT for other depths

    Worked example from the tutorial. An image whose values run from 50 to 150 contains a pixel of value 100. Then 255 × (100 − 50) ÷ (150 − 50) = 255 × 0.5 = 127.5 — the midpoint of the narrow range lands on the midpoint of the full range, which is exactly what a linear map should do.

    The lecture’s version, “Experiment 1: lighten up”, is cruder and worth seeing because of what it costs:

    Python Experiment 1: double the darks, clip the lights 
    imgcopy = img.copy()                       # copy — see the note below
low_idx  = imgcopy < 128                    # identify dark grays
high_idx = imgcopy >= 128                   # identify light grays
imgcopy[low_idx]  = 2 * imgcopy[low_idx]   # double the darks
imgcopy[high_idx] = 255                    # set the lights to white
plt.imshow(imgcopy)                        # display

    Two things to notice

    The slide writes imgcopy = img, which in NumPy is not a copy — it is a second name for the same array, so the “experiment” destroys the original. Use img.copy(), as the next experiment on the slides correctly does.

    And this is not a stretch, it is a stretch plus a clip. Every pixel at or above 128 is forced to 255, so all of them become the same value and the detail between them is gone forever. In the lecture’s histograms that shows up as a new spike of about 7,400 pixels sitting at 255 that was not there before.

    4.3.4 Colour quantization and depth reduction

    # Permalink to topic 4.3.4, Colour quantization and depth reduction
    • ● Slides
    • ● Tutorial

    Definition

    Quantization / colour depth reduction
    The process of reducing the number of colours or shades used in an image. The reduced set can be chosen by hand, or by a clustering technique such as K-means. This is one way to compress an image.

    The lecture’s hand-made version is “Experiment 2: three shades of gray”. Reading break points off the histogram — 0, 25, 100, 255 — every pixel is snapped to one of three representative values:

    Python Experiment 2: reduce the image to three gray levels 
    idx_low  = img < 25
idx_mid  = (img >= 25) & (img < 100)
idx_high = img >= 100

imgcopy = img.copy()
imgcopy[idx_low]  = 25
imgcopy[idx_mid]  = 100
imgcopy[idx_high] = 175
plt.imshow(imgcopy)

    Note

    The break points are 0 : 25 : 100 : 255 but the values assigned are 25, 100 and 175 — not 0, 128 and 255. That is deliberate: it keeps the result off pure black and pure white, so the caption “black, white and one gray” is really dark gray, mid gray and near white. The picture stays recognisable with three values; all the texture is gone.

    Key idea

    Contrast stretching reveals information; quantization deliberately discards it. There is no single “best” version of an image, only the best representation for a purpose — a printer with three inks and a radiologist looking for a 2-value difference want opposite things.

    4.3.5 K-means for quantization (k = 3, k = 10)

    # Permalink to topic 4.3.5, K-means for quantization
    • ● Slides
    • ▣ Lab 11
    • ● Tutorial

    Experiment 2 was not automatic. Somebody looked at a histogram and said “let us change the data as follows”. To let a computer clean up or compress pictures on its own, the choice of representative values has to become an algorithm — and the one the course uses is K-means.

    Definition, as stated in the lecture

    K-means
    Given N items of data, find K “representative” values such that every data item can be assigned to a nearby representative.
    1. Initialise the centres C — at random, or spread evenly across the data range.
    2. Assignment step. For each data point P(I), set PTOC(I) to the index of the nearest centre.
    3. Update step. Replace each centre by the average of the P assigned to it.
    4. Repeat until no P is reassigned after the latest update. That is convergence.
    5. Recolour. Replace each pixel by its centre’s value.

    Replacing every shade by its representative reduces the colour complexity from N to K, so less memory is needed. On the course’s casablanca.pgm film still, k = 10 leaves faces still modelled with only faint banding in the background, while k = 3 flattens faces into patches yet the piano, the three figures and the room all stay readable.

    Python K-means quantization with scikit-learn 
    N = 16
kmeans = KMeans(n_clusters=N, random_state=N-1).fit(img.reshape(-1, 1))

# cluster centres, sorted so label order matches intensity order
centers = kmeans.cluster_centers_.flatten()
center_order = np.argsort(centers)
label_map = np.zeros_like(center_order)
label_map[center_order] = np.arange(N)

# map the labels back and scale to the full intensity range
imgcopy = label_map[kmeans.labels_].reshape(img.shape) * (255 / (N - 1))
imgcopy = imgcopy.astype(np.uint8)

    4.4 Local / Convolutional Operations

    In contrast stretching we completely ignored the geometry of the picture. We counted the pixels of each shade but did not care what was next to what, so a square that is half white over half black and a checkerboard of the same two colours would have been treated identically. Everything in this section looks at a pixel and its neighbours.

    4.4.1 The kernel: a window on a neighbourhood

    # Permalink to topic 4.4.1, The kernel: a window on a neighbourhood
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial
    • ★ Final

    A kernel is a small matrix — usually 3 × 3 — that is slid over every pixel of the image. Centre it on the target pixel, multiply each kernel cell by the pixel underneath it, add the products up, and write that single number into the output image at the target position. That operation is convolution.

    3 × 3 convolution at one pixel

    O(i, j) = ∑a=−1..1 ∑b=−1..1 K(a, b) · P(i+a, j+b)

    P
    the input image
    O
    the output image; a fresh array, never written back into P
    K
    the kernel, indexed from the centre so K(0, 0) sits on the target pixel
    i, j
    row and column of the target pixel

    Key idea — this is the whole section

    Blur, sharpen, denoise and edge-detect are the same operation. The only thing that differs is the nine numbers in the kernel. Learn the mechanism once and every filter below is a table lookup.

    Three details that are easy to get wrong

    Write to a second array. If you overwrite P as you go, the pixel to the right sees your new value instead of the original and the result is not a convolution at all.

    The border has no neighbourhood. A 3 × 3 kernel cannot be centred on row 1 or column 1. The course’s code loops i = 2 : m-1 and simply leaves the border alone; the alternatives are to pad with zeros, to replicate the edge pixel, or to crop the output. Lab 09 does not state a policy, so state yours in the report.

    The output may leave 0 to 255. A sharpening kernel can produce −40 or 300. Rescale (see 4.1.6) rather than let uint8 clip it.

    4.4.2 Local contrast enhancement

    # Permalink to topic 4.4.2, Local contrast enhancement
    • ● Slides
    • ● Tutorial

    Sometimes the contrast problem is local: an interesting feature is indicated only by a small shade change from one pixel to the next. Stretching the whole histogram will not fix that, because the feature is not at the ends of the range — it is a 3-level wobble somewhere in the middle.

    The lecture’s analogy: a globe made exactly to scale would be extremely smooth, and you could neither see nor feel Mount Everest on it. Relief globes exaggerate height far beyond true scale to make up for the limitations of our senses. Local contrast enhancement does the same thing to a pixel.

    Local contrast enhancement, in three steps

    average = ¼ ( P(I,J−1) + P(I−1,J) + P(I,J+1) + P(I+1,J) )

    height = P(I,J) − average

    P(I,J) ← average + S × height

    average
    the mean of the four NEWS neighbours — north, east, west, south
    height
    how far this pixel departs from what its neighbours predict; the nonzero height is the reason the pixel is interesting
    S
    the exaggeration parameter. S = 1 leaves the image unchanged; S > 1 sharpens; S < 1 flattens

    Key idea

    The last line is not an equation, it is an assignment statement. We are not solving for anything; we are deliberately changing the value of the pixel in the hope that the new image is more informative. Nothing guarantees the new value is “true”.

    Effect of the exaggeration parameter S

    The exaggeration parameter S on the course’s two examples, a washed-out surf photo and a cyclist over a pool
    S What the height does Result in the lecture’s images
    0.25Shrunk to a quarterBarely more separation between foam, water and sand than the original
    1UnchangedThe original image, exactly

    10Ten timesSpokes, diving-board frame, fence and pool-tile lines all distinct — and the noise is amplified just as much

    A worked identity from the tutorial, which is also a practice problem: at S = 2 the whole three-step recipe collapses into one convolution, because average and height are both linear in the pixel values. Expand it and you get 2Pcentre − ¼(N + E + W + S), which is the sharpening kernel in 4.4.11 up to a scale factor.

    4.4.5 Salt-and-pepper noise

    # Permalink to topic 4.4.5, Salt-and-pepper noise
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial

    The physical process of recording and storing an image is subject to disturbance and damage. In some devices — satellite scanners, ordinary cameras — the sensor fails to record the actual colour at a pixel position and instead reports either the highest or the lowest possible value. In a grayscale image that appears as a scattering of pure black and pure white spots.

    Definition

    Salt-and-pepper (impulse) noise
    A small fraction of pixels are replaced by an extreme value — 0 (pepper) or the maximum, 255 (salt). The rest of the image is untouched.

    Three observations from the lecture explain why it is worth treating at all:

    1. An image has a lot of extra information in it — most of it consists of pixels of roughly the same colour as their neighbours.
    2. The eye is very sensitive to sudden changes in colour or brightness. Even if 99 per cent of the pixels are good, the eye goes straight to the bad ones.
    3. Salt-and-pepper interrupts a smooth region with a single extreme, meaningless value. Averaging only dilutes that value — it would be better if we could ignore it.

    That third observation is the argument for the median, and the exam matrix in the next topic is a four-by-five image with exactly this damage: a 0 and a 15 sitting in a field of 2s, 3s, 4s and 5s.

    4.4.6 Median filter

    # Permalink to topic 4.4.6, Median filter
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial
    • ★ Final

    Replace each pixel by the median of its neighbourhood: sort the nine values in the 3 × 3 window and take the middle one, the fifth. An extreme value can only ever be the first or the last after sorting, so it is discarded rather than diluted.

    Key idea

    The median filter is non-linear. It is not a convolution, there is no kernel of weights, and you cannot compose two of them into one. What it buys you is that a wrong value has no influence at all on the answer, rather than one-ninth of the influence.

    Python 3 × 3 median filter, written out in full 
    import numpy as np

p  = image.astype(float)
m, n = p.shape
p2 = p.copy()                      # write into a SECOND array

for i in range(1, m - 1):          # skip the border: no full window there
    for j in range(1, n - 1):
        window = [p[i-1, j-1], p[i-1, j], p[i-1, j+1],
                  p[i,   j-1], p[i,   j], p[i,   j+1],
                  p[i+1, j-1], p[i+1, j], p[i+1, j+1]]
        p2[i, j] = np.median(window)

filtered = p2.astype(np.uint8)

    4.4.8 Gaussian noise

    # Permalink to topic 4.4.8, Gaussian noise
    • ● Slides
    • ● Tutorial

    Salt-and-pepper was relatively easy to detect and treat, because the damaged pixels announce themselves. More often every pixel of an image is a little bit wrong. The simplest model of that uses the Gaussian function, the bell curve: small errors are very probable and big errors happen occasionally.

    The 2-D Gaussian used all through this module

Unless the camera is perfect, the light from a single point in the object does not land in exactly one pixel — it also spills into the neighbours, by blurring. So a neighbour is not just another sample of the scene, it holds partial information about this pixel. If the central pixel is corrupt, or even missing, its neighbours can be used to recover a good estimate of the correct value.

    4.4.9 Gaussian filter: weighted averaging

    # Permalink to topic 4.4.9, Gaussian filter: weighted averaging
    • ● Slides
    • ▣ Lab 09
    • ● Tutorial

    The technique is called Gaussian averaging, or filtering, or smoothing. Choose a neighbourhood around each pixel — a 3 × 3 or 5 × 5 block with the pixel at the centre — and replace the pixel by a weighted average of the block, with the weights taken from the Gaussian surface. The original pixel dominates the result, but the neighbours influence its new value.

    Key idea — what σ actually controls

    σ is how much you trust the neighbours relative to the centre. Reduce it and you are believing the central pixel most; increase it and the neighbours get a stronger say. As σ or the neighbourhood size grows, the processed picture goes from sharp and noisy, to smooth, to blurry. There is no setting that removes noise without removing detail — the two are the same operation seen from different sides.

    4.4.10 Computing kernel coefficients

    # Permalink to topic 4.4.10, Computing kernel coefficients
    • ● Slides
    • ● Tutorial

    Where do the numbers in a Gaussian kernel come from? Evaluate the Gaussian at each cell’s offset from the centre, then divide every entry by the total so the weights sum to 1. The normalisation is the step that matters: without it the filter changes the overall brightness of the image.

    Kernel coefficients for an n × n Gaussian

    wij = exp( −( (i−c)2 + (j−c)2 ) ÷ ( 2v ) )

    w ← w ÷ ∑ w

    n
    the neighbourhood size — 3, 5, 7 and so on, always odd so there is a centre
    c
    the centre index, ⌊n÷2⌋ counting from 0
    v
    the variance, σ2
    ∑w
    the sum of every unnormalised weight; dividing by it makes the kernel sum to exactly 1
    Python Generating an n by n Gaussian kernel 
    import numpy as np

def gaussian_kernel(n, v):
    """n = 3, 5, 7 ... (size of neighbourhood); v = variance = sigma * sigma"""
    c = n // 2
    w = np.empty((n, n))
    for i in range(n):
        for j in range(n):
            w[i, j] = np.exp(-(((i - c) ** 2 + (j - c) ** 2) / (2 * v)))
    return w / w.sum()          # <-- the step that is easy to forget

    Common mistake

    Forgetting w / w.sum(). An unnormalised 3 × 3 Gaussian at σ = 1 sums to about 4.90, so applying it multiplies every pixel by roughly five and the whole image saturates to white. Any kernel that is meant to preserve brightness — box, Gaussian, sharpen — must sum to 1. Kernels that are meant to measure a difference — Sobel, Prewitt, Laplacian — sum to 0 instead, for the same reason in reverse: a flat region must give zero.

    4.4.12 Bilateral filter

    # Permalink to topic 4.4.12, Bilateral filter
    • ○ Not in slides

    A Gaussian filter blurs edges because it weights a neighbour purely on how far away it is. The bilateral filter adds a second weight based on how different in value the neighbour is, so a neighbour on the far side of an edge is discounted and the edge survives the smoothing.

    Bilateral weight for a neighbour q of pixel p

    w(p, q) = exp( −d2 ÷ 2σs2 ) × exp( −( Ip − Iq )2 ÷ 2σr2 )

    d
    the distance from p to q in pixels — the spatial term, identical to the Gaussian filter
    σs
    the spatial standard deviation; how far the filter reaches
    Ip, Iq
    the two pixels’ intensities
    σr
    the range standard deviation; how different two intensities may be before the neighbour is ignored

    As with every averaging kernel, the nine weights are divided by their total before use so that a flat region is unchanged.

    Key idea, and its failure case

    Edge-preserving smoothing sounds strictly better, and against Gaussian grain it is. Against salt-and-pepper it is the worst filter of the five: a corrupted pixel is, by definition, wildly different from its neighbours, so the range term drives every neighbour’s weight to nearly zero and the filter faithfully preserves the corruption. The demo in 4.4.7 measures this — bilateral leaves an MSE of 3938 where the median leaves 19.

    Note also that the bilateral filter is not a convolution: its weights depend on the pixel values, so they are different at every position. Like the median filter, it is non-linear.

    4.5 Edge Detection

    The eye does several things so automatically that we cannot explain how: recognising edges, judging the extent of an object, spotting movement, recognising an object rotated or badly lit, recognising a face that is never the same twice. Recognising edges is one of the simpler tasks on that list, and it is the one this section builds.

    4.5.1 What is an edge? Slope measures change

    # Permalink to topic 4.5.1, What is an edge? Slope measures change

    “If we are walking in the park and we come to an edge, we are surprised. This suggests that an edge represents a difference between what we expect and what we encounter.” We do not call it an edge when the ground slopes up or down at about the same rate the whole way. So:

    Key idea

    A linear function is expected and predictable, and an edge occurs when linear behaviour is disrupted. Brightness changing everywhere is not an edge; brightness changing suddenly is.

    4.5.2 Building an edge detector: the E statistic

    # Permalink to topic 4.5.2, Building an edge detector: the E statistic
    • ● Slides
    • ● Tutorial

    A slope of large magnitude, in either direction, says something is changing fast over a short range. That is what we mean by an edge. So take the absolute value of both slopes and add them:

    The E statistic, also called the NEWS value

    E = |P(I,J+1) − P(I,J−1)| + |P(I+1,J) − P(I−1,J)|

    E
    the edge strength at this pixel: zero where the pixels are flat, large where nearby values differ a lot
    the two absolute values
    the horizontal and vertical slope magnitudes; taking absolute values means a dark-to-light edge scores the same as light-to-dark
    NEWS
    north, east, west, south — the four neighbours the statistic combines

    Computing E everywhere gives a new image, the E image: black wherever the original is flat, bright wherever it changes. On the course’s coins.png the coin rims and the embossed lettering glow and the background is black.

    What E does not do

    Two honest limitations, both stated in the lecture. First, E only looks for large slopes; a better indicator would check for large changes in the slope, that is, an estimate of the second derivative — see the discrete Laplacian in 4.4.11. Second, we have not “recognised” anything yet. A single black pixel in a sea of white gets a high E. Is that an edge? To really recognise edges we would have to process the E array further, looking for lines and curves that seem to indicate the borders of objects — which is where section 4.6 starts.

The Sobel operator uses six: it differences the two columns (or rows) on either side of the target and weights the middle one double, which smooths the estimate and makes it far less jumpy on noisy data. It is the standard gradient operator and the one the final exam uses.

    A bug in the 2025 dashboard

    4.6 Segmentation & Morphology

    4.6.1 Goal of segmentation

    # Permalink to topic 4.6.1, Goal of segmentation
    • ● Slides
    • ● Tutorial

    Edge detection ended with a pile of pixels that have a high E value. We never asked whether those pixels were scattered or organised into lines, edges and boundaries. To count the coins in the photograph we need two things: detect the edges, and then group the pixels that form an edge into an object.

    Key idea

    Everything before this section produced another image. Segmentation produces a list of objects. That is the jump from a grid of numbers to something a program can count, measure and reason about — and it is another thing your brain does automatically and a computer finds hard.

    To make it tractable, simplify: assume the array holds 1 for the thing we care about and 0 otherwise, obtainable by thresholding (4.3.6). Then the goal is exactly two questions:

    • How many connected components are there?
    • What is the size of each component?

    This is the connected-component problem from graph theory, met in M3 §3.3 — except that here the graph is implicit. Nobody hands you an edge list; the edges are wherever two pixels touch, and that regularity is what makes the image version so much easier than the general one.

    4.6.3 Two-pass labeling algorithm (2-D)

    # Permalink to topic 4.6.3, Two-pass labeling algorithm in 2-D

    Even though the problem is two-dimensional, the algorithm walks the pixels linearly, one row at a time. That immediately raises two questions the lecture asks out loud: what if the last pixel of one row and the first of the next are both non-zero, and how do we handle a pixel that is related to pixels above it as well as to those to the left?

    Key idea — the shape of the algorithm

    Make cheap, purely local decisions in pass one, accept that some of them will be wrong, record the contradictions as you meet them, and defer the globally-informed resolution to a second pass. That design pattern is worth more than the algorithm itself.

    1. First pass (4.6.4): raster-scan the image, giving every foreground pixel a provisional label from its already-visited neighbours, inventing a new label when it has none, and recording an equivalence whenever two different labels turn out to touch.
    2. Resolution (4.6.5): follow every equivalence chain to its smallest label, then renumber those roots 1, 2, 3, …
    3. Second pass: sweep the label array once more, replacing every provisional label with its final one.

    Walk the array one row at a time, left to right. At each foreground pixel look backwards (the pixel to the left) and upwards (the pixel above) — the only two neighbours that have already been visited under 4-connectivity. There are exactly four cases.

    Pseudocode First pass of the two-pass labelling algorithm 
    l = 0
for i in rows:
    for j in columns:

        if p[i, j] == 0:                       # background
            label[i, j] = 0

        elif LEFT is background and ABOVE is background:
            l = l + 1                          # Case 1: new component
            label[i, j] = l

        elif LEFT is background:               # Case 2: continue
            label[i, j] = label[ABOVE]

        elif ABOVE is background:              # Case 2: continue
            label[i, j] = label[LEFT]

        else:                                  # Case 3: merge
            label[i, j] = min(label[LEFT], label[ABOVE])
            record that label[LEFT] and label[ABOVE] are equivalent

    Note on the slide version

    The lecture slide mixes Python’s elif with MATLAB’s elseif, carries stray semicolons, and uses LEFT and ABOVE as if they were indices. It is pseudocode, not runnable Python; the version above is the same logic written coherently. The slide also omits the last line — recording the equivalence — which is the line that makes the second pass possible.

    After one sweep of the comb pattern the algorithm has used 6 provisional labels for what are really 4 components. In the lecture’s larger example it is 15 labels for 6 components. The first sweep always over-identifies; that is expected, not a bug.

    Common mistake

    Taking the minimum in the merge case is not optional bookkeeping — it is what guarantees each component converges on a single root label rather than cycling. And the merge case must record the equivalence even though it also assigns the minimum; the pixels already labelled with the larger value are behind you and will not be revisited in this pass.

    4.6.5 Equivalence table and label adjustment

    # Permalink to topic 4.6.5, Equivalence table and label adjustment
    • ● Slides
    • ● Tutorial

    The diagnosis. If a pixel has two non-zero neighbours, left and above, and their labels do not match, we have a problem. The good news is that we always know when it happens, and the cure is to remember that one label must later be replaced by the other.

    And it chains. Once we realise that 1 and 5 label the same component, we must replace every 5 by a 1. Then we find that 10s should become 7s and 7s should become 1s — so really 10s should be 1s too.

    Key idea — the fact that makes this work

    A component might have multiple labels, but a label never refers to two different components. So if we simply choose one label per component, the problem is sorted out. The rule is: when given two labels, keep the lower one.

    Keep an index array recording the adjustment made to each label. Walking it finds the minimum label of each component; then a final array renumbers those roots consecutively from 1. In the lecture’s example, 15 provisional labels resolve to 6 components:

    4.6.6 4-connected vs. 8-connected

    # Permalink to topic 4.6.6, 4-connected versus 8-connected
    • ◐ Slides, partial

    “We naturally think of a pixel as being connected to the 4 neighbouring pixels that touch it.” That is 4-connectivity: the neighbours that share an edge. 8-connectivity also counts the four that share only a corner. Which one you choose changes the answer, and neither is more correct than the other — it is a modelling decision you have to state.

That is the only change needed in the code of 4.6.4 — and with four neighbours instead of two there are more merges, so the equivalence table does more work.

    It changes the answer

    On the demo’s diagonal staircase pattern the count goes from 6 components under 4-connectivity to 3 under 8-connectivity. On the default comb pattern it goes from 4 to 3. Neither number is wrong; they answer different questions. Report which rule you used. The 2025 dashboard offered a 4-versus-8 radio button and ignored it — it always ran 4-connectivity — which is exactly the sort of silent disagreement between control and computation this rebuild exists to remove.

    So the 3-D first pass is: when you meet a non-zero voxel, if it has no back neighbours, increment l and use it; otherwise label it with the minimum of the labels of the three back neighbours; and if several back neighbours carry different labels, make them all point at the minimum. Then walk the label array looking for unique labels and relabel, as in 4.6.5.

    Key idea

    The pattern “look only at already-visited neighbours, record conflicts, resolve later” is dimension-independent. Going from 1-D to 2-D to 3-D changes a constant — 1, 2, 3 back neighbours — and nothing else. That is why the lecture spends a whole slide on the one-dimensional case that nobody needs: it is the algorithm with the difficulty removed.

    4.6.8 Real-world example: MRI

    # Permalink to topic 4.6.8, Real-world example: MRI

    A strong magnetic field is applied to a specimen and radio-frequency signals measure the response; the scanner records that response over a grid of small regions. Skin, bone, spinal fluid and brain matter each have typical response values, and a tumour registers differently. The course’s example slice is a 64 × 64 array of integers between 0 and 255, in which tumour response is estimated to fall between 200 and 255.

    Why the components step is the one that matters

    “If we know there are 30 boxes that showed tumour response, we still need to know if those 30 boxes are scattered, or form a single, continuous mass.” Counting bright pixels is a histogram question and takes one pass. Deciding whether they are one object or thirty is a connectivity question, and the two answers mean completely different things to a clinician.

    Because every pixel and voxel now carries a component number, you can select any component and change its position, size or colour, hide it, or move it into a separate image. That is the practical payoff: the image has become a list of objects you can address individually.

    4.6.9 Binary images and the set language

    # Permalink to topic 4.6.9, Binary images and the set language
    • ● Slides, supplementary deck
    • ◐ Tutorial, partial

    Definition

    Binary image
    An image whose pixels take only two values: 1 (foreground, the object) and 0 (background). Equivalently, a set — the set of coordinates where the value is 1.

    That second reading is the one morphology is built on. Once a binary image is a set of positions, every operation of set theory is available and means something pictorial. This is why the supplementary deck opens with six Venn diagrams before it defines a single operator.

    Set operations and what each does to a binary image

    The set vocabulary morphology is written in. A and B are binary images over the same grid U.
    Notation Name A pixel is in the result when… What it does to the picture
    A ∪ BUnionit is 1 in A or in B or bothMerges the two shapes into one
    A ∩ BIntersectionit is 1 in bothKeeps only the overlap
    A′Complementit is 0 in ASwaps object and background — the binary version of reverse video
    A − BDifferenceit is 1 in A and 0 in BBites B’s shape out of A
    A ⊆ BSubset(a statement, not an image) every 1 of A is a 1 of BA fits entirely inside B — this is the test erosion performs
    A ∩ B = ∅Disjoint(a statement) they share no 1The shapes do not touch at all — the test dilation performs, negated

    The last two rows are the payoff. Dilation asks “do these two sets overlap at all?” and erosion asks “does this set fit entirely inside?” Everything in 4.6.10 and 4.6.11 is one of those two questions asked once per pixel.

    The structuring element

    Morphology compares the image with a second, much smaller binary image called the structuring element, usually written B. It is the probe: a small shape, with a designated origin, that gets moved to every position in the image. Two operations on it appear in the definitions.

    4.6.10 Morphology: dilation

    # Permalink to topic 4.6.10, Morphology: dilation

    • ✚ New for 2026

    Dilation

    A ⊕ B = { z : ( Bz ∩ A ) ≠ ∅ }

    A
    the binary image, read as the set of foreground positions
    B
    the structuring element
    Bz
    B moved so its origin sits on position z
    ≠ ∅
    “is not empty” — the probe overlaps the object somewhere

    Read it in words

    Put the probe down at position z. If it touches the object anywhere at all, mark z as foreground. Dilation grows the object by roughly the radius of the probe: it fattens shapes, closes small gaps, joins things that were nearly touching, and fills small holes.

    Worked example — final exam, dilation part

    The exam gives a 4 × 5 binary image with four foreground pixels forming a T-shape, and the 3 × 3 cross structuring element.

    Dilation of the exam binary image

    The exam’s binary image before and after dilation with the cross element. Foreground goes from 4 pixels to 12.

    r100000after01110
    r201110after11111
    r300100after01110

    One step in detail. Take z = row 1, column 2, which is background in the input. Place the cross there: its five offsets cover (0,2), (1,1), (1,2), (1,3) and (2,2) in 1-indexed row-column terms — of which (1,2), (1,1), (1,3) are off the top or are background, but (2,2) is foreground. The intersection is not empty, so row 1 column 2 becomes 1. The T-shape has grown upwards by one pixel.

    The effect, in one sentence for the exam: dilation expands the object outward by the size of the structuring element, filling in small gaps and connecting nearby regions — here the four-pixel T becomes a twelve-pixel cross-shaped blob.

    Border convention

    When the probe hangs off the edge of the image, the off-image cells are treated as background. That is what this page and the demo do, and it is the usual convention. Say which convention you used; the alternative (treating off-image cells as foreground) changes erosion results at the border completely.

    Erosion

    A ⊖ B = { z : Bz ⊆ A }

    Bz ⊆ A
    the whole probe, placed at z, lies inside the object — every cell of the probe sits on a foreground pixel
    A, B, z
    as in 4.6.10

    Read it in words

    Put the probe down at position z. Only if it fits entirely inside the object, mark z as foreground. Erosion shrinks the object by roughly the radius of the probe: it thins shapes, deletes anything smaller than the probe outright, opens up narrow bridges, and enlarges holes.

    Dilation and erosion are duals: eroding the object is the same as dilating the background. Neither is the inverse of the other — you cannot undo an erosion by dilating, and that failure is exactly what makes opening and closing useful (4.6.12).

    Worked example — final exam, erosion part

    Same 4 × 5 image, same cross element. The answer is every pixel 0 — the object vanishes.

    Why: for the cross to fit, a pixel needs itself and all four of its N/E/W/S neighbours to be foreground. The only candidate is row 2 column 3, which has foreground left, right and below — but row 1 column 3 above it is background. So the test fails there too, and it fails everywhere else more obviously. The object is thinner than the structuring element, so erosion wipes it out.

    4.6.12 Uses of morphological operators: opening and closing

    # Permalink to topic 4.6.12, Uses of morphological operators: opening and closing
    • ● Slides, supplementary deck
    • ✚ New for 2026

    Dilation alone fattens everything; erosion alone thins everything. Compose them in the two possible orders and you get operators that change small features while leaving the overall size of the object alone.

    Opening and closing

    A ◦ B = ( A ⊖ B ) ⊕ B     (erode, then dilate)

    A • B = ( A ⊕ B ) ⊖ B     (dilate, then erode)

    ◦
    opening: erosion first. Anything the probe could not fit inside is destroyed by the erosion and there is nothing left for the dilation to grow back
    •
    closing: dilation first. Gaps and holes smaller than the probe are filled by the dilation and the erosion cannot reopen them
    order
    the two are not the same operation; swapping the order is the whole difference

    The four operators and the job each one does

    The four morphological operators, what each one changes, and the practical job it is used for
    Operator Definition Effect on the object Job it is used for
    Dilation A ⊕ B Probe touches the object anywhere Grows; overall size increases Bridging a broken line; filling small holes; recovering an object thinned by noise
    Erosion A ⊖ B Probe fits entirely inside Shrinks; overall size decreases Separating objects joined by a thin bridge; deleting anything smaller than the probe; finding the “core” of a shape
    Opening A ◦ B Erode then dilate Removes thin spurs and isolated specks; the main body keeps its size Despeckle. Removing salt noise from a binary image without shrinking the objects
    Closing A • B Dilate then erode Fills small holes and notches; the outline keeps its size Hole fill. Repairing a region that thresholding punched holes in

    The three jobs on the lecture’s “Uses” plate

    The supplementary deck shows three input-and-output pairs with no text at all. They are: (a) despeckle — shapes plus scattered white specks and thin streaks, of which only the three large shapes survive, which is an opening; (b) hole fill — blobs with black holes and a thin branching artefact, coming out smoothed with the holes filled, which is a closing followed by an opening; and (c) separate touching objects — overlapping white shapes pulled apart and shrunk, which is an erosion, usually followed by connected-component labelling to count them.

    The numbers in the demo make (a) and (b) exact. On the nine-by-nine block with four isolated specks, opening with the square element takes the foreground from 29 pixels to 25 — precisely the 5 × 5 block, with all four specks gone. On the nine-by-nine block with a one-pixel hole, closing takes it from 48 to 49 — the hole filled, the outline untouched, while opening leaves all 48 exactly as they were.

    The exercise this section is for

    The supplementary deck ends with a graded exercise: a photograph of about seventeen peppercorns, two of which touch and read as a single blob. Can we count the objects in this image? The full pipeline is this whole module in order: threshold to binary (4.3.6), open to despeckle (here), erode to break the touching pair apart (4.6.11), label the connected components (4.6.3), and count them (4.6.1).
