    1.1 Brute Force

    1.1.1 The brute-force philosophy: generate and test

    # Permalink to topic 1.1.1, The brute-force philosophy: generate and test
    • ● Slides
    • ● Tutorial
    • ▣ Lab 03

    Brute force is what you reach for before you are clever. The lecture puts it plainly: given a problem, the first pass is often brute force. It is a conceptually simple approach; however, it is usually not the best method.

    Definition

    Generate and test
    A two-step paradigm. Generate: enumerate every candidate solution the problem allows. Test: check each candidate against the requirement and keep the ones that pass.

    The trade-off is worth stating out loud, because it is the reason the rest of this module exists. Brute force is universal — if you can enumerate the candidates you can solve the problem, and you are guaranteed the right answer given enough time. Brute force is also explosive — the number of candidates usually grows far faster than the size of the input.

    Where brute force is used in practice

    Where brute force shows up in practice, from the tutorial's motivation section
    Field What is generated What is tested
    CybersecurityEvery possible password stringDoes it unlock the account?
    Data scienceEvery subset of the available featuresDoes this subset predict best?
    LogisticsEvery tour through the citiesIs this tour the shortest?
    PuzzlesEvery digit in every empty Sudoku cellDoes the grid stay legal?

    Key idea

    A brute-force solution is not a failure — it is a baseline. It gives you a correct answer to compare against, and a cost to beat. Three of this module's five strategies are defined by how they improve on it.

    The three canonical brute-force algorithms in this course are selection sort (1.1.2), bubble sort (1.1.3) and sequential search (1.1.4). Lab 03 asks you to implement the first two from scratch.

    1.1.2 Selection sort

    # Permalink to topic 1.1.2, Selection sort
    • ● Slides
    • ● Tutorial
    • ▣ Lab 03
    • ★ Midterm

    Selection sort builds the answer one position at a time. Walk left to right; at each position, find the smallest value still to its right and swap it in. Once a position has been filled it is never touched again.

    Definition

    The selection-sort rule (stated verbatim in the slides)
    Take the current element and swap it with the smallest element on its right.

    Input: an n-dimensional array a = [a(1), a(2), …, a(n)]. Output: the same n-dimensional array a, with its entries sorted in ascending order.

    Selection sort worked by hand on the lecture's four-element array

    Selection sort on [17, 31, 6, 4], the array worked by hand in the lecture
    Step Array before Smallest on the right Array after Positions now final
    Step 1[17, 31, 6, 4]4[4, 31, 6, 17]1
    Step 2[4, 31, 6, 17]6[4, 6, 31, 17]2
    Step 3[4, 6, 31, 17]17[4, 6, 17, 31]4 — sorted
    Pseudocode Selection sort, as given in the lecture 
    % look at each position in turn
for i = 1, n-1

    min_loc = i     % initialize

    % find location of smallest element on right
    for j = i+1, n
        if ( a(j) < a(min_loc) ) min_loc = j
    end for loop over j

    swap a(i) and a(min_loc)  % the actual swap

end for loop over i

    Note

    The pseudocode is 1-indexed, so the outer loop stops at n−1: once the first n−1 positions hold their final values, the last one has nothing left to compete with. Lab 03's Python version is 0-indexed — translate the bounds, do not copy them.

    1.1.3 Bubble sort

    # Permalink to topic 1.1.3, Bubble sort
    • ● Slides
    • ● Tutorial
    • ▣ Lab 03
    • ★ Midterm

    Bubble sort never looks further than the pair in front of it. Sweep left to right comparing neighbours; swap any pair that is out of order. The largest value reaches the far end after the first sweep — which is where the name comes from, the largest entry "bubbles up" to the top.

    Definition

    The bubble-sort rule (stated verbatim in the slides)
    Moving left to right, compare consecutive elements and switch them if they are out of order. Continue until no swaps are made through an entire sweep.

    The stopping condition is the interesting part: bubble sort stops as soon as a whole sweep passes without a single swap. That is what makes its best case cheap (see 1.4.6) and it is why selection sort and bubble sort do not have the same best-case cost even though both are quadratic in the worst case.

    Note — two versions of the same sort

    The rule as stated sweeps the whole array every time, and the lecture's hand trace does exactly that: three comparisons per sweep on a four-element array. The usual optimisation notices that after sweep k the last k entries are already final, and shortens each sweep by one. Both are bubble sort and both are O(n2); the shortened version makes n(n−1)/2 comparisons in the worst case and the full version makes (n−1)2. The demo below runs either.

    1.1.4 Sequential (linear) search

    # Permalink to topic 1.1.4, Sequential (linear) search
    • ● Slides
    • ● Tutorial
    • ▣ Lab 04

    Suppose we want to find the element of a list or array equal to a given value, called the search key. The key can be a number — find 17 — or a string — find 'miami'. Brute force checks them in order and stops the moment it succeeds.

    Definition

    Sequential search, given a list a and a search key K
    Is a(1) = K? If so, stop. Otherwise continue. Is a(2) = K? If so, stop. Otherwise continue. Keep going until you find an i with a(i) = K, or the list is exhausted.
    Pseudocode Sequential search, from the tutorial 
    // input:  list a of length n, search key K
// output: the index of a match, or -1 if there is none
for i = 1 to n
    if a[i] == K
        return i        // found it
    end if
end for
return -1

    Two properties matter. Sequential search needs no precondition — the data does not have to be sorted, which is exactly what binary search (1.2.2) demands in exchange for being faster. And its cost is proportional to n: at worst it looks at every element, so it is O(n).

    Note

    Like bubble sort, the lecture ends this frame with "Exercise: write pseudocode and estimate the computational cost for a list of size n." Lab 04 makes you do it for real, counting codons inside a protein string (1.5.3).

    1.1.5 Computational cost of brute force

    # Permalink to topic 1.1.5, Computational cost of brute force
    • ● Slides
    • ● Tutorial
    • ◐ Lab 03, partial
    • ★ Midterm

    The amount of work depends on the size of the array, n. The lecture works the count for selection sort from a particular case to a general one — its words: "I like to go from particular to general, so let me first set n = 4, and manually count the number of operations."

    Two summation identities do all the algebra in this module, so they are worth memorising.

    The two series formulae

    ∑i=1n i = n(n+1) / 2     ∑i=1n i2 = n(n+1)(2n+1) / 6

    n
    the size of the array — the problem size
    i
    the summation index, running over the outer loop's positions

    Next, pick the operation of interest. For a sort, the key work done by the algorithm is the comparison — the if ( a(j) < a(min_loc) ) test inside the inner loop. Each (i, j) pair costs exactly one comparison, so counting the work means counting the pairs.

    Summing the general column over the outer loop gives the exact count.

    Exact comparison count for selection sort

    C(n) = ∑i=1n−1 (n − i) = n(n − 1) − n(n − 1) / 2 = n2/2 − n/2

The table below is the same information as the lecture's log–log plot of the two curves: by n = 20 the linear correction is a rounding error, and beyond that the two are indistinguishable on a plot. So we say the algorithm is quadratic in n, or O(n2).

    Key idea

    Selection sort makes n2/2 − n/2 comparisons no matter what the array contains. There is no early exit, so the best case and the worst case are the same — a fact the midterm asks about directly (1.4.6).

    1.2 Divide and Conquer

    1.2.1 Divide–conquer–combine framework

    # Permalink to topic 1.2.1, Divide–conquer–combine framework
    • ● Slides
    • ● Tutorial

    The basic idea, in the lecture's words: divide the problem into several smaller problems of the same type; each sub-problem may be divided further. The tutorial names the three stages.

    Definition

    Divide
    Split the instance into two or more sub-problems of the same type, ideally of equal size.
    Conquer
    Solve each sub-problem the same way. Recursion bottoms out at a base case small enough to solve directly.
    Combine
    Merge the sub-solutions into a solution for the original instance.

    The step that decides whether the strategy pays is combine. If merging two half-answers is cheap, halving the problem halves the work and you win. If merging is as expensive as solving, you have gained nothing.

    Worked example: maximum subarray sum

    This is the exercise deck's divide-and-conquer problem, and it shows both halves of the module at once. You are given an array of integers A, which may include both positive and negative numbers. Find the contiguous subarray with the maximum sum. A contains at least one number.

    The worked maximum-subarray example from the exercises deck

    Maximum subarray sum for A = [−2, 1, −3, 4, −1, 2, 1, −5, 4]
    Quantity Value
    Input array A[−2, 1, −3, 4, −1, 2, 1, −5, 4]
    Best contiguous subarray[4, −1, 2, 1]
    Its positions in A4 through 7 (1-indexed)
    Maximum sum6

    The exercise gives two routes to that answer, and the contrast is the whole point.

    Brute force and divide and conquer, step by step

    Two approaches to maximum subarray sum, as written in the exercises deck
    Step Brute-force approach Divide-and-conquer approach
    1Generate all possible subarrays.Divide the array into two halves.
    2Calculate the sum for each subarray.Find the maximum subarray sum in each half.
    3Return the maximum sum.Find the maximum subarray sum crossing the midpoint.
    4—Return the maximum among the three sums.

    Key idea

    Step 3 of the divide-and-conquer route is the combine step, and it is the only part that is not recursive. A subarray that straddles the midpoint belongs to neither half, so it has to be handled explicitly — forgetting it is the classic wrong answer to this problem.

    1.2.2 Binary search

    # Permalink to topic 1.2.2, Binary search
    • ● Slides
    • ● Tutorial
    • ◐ Lab 04, partial

    Now suppose you are given a sorted array or list and asked to search for a certain item — looking up a word in a dictionary, or a number in a phone book. You may not use dictionaries or phone books, but the computer still has to. We could use sequential search, but that seems terribly inefficient when the data is already in order.

    Definition

    Binary search (also: half-interval search)
    Check the middle entry of the array. If it is not equal to the key, work out which half of the array to discard, and repeat on the half that survives. After one step the problem has been cut down by half.

    Worked example: find 17

    Find the location where 17 occurs in the sorted array a = [1, 4, 7, 9, 17, 31, 33]. The array has n = 7 elements.

    Binary search trace for the lecture's worked example

    Binary search for 17 in [1, 4, 7, 9, 17, 31, 33]: three comparisons, found at position 5
    Comparison Interval still in play Middle entry Test What survives
    1[1, 4, 7, 9, 17, 31, 33]a(4) = 917 > 9 — discard the first half[17, 31, 33]
    2[17, 31, 33]a(6) = 3117 < 31 — discard the second half[17]
    3[17]a(5) = 1717 = 17 — foundposition 5

    Common mistake

    Binary search is only correct on sorted data. Running it on an unsorted array does not return a wrong index occasionally — it returns "not found" for values that are certainly present. Sorting first is a legitimate move, but it is a transform step with its own cost (1.3.2), and it only pays off if you search many times.

    Each comparison halves the interval, so the number of comparisons is the number of times n can be halved before one element is left. That is O(log n) — the second-cheapest class in the whole ordering chain (1.4.5).

    Note

    The lecture classifies binary search as divide and conquer; the tutorial revisits it under decrease and conquer, because only one half is ever explored — the other is thrown away, never solved. Both labels appear in this course. If an exam question asks, say which definition you are using.

    1.3 Other Strategies

    1.3.1 Decrease and conquer

    # Permalink to topic 1.3.1, Decrease and conquer
    • ● Slides
    • ● Tutorial
    • ✚ New demo for 2026

    This strategy exploits the relationship between a solution to a problem of a given size and a solution to a smaller problem. The difference from divide and conquer is the count: decrease and conquer produces one smaller instance, not several.

    Worked example: computing π8

    Brute force computes π × π × π × π × π × π × π × π, which requires 7 multiplications. Decrease and conquer notices that π8 = π4 × π4, and that π4 in turn is π2 × π2.

    The squaring chain

    π2 = π × π     π4 = π2 × π2     π8 = π4 × π4

    πk
    the value being built; each line reuses the line above it
    ×
    one multiplication — there are three of them in total, not seven

    Multiplication count for the squaring chain

    Multiplications used to reach π to the eighth power, counted line by line
    Line Computed from Multiplications this line Running total
    π2π and π11
    π4π2 and π212
    π8π4 and π413
    Brute forceπ multiplied by itself seven times77

    Thus we used 3 rather than 7 multiplications. The algorithm needs a slight modification for an odd exponent: for π9 we simply write π9 = π8 × π, compute as above, and then perform one additional multiplication.

    Two more examples from the lecture: Horner's method for evaluating polynomials, and insertion sort, which sorts n items by inserting one item into an already-sorted list of n−1.

    1.3.2 Transform and conquer

    # Permalink to topic 1.3.2, Transform and conquer
    • ● Slides
    • ● Tutorial

    Here we transform the problem so that it is easier to solve. The work moves from "solve this" to "restate this as something already solved".

    Example from mathematics: change of coordinates

    The integral over the unit disc D: x2 + y2 ≤ 1 is awkward in Cartesian coordinates because the domain is round and the limits are not constant. Transforming to cylindrical (polar) coordinates, x = r cos θ and y = r sin θ, makes both limits constant.

    The polar transform

    I = ∫D (x2 + y2) dx dy = ∫02π dθ ∫01 r2 · r dr = 2π · ¼ = π/2

    D
    the unit disc, x2 + y2 ≤ 1
    r, θ
    polar radius and angle, with x = r cos θ and y = r sin θ
    the extra r
    the Jacobian of the change of variables; it is why the integrand is r2 · r and not r2

    Example from computing: are two elements equal?

    Given an array such as [61, 17, 32, 4, 17], are any two of its elements equal? One strategy is to sort the array first (the transform), then check adjacent entries only.

    Duplicate detection by sorting, adjacent comparisons

    Duplicate detection on the sorted array [4, 17, 17, 32, 61]
    Check Comparison Values Result
    1a(1) = a(2)?4 = 17No — keep going
    2a(2) = a(3)?17 = 17Yes — a duplicate exists, stop

    Common mistake

    The slide says "Yes! Stop." and then "Keep going until you hit end of the array" on the next line, which reads as a contradiction. The rule that is actually meant: stop at the first adjacent pair that matches; if none matches by the end of the array, the elements are all distinct.

    Compare that with the brute-force approach, which tests every pair. Brute force makes n(n−1)/2 comparisons — for n = 5 that is 10. Sort-then-scan makes at most n−1 = 4 adjacent comparisons, but pays for the sort first. Which wins depends entirely on the cost of the sort, which is why this pairs with 1.4.7.

    A second example, from ISC 4220: solving linear systems by Gaussian elimination. There we transform a system into an upper triangular system, which is easy to solve by back substitution.

    1.3.3 Greedy algorithms

    # Permalink to topic 1.3.3, Greedy algorithms
    • ● Slides
    • ● Tutorial

    The strategy is to construct a solution through a sequence of steps. At each step we make the best local choice among all feasible choices available at that step, and the choice is irrevocable — once made, it cannot be subsequently changed.

    Definition

    Greedy algorithm
    An algorithm that builds a solution step by step, taking the locally best feasible option at each step and never reconsidering it. This technique is not as broad as the others and is used for optimization problems.

    Worked example: making change for 41 cents

    Suppose you have coins with the denominations 1c, 5c, 10c and 25c — the change problem faced by cashiers all over the world, where the criterion is to use as small a number of coins as possible. A greedy algorithm takes as many coins of the highest denomination as it can, then moves down.

    Greedy change-making for 41 cents

    Greedy change-making for 41c with denominations 1c, 5c, 10c, 25c — four coins

    Step 141c − (1) × 25c16c
    Step 216c − (1) × 10c6c
    Step 36c − (1) × 5c1c
    Step 41c − (1) × 1c0c

    1.3.4 When greedy fails (counterexamples)

    # Permalink to topic 1.3.4, When greedy fails (counterexamples)
    • ◐ Slides, partial
    • ● Tutorial

    Greedy algorithms are not always optimal. The lecture's counterexample removes the 5c coin: with denominations 1c, 10c and 25c, make change for 30c.

    Greedy change-making for 30 cents with the 5 cent coin missing

    Greedy change-making for 30c with denominations 1c, 10c, 25c — six coins, where three would do
    Step Operation Remaining
    Step 130c − (1) × 25c5c
    Step 25c − (5) × 1c0c
    Greedy total25 + 1 + 1 + 1 + 1 + 16 coins
    Optimal10 + 10 + 103 coins

    The greedy solution requires 6 coins. However, using three 10c coins is the optimal solution. The first choice — take the 25c because it is the biggest — is what does the damage, and greedy can never take it back.

    Key idea — the lecture's metaphor

    Scrabble versus chess. In Scrabble, the best strategy often is to simply play the highest-scoring word possible. In chess, capturing the most powerful piece is often not the best strategy. Greedy algorithms are narrower in scope; they are generally confined to optimization problems, and they need a structural proof before you can trust them.

    Note

    1.4 Efficiency Analysis

    1.4.1 Why efficiency matters (seconds to centuries)

    # Permalink to topic 1.4.1, Why efficiency matters
    • ● Slides
    • ● Tutorial

    Efficiency becomes critical when we solve large problems — that is, for large n. The obvious way to measure an algorithm is to time it: the speed of an algorithm can often be quantified by the wall-clock time, the actual amount of time taken to perform a job, as measured with a stopwatch.

    Unfortunately, that metric depends on things that have nothing to do with the algorithm: the actual implementation (how well it was coded); the language used (interpreted, compiled, vectorized); the computer and processor it ran on; and what else the machine was doing at the time.

    Definition

    Efficiency
    A platform-independent, instance-independent measure of computational cost whose predictive value improves as the input size is increased.

    Read the last clause again: efficiency is a claim about large inputs. It is deliberately silent about which of two algorithms is faster on ten items, and increasingly reliable about which is faster on ten million.

    1.4.3 Operation of interest and counting operations

    # Permalink to topic 1.4.3, Operation of interest and counting operations
    • ◐ Slides, partial
    • ● Tutorial
    • ✚ New demo for 2026
    • ★ Midterm

    Counting every machine instruction is hopeless and pointless. Instead, pick one operation of interest — the operation that the algorithm does most, and that all the other work is proportional to — and count only that. For a sort or a search, the key work is the comparison.

    Key idea — the quick hack

    You can usually read the answer straight off the loop nesting. Two nested for loops each running to n trigger the inner operation n2 times, so the asymptotic cost is O(n2). Three such nested loops give O(n3). For large n, the asymptotic cost does not care whether the loops run to n or n-1.

    Pseudocode Two nested loops, both running to n 
    for i = 1, n
    for j = 1, n
        some operation      <-- this is what we count
    end for j loop
end for i loop

    Now change one bound. If the inner loop j starts from i (or i-1, or i+1) instead of 1, then the count drops by about half — the lecture writes this as O(n2/2), which is still O(n2) once constants are dropped.

    Pseudocode Two nested loops, the inner one starting at i plus 1 
    for i = 1, n
    for j = i+1, n
        some operation      <-- triggered about half as often
    end for j loop
end for i loop

    1.4.4 Big-O notation

    # Permalink to topic 1.4.4, Big-O notation
    • ● Slides
    • ● Tutorial
    • ★ Midterm

    The scaling of the algorithm is often identified by the highest power of n. When the leading term in the work is a constant times n — for example 50n + 21 — we say the method grows linearly. It is order n, or written as O(n). Similarly, when the work is say 4n2 + 6n + 3 we say the method has quadratic growth in n, or equivalently is of order O(n2).

    Definition — the two simplification rules

    Drop lower-order terms
    n2/2 − n/2 becomes n2/2, because the quadratic term dominates once n is large.
    Drop constant factors
    n2/2 becomes n2, because a constant multiplier does not change the growth rate. Both ½n2 and 100n2 are O(n2).

    Worked reductions from an exact count to a Big-O class

    From an exact operation count to its Big-O class, applying the two rules in order

    Why the notation earns its keep

    You have heard of Moore's law: the number of transistors integrated on a chip doubled every 18 to 24 months for four decades, which allows us to solve bigger problems as chips improve. What is less widely known is that simultaneous improvements in algorithms have been of a similar magnitude.

    The standard example is the Discrete Fourier Transform. Computed directly it is O(n2); the Fast Fourier Transform (FFT) algorithm reduces it to O(n log n). At n = 106 that is the difference between 1012 operations and roughly 2 × 107 — a better return than four decades of hardware.

    Common mistake

    Big-O describes growth, not speed. An O(n log n) algorithm with an enormous constant can lose to an O(n2) algorithm on every input size you will ever run. The notation tells you who wins eventually; 1.4.7 is about finding out where "eventually" starts.

    1.4.5 Complexity classes

    # Permalink to topic 1.4.5, Complexity classes
    • ● Slides
    • ● Tutorial

    Asymptotically — that is, as n gets large — the growth classes fall into a fixed order. The lecture boxes this chain, and it is the thing to memorise.

    The ordering chain

    n < n log n < n2 < n3 < 2n < n!

    <
    read as "grows more slowly than", for large n — not as a comparison of two particular numbers
    n!
    n factorial: n × (n−1) × … × 2 × 1

    Why is O(n log n) preferable to O(n2)? Take the ratio and let n grow. By L'Hôpital's rule:

    The ratio vanishes

    limn → ∞ (n log n) / n2 = limn → ∞ (log n) / n = 0

    the limit being 0
    means n log n is eventually negligible compared with n2 — not that it is small

    1.4.6 Best-case vs. worst-case analysis

    # Permalink to topic 1.4.6, Best-case vs. worst-case analysis
    • ● Tutorial
    • ✚ New demo for 2026
    • ★ Midterm

    Two arrays of the same length can cost an algorithm very different amounts of work. Best-case and worst-case analysis pins that variation down instead of averaging it away.

    Definition

    Best case
    The smallest number of operations the algorithm performs over all inputs of size n. Name the input that achieves it — a best case with no example is not an answer.
    Worst case
    The largest number of operations over all inputs of size n. This is the guarantee: the algorithm will never be slower than this.
    Average case
    The expected number of operations, assuming some distribution over the inputs. It requires you to state that assumption, which is why it is the hardest of the three to defend.

    Best and worst cases for the four algorithms in this module

    Best and worst cases for this module's four algorithms, counted in comparisons
    Algorithm Best case Input that causes it Worst case Input that causes it
    Sequential search 1 comparison, O(1) The key is the first element n comparisons, O(n) The key is last, or absent
    Binary search 1 comparison, O(1) The key is the middle element ⌊log₂ n⌋ + 1, O(log n) The key is at an end, or absent
    Selection sort n(n−1)/2, O(n2) Any input — there is no early exit n(n−1)/2, O(n2) Any input
    Bubble sort, shortened sweeps n−1 comparisons, O(n) Already sorted — one sweep, no swaps, stop n(n−1)/2, O(n2) Sorted in reverse
    Bubble sort, full sweeps n−1 comparisons, O(n) Already sorted — one sweep, no swaps, stop (n−1)2, O(n2) Sorted in reverse

    Key idea

    Selection sort's best case equals its worst case, and bubble sort's does not. That single line is the answer to midterm Problem 1(b), and it follows directly from the two rules in 1.1.2 and 1.1.3: selection sort always scans the whole remaining suffix; bubble sort stops when a sweep makes no swaps.

    Common mistake

    "Best case" is not "small n". Both cases are stated for the same n — they differ in what the input contains, not in how big it is.

    1.5.2 Random protein sequence generation

    # Permalink to topic 1.5.2, Random protein sequence generation
    • ▣ Lab 04
    • ✚ New for 2026

    Lab 04 gives the search algorithms a job, and it starts by manufacturing the data to search. DNA is written in four nucleotides — A, G, C and T. A codon is a group of three consecutive nucleotides, and each codon names one amino acid. There are 43 = 64 possible codons; three of them (TAA, TAG, TGA) are stop codons that end the chain rather than adding an amino acid, leaving 61 coding codons for 20 amino acids — which is why most amino acids have more than one codon.

    Definition — the lab's generation procedure

    generate_random_protein(n)
    Returns a string of length 3n, where n is the number of amino acids. Start with an empty string. Generate three random integers in the range 1 to 4; let 1 represent A, 2 represent G, 3 represent C and 4 represent T, and read off the three-letter codon. If the codon is one of the three stop codons, discard it and generate a new one. Otherwise append it to the protein string, and repeat until the string has length 3n.

    Key idea — rejection sampling

    "Discard it and generate a new one" is a technique with a name: rejection sampling. You sample from an easy distribution — all 64 codons, uniformly — and throw away the draws that violate the constraint. Three of 64 codons are rejected, so about 4.7% of draws are wasted and a protein of n amino acids needs about 1.05n draws. The same idea reappears in M2 as the basis of Monte Carlo sampling.

    Common mistake

    Lab 04's test for this function only checks the length and that every character is one of A, T, C or G — it does not check that stop codons were excluded. Your code can pass the test and still be wrong. Verify the constraint yourself: generate a long protein and count the occurrences of TAA, TAG and TGA in the codon-aligned reading frame. The answer must be zero.

    This is sequential search (1.1.4) with a twist: the search key is not one value but a set of them, because an amino acid usually has several codons.

    Definition — the lab's counting function

    frequency_amino_acid(protein, amino_acid)
    Employs sequential search to count the number of occurrences of a given amino acid in a protein.     Note — exact strings matter

    The amino-acid name is matched exactly. The tests use 'Glutamic acid' and 'Aspartic acid' with a lowercase second word — matching the table, not the lab's introductory paragraph, which capitalises them. 'Stop codons', plural, is also a valid argument and must return 0 for a protein generated by 1.5.2.

    The cost is exactly the sequential-search cost. For a protein of n amino acids, the loop examines n codons and, for each, compares against however many codons that amino acid has — at most 6. So the count is O(n), with a constant factor between 1 and 6. Doubling the protein doubles the work.

    1.5.4 Codon tables and DNA–RNA translation

    # Permalink to topic 1.5.4, Codon tables and DNA–RNA translation
    • ▣ Lab 04
    • ✚ New for 2026

    The codon table is the lookup that turns three letters into an amino-acid name. In Lab 04 it is also the hidden bulk of the work: transcribing it into a Python dictionary is 21 entries and 64 codons of pure typing, and a single typo breaks one test assertion with no clue which.

    Key idea — this is a data-structure choice, not biology

    The table is a map from a name to a set of codons, which is what 1.5.3 needs. Inverting it — a map from a codon to a name — turns the counting problem from "scan the protein once per amino acid" into "scan the protein once, total". Building the inverse map is the transform-and-conquer move applied to your own data.

    DNA and RNA

    The codons above are written in DNA letters: A, C, G and T. In RNA the base thymine (T) is replaced by uracil (U), so transcription copies a DNA codon into an RNA codon by substituting every T with a U. The start codon is ATG in DNA and AUG in RNA — both mean Methionine. Lab 04 works entirely in DNA letters, so no translation step is needed there; the distinction matters only if you compare the lab's table against a biology reference, which will usually be written in RNA.
