    How to use this page

    These are practice problems built on the types of question the course sets, using the same data the Fall 2025 papers used. They are not a copy of any paper you will sit, and the numbers on a future exam will differ. What carries over is the shape: what you are asked to produce, what counts as working, and where the marks are.

    Key idea

    Both papers say the same thing in their instructions: no credit is given for an answer without a clear explanation or derivation. On the midterm, leaving a question blank earns 15 per cent; an answer that shows no understanding earns nothing. Showing the steps is not politeness, it is where most of the marks are.

    The worked solutions

    Each problem type ends with a Show the worked solution control. It is a standard disclosure: reach it with Tab, open and close it with Enter or Space, and your screen reader will announce whether it is expanded or collapsed. Nothing is hidden from assistive technology that is not also hidden visually.

    Common mistake

    Reading the solution first. The solutions below are complete, which makes them very easy to nod along to. Write your own answer on paper first, then open the disclosure and compare working, not just final answers — most of the marks are in the working.

    If you need this in another format

    Every problem on this page is real text: no image is needed to answer anything, every matrix is a real table with headers, and every code snippet is selectable. If you need the material as a document, in large print, or in braille, ask the instructor — you do not need to explain why. See the accessibility statement (Markdown file, opens outside the dashboard).

    Type 1 Sorting traces: bubble sort and selection sort

    # Permalink to problem type 1, sorting traces
    • ★ Midterm, 20 marks
    • ● M1 topics 1.1.2, 1.1.3, 1.4.6

    The question. Consider the sorting algorithms bubble sort and selection sort.

    1. (10 marks) Briefly explain the basic idea behind each algorithm, including how they compare and swap elements.
    2. (5 marks) Give the best-case and worst-case time complexities for both algorithms, and explain when each case occurs.
    3. (5 marks) Given the array [7, 3, 9, 4, 2, 10], show the first two passes of both bubble sort and selection sort.
    Show the worked solution for type 1, sorting traces

    (a) The two ideas.

    Bubble sort sweeps left to right comparing each adjacent pair and swapping them when they are out of order. One sweep carries the largest remaining element to the end — it “bubbles up”. Sweeps repeat until an entire sweep makes no swap at all.

    Selection sort takes the current position, finds the smallest element anywhere to its right, and swaps the two. The prefix to the left of the current position is sorted and never touched again. It performs at most one swap per position, but it always scans the whole remaining tail to find the minimum.

    (b) Best and worst case.

    Complexities, and when each case happens
    Algorithm Best case When Worst case When
    Bubble sort O(n) the array is already sorted, so the first sweep makes no swap and the algorithm stops after n − 1 comparisons O(n2) the array is in reverse order, so every pair is swapped on every sweep
    Selection sort O(n2) always — it makes n(n − 1)/2 comparisons regardless of the input, because it must scan the tail to be sure it has the minimum O(n2) always, for the same reason

    The mark for “explain when these cases occur” is the point of the question: selection sort has no cheap case, and that is the interesting difference between the two.

    (c) The first two passes on [7, 3, 9, 4, 2, 10].

    Bubble sort, every comparison of the first two sweeps
    Sweep Pair compared Swap? Array after
    17 and 3yes[3, 7, 9, 4, 2, 10]
    17 and 9no[3, 7, 9, 4, 2, 10]
    19 and 4yes[3, 7, 4, 9, 2, 10]
    19 and 2yes[3, 7, 4, 2, 9, 10]
    19 and 10no[3, 7, 4, 2, 9, 10]
    23 and 7no[3, 7, 4, 2, 9, 10]
    27 and 4yes[3, 4, 7, 2, 9, 10]
    27 and 2yes[3, 4, 2, 7, 9, 10]
    27 and 9no[3, 4, 2, 7, 9, 10]
    29 and 10no[3, 4, 2, 7, 9, 10]

    After two sweeps of bubble sort: [3, 4, 2, 7, 9, 10].

    Selection sort, the first two passes
    Pass Position being filled Smallest to its right Swap Array after
    112, at position 5swap positions 1 and 5[2, 3, 9, 4, 7, 10]
    223, already at position 2none needed[2, 3, 9, 4, 7, 10]

    After two passes of selection sort: [2, 3, 9, 4, 7, 10]. Note that pass 2 does the full scan and then performs no swap — the scan still happened, and it still costs.

    More on this: selection sort in M1 §1.1.2, bubble sort in §1.1.3, and the complexity comparator for the exact operation counts.

    Type 2 Random variables: PMF, CDF, expected value, variance

    # Permalink to problem type 2, random variables
    • ★ Midterm, 20 marks
    • ● M2 topics 2.3.1, 2.3.2, 2.3.4, 2.3.5, 2.3.6, 2.3.8

    The question. A random variable X takes the four values 1, 2, 3 and 4 with the probability mass function below.

    Probability mass function of X
    Value x p(X = x)
    10.15
    20.35
    30.25
    40.25
    1. (3 marks) Verify that these probabilities form a valid PMF.
    2. (5 marks) Calculate the cumulative distribution function of X at all points.
    3. (2 marks) What is the probability that X is less than or equal to 3?
    4. (5 marks) Calculate the expected value of X.
    5. (5 marks) Calculate the variance of X.

    Show your work for each part.

    Show the worked solution for type 2, random variables

    (a) Valid PMF. Two conditions. Every probability is non-negative: 0.15, 0.35, 0.25 and 0.25 all are. And they sum to one: 0.15 + 0.35 + 0.25 + 0.25 = 1.00. So it is a valid PMF.

    (b) The CDF. The CDF is a step function defined for every real x, not only at the four values — that is where the marks usually go missing.

    CDF of X, defined on the whole real line
    Range of x F(x) = P(X ≤ x) Working
    x < 10.00no value of X is that small
    1 ≤ x < 20.150.15
    2 ≤ x < 30.500.15 + 0.35
    3 ≤ x < 40.750.15 + 0.35 + 0.25
    x ≥ 41.000.15 + 0.35 + 0.25 + 0.25

    (c) P(X ≤ 3) = F(3) = 0.75.

    (d) Expected value.

    E[X] = 1(0.15) + 2(0.35) + 3(0.25) + 4(0.25) = 0.15 + 0.70 + 0.75 + 1.00 = 2.60.

    (e) Variance. Use Var(X) = E[X2] − (E[X])2.

    E[X2] = 1(0.15) + 4(0.35) + 9(0.25) + 16(0.25) = 0.15 + 1.40 + 2.25 + 4.00 = 7.80.

    (E[X])2 = 2.602 = 6.76, so Var(X) = 7.80 − 6.76 = 1.04.

    Checking by the definition gives the same number: 0.15(1−2.6)2 + 0.35(2−2.6)2 + 0.25(3−2.6)2 + 0.25(4−2.6)2 = 0.384 + 0.126 + 0.040 + 0.490 = 1.04.

    More on this: M2 §2.3 Distributions.

    Type 3 Counting the operation of interest

    # Permalink to problem type 3, counting the operation of interest
    • ★ Midterm, 20 marks
    • ● M1 topics 1.4.3, 1.4.4, 1.4.5

    The question. For each code snippet, do three things. (a, 1 mark) State the line number of the operation you consider the operation of interest. (b, 2 marks) Give the exact number of times it is executed, in terms of the input size n. (c, 2 marks) Express the time complexity in Big-O notation. Assume n is a positive integer.

    Python Code 1, 5 marks 
    1  total = 0
2  for i in range(n):
3      total += i
4  print(total)
    Python Code 2, 5 marks 
    1  for i in range(n):
2      for j in range(n):
3          if i == j:
4              print(i, j)
    Python Code 3, 5 marks 
    1  i = 1
2  while i < n:
3      print(i)
4      i *= 2
    Python Code 4, 5 marks 
    1  for i in range(n):
2      for j in range(i):
3          print(i, j)
    Show the worked solution for type 3, counting the operation of interest
    Operation of interest, exact count, and complexity class for each snippet
    Snippet Operation of interest Exact number of executions Big-O
    Code 1 line 3, total += i n O(n)
    Code 2 line 3, the comparison i == j n2 O(n2)
    Code 3 line 3, print(i) ⌊log2(n − 1)⌋ + 1 for n ≥ 2, and 0 for n = 1 O(log n)
    Code 4 line 3, print(i, j) n(n − 1)/2 O(n2)

    Code 1. The loop runs for i = 0 up to n − 1, so the body runs exactly n times. Linear.

    Code 2. Careful here: two different lines have two different counts, and only one of them is the operation of interest. The comparison on line 3 runs once for every pair, so n2 times. The print on line 4 runs only when i == j, which is n times. Either can be defended as “the operation of interest”, but the complexity of the snippet is set by the comparison: O(n2).

    Code 3. i takes the values 1, 2, 4, 8, …, and the loop continues while i < n. So the body runs once for every power of two strictly below n. For n = 8 that is 1, 2, 4 — three times — and ⌊log2 7⌋ + 1 = 2 + 1 = 3. Logarithmic.

    Code 4. The inner loop runs i times, and i goes from 0 to n − 1, so the body runs 0 + 1 + 2 + … + (n − 1) = n(n − 1)/2 times. That is half of n2, and half of a quadratic is still a quadratic: O(n2).

    Common mistake

    Answering Code 4 with n2. The exact count is worth 2 of the 5 marks and it is not n2 — the constant factor of one half is exactly what part (b) is testing, and part (c) is where it stops mattering.

    More on this: M1 §1.4 Efficiency analysis and the complexity comparator, where you can watch these classes separate as n grows.

    Type 4 Conditional probability and the law of total probability

    # Permalink to problem type 4, conditional probability
    • ★ Midterm, 20 marks
    • ● M2 topics 2.1.7, 2.1.10

    The question. You are studying how students in a computational science course use AI tools. You have gathered the following.

    The given probabilities
    Statement Probability
    A student has access to AI tools0.80
    Uses AI for legitimate learning, given AI access0.70
    Uses AI for academic dishonesty, given AI access0.25
    Traditional academic dishonesty, given no AI access0.15
    Seeks help from tutors or study groups, given no AI access0.60

    Define the events:

    • A: the student has AI access.
    • B: the student uses AI for legitimate learning.
    • C: the student engages in any form of academic dishonesty, AI-assisted or traditional.
    1. (10 marks) Calculate P(B).
    2. (10 marks) Calculate P(C).
    Show the worked solution for type 4, conditional probability

    (a) Legitimate learning use only happens among students with access, so B is contained in A and the multiplication rule applies directly:

    P(B) = P(A) × P(B given A) = 0.80 × 0.70 = 0.56.

    (b) Dishonesty can arise in two mutually exclusive ways — with access, or without it — so use the law of total probability over the partition {A, not A}, with P(not A) = 0.20:

    P(C) = P(A) × 0.25 + P(not A) × 0.15 = 0.80 × 0.25 + 0.20 × 0.15 = 0.20 + 0.03 = 0.23.

    Common mistake

    Using the 0.60 figure. “Seeks help from tutors” is a distractor: it is not a form of dishonesty and it does not appear in either answer. The other trap is forgetting P(not A) = 0.20 and adding 0.25 + 0.15 directly, which gives 0.40 and no marks.

    More on this: M2 §2.1 Probability fundamentals.

    Type 6 Monte Carlo integration: exact value, then pseudocode

    # Permalink to problem type 6, Monte Carlo integration
    • ★ Midterm, 20 marks, compulsory
    • ● M2 topics 2.5.1, 2.5.2, 2.5.4

    The question. Consider the definite integral of f(x) = cos(x) + sin(3x) from 0 to π/2.

    1. (5 marks) Calculate the exact value of this integral analytically. Show your work.
    2. (15 marks) Give detailed pseudocode for estimating this integral by the Monte Carlo method, covering: initialisation of variables (5 marks); how to generate random points within the integration limits (5 marks); and the calculation of the estimate (5 marks).

    This problem is compulsory: the instructions require it as one of the five problems you answer.

    Show the worked solution for type 6, Monte Carlo integration

    (a) The exact value. Integrate term by term.

    The integral of cos(x) is sin(x), which between 0 and π/2 gives sin(π/2) − sin(0) = 1 − 0 = 1.

    The integral of sin(3x) is −cos(3x)/3, which between 0 and π/2 gives −cos(3π/2)/3 + cos(0)/3 = −0/3 + 1/3 = 1/3.

    So the exact value is 1 + 1/3 = 4/3, which is about 1.3333. Keep this number: it is what your Monte Carlo estimate should approach, and quoting it is how you show the estimate works.

    (b) The pseudocode. The method rests on one identity: the integral equals the width of the interval times the average value of the function over it, and a random sample estimates that average.

    Monte Carlo estimate of a one-dimensional integral

    ∫ab f(x) dx  ≈  (b − a) · (1/N) ∑i=1N f(xi)

    a, b
    the integration limits, 0 and π/2 here
    N
    the number of sample points
    xi
    a point drawn uniformly at random from the interval [a, b]
    Pseudocode Monte Carlo estimate of the integral 
    # 1. Initialisation
a    = 0
b    = pi / 2
N    = 100000        # number of samples
seed = 42            # fixed so the run can be reproduced
set_random_seed(seed)
total = 0

# 2. Generate points inside the integration limits
repeat N times:
    u = uniform_random_in_[0,1)
    x = a + u * (b - a)     # maps [0,1) onto [a, b)
    total = total + (cos(x) + sin(3 * x))

# 3. Form the estimate
mean_value = total / N
estimate   = (b - a) * mean_value

report estimate                       # approaches 4/3 = 1.3333
report abs(estimate - 4/3)            # the error, which falls like 1/sqrt(N)

    Three things earn the marks and are easy to leave out. Seed the generator, so the run is reproducible. Map the uniform sample onto [a, b] rather than sampling [0, 1) and forgetting the interval. And multiply by the width (b − a) at the end — an average is not an integral.

    Note

    The error of this estimate falls like one over the square root of N, so 100 times more samples buys about one extra correct digit. That rate is independent of the dimension, which is exactly why Monte Carlo wins in high dimensions and loses in one.

    More on this: M2 §2.5 Monte Carlo methods.

    Type 7 Lines: parametric form, the s coordinate, closest point, distance

    # Permalink to problem type 7, lines and distances
    • ★ Final, 20 marks
    • ● M6 topics 6.1.2, 6.1.3, 6.1.4, 6.1.7, 6.1.8

    The question. Consider the line through the two points p1 = (2, 0) and p2 = (5, 4).

    1. (5 marks) Write a formula for a point p(s) on the line.
    2. (5 marks) Use the dot-product method to compute the s coordinate of the point p = (3.5, 2), which lies on the line.
    3. (5 marks) Find the point on the line closest to q = (1, 1).
    4. (5 marks) Compute how far q is from the line.
    Show the worked solution for type 7, lines and distances

    (a) Parametric form. Take the direction vector v = p2 − p1 = (5−2, 4−0) = (3, 4), whose length is √(9 + 16) = 5. Then

    p(s) = p1 + s v = (2 + 3s, 4s).

    With this normalisation, s = 0 is p1, s = 1 is p2, s between 0 and 1 is between them, and s outside [0, 1] is beyond one end.

    (b) The s coordinate of (3.5, 2). Project the offset onto the direction:

    p − p1 = (1.5, 2), and (1.5, 2) · (3, 4) = 4.5 + 8 = 12.5. Dividing by |v|2 = 25 gives s = 12.5 / 25 = 0.5.

    Sanity check: s = 0.5 predicts the point (2 + 1.5, 2) = (3.5, 2), which is what we were given, and it is the midpoint. If your course convention measures s in units of length along the line — dividing by |v| rather than |v|2 — the same point gives s = 2.5, which is half of the length 5. State which convention you are using.

    (c) Closest point to q = (1, 1). Same projection, different point:

    q − p1 = (−1, 1), and (−1, 1) · (3, 4) = −3 + 4 = 1. So s* = 1 / 25 = 0.04, and the closest point is

    p(0.04) = (2 + 3(0.04), 4(0.04)) = (2.12, 0.16).

    Because s* = 0.04 lies between 0 and 1, the closest point is genuinely between p1 and p2 — that is what the sign and size of s tell you.

    (d) Distance from q to the line. Either measure it directly or use the cross product; both give the same number, and doing both is a free check.

    Directly: q − p(0.04) = (1 − 2.12, 1 − 0.16) = (−1.12, 0.84), whose length is √(1.2544 + 0.7056) = √1.96 = 1.4.

    By cross product: |(−1)(4) − (1)(3)| / |v| = |−7| / 5 = 1.4.

    More on this: M6 §6.1 Points and lines.

    Type 8 Triangulating a polygon by ear clipping

    # Permalink to problem type 8, ear clipping
    • ★ Final, 5 marks
    • ● M6 topics 6.3.4, 6.3.5, 6.3.6

    The question. Explain how to triangulate the polygon below. Give the detailed steps of the algorithm — ear clipping — applied to this specific polygon, identifying which vertices are processed and in what order. You do not need to perform the exact numerical computations.

    The polygon is closed and has five vertices, listed in counter-clockwise order. Each side joins consecutive vertices in the list, and the last vertex joins back to the first.

    Vertex list of the polygon to be triangulated

    The polygon: four vertices are the corners of a 5 by 5 square, and the fifth, (2, 2), is a reflex vertex that notches the top edge downward into the interior. Signed area by the shoelace formula is +17.5, confirming the counter-clockwise order.
    Vertex Coordinates Interior angle Joined to
    v1(0, 0)convexv5 and v2
    v2(5, 0)convexv1 and v3
    v3(5, 5)convexv2 and v4
    v4(2, 2)reflex, greater than 180 degreesv3 and v5
    v5(0, 5)convexv4 and v1
    Show the worked solution for type 8, ear clipping

    The algorithm, stated first. An ear is a vertex that is convex and whose two neighbours can be joined by a straight segment that stays inside the polygon — equivalently, the triangle formed by the vertex and its two neighbours contains no other vertex of the polygon. The “polygons have ears” theorem guarantees that every simple polygon with more than three vertices has at least two ears, so the following always terminates.

    1. Walk the vertex list and classify each vertex as convex or reflex, using the sign of the cross product of the two edge vectors meeting there.
    2. Find a convex vertex whose triangle with its neighbours contains no other vertex. That is an ear.
    3. Output that triangle, delete the ear vertex from the list, and reclassify its two neighbours — removing a vertex can turn a reflex neighbour convex.
    4. Repeat until three vertices remain; they are the last triangle.

    A polygon with n vertices always yields n − 2 triangles, so this one gives three.

    Applied to this polygon.

    Ear clipping, step by step. Three triangles, whose areas sum to 17.5 — the area of the polygon.
    Step Vertex tested Verdict Triangle output Area Vertices remaining
    1 v1 (0, 0) not an ear — the triangle (0,5), (0,0), (5,0) contains the reflex vertex (2, 2) — — all five
    2 v4 (2, 2) skipped — it is reflex, so it can never be an ear — — all five
    3 v3 (5, 5) ear — convex, and the triangle (5,0), (5,5), (2,2) contains no other vertex (5,0), (5,5), (2,2) 7.5 v1, v2, v4, v5
    4 v2 (5, 0) ear — its neighbours are now v1 and v4, and the triangle (0,0), (5,0), (2,2) is empty (0,0), (5,0), (2,2) 5.0 v1, v4, v5
    5 — three vertices left, so they form the last triangle (0,0), (2,2), (0,5) 5.0 none

    The order matters only in that a reflex vertex is never an ear and a vertex whose triangle swallows another vertex is never an ear. Any order that respects those two rules produces a valid triangulation, though not necessarily the same one — which is exactly the point M6 makes when it introduces the Delaunay triangulation.

    Type 9 Decision trees: impurity, split tables, gain, Hunt's choice

    # Permalink to problem type 9, decision trees
    • ★ Final, 25 marks
    • ● M5 topics 5.6.3, 5.6.5–5.6.9

    The question. You are building a decision tree to classify tumours as Benign or Malignant from two attributes: tumour size in centimetres, and cell density, recorded as Low or High. You have six records.

    The six training records

    Training set: six records, two attributes, two classes
    Record Size (cm) Density Class
    16HighMalignant
    23LowBenign
    37HighMalignant
    42LowBenign
    58LowMalignant
    64HighBenign

    Make the Size attribute binary by splitting it at 5 cm: less than 5, and 5 or more. The split table for Size is given.

    The given split table for the Size attribute

    Given: how the Size split divides the six records
    Size Malignant Benign
    less than 503
    5 or more30
    1. (5 marks) Compute the impurity of the root node using classification error, E(t) = 1 − maxi p(i | t).
    2. (5 marks) Construct the equivalent split table for the Density attribute.
    3. (5 marks) Using classification error, compute the impurity of the two child nodes of the Size split. Give the four conditional probabilities first.
    4. (5 marks) Use the impurities to compute the gain of both possible splits.
    5. (5 marks) According to Hunt's algorithm, which split should be applied at the root?
    Show the worked solution for type 9, decision trees

    (a) Root impurity. The root holds all six records: three Malignant (1, 3, 5) and three Benign (2, 4, 6). So p(Malignant) = 3/6 = 0.5 and p(Benign) = 0.5, and

    E(root) = 1 − max(0.5, 0.5) = 1 − 0.5 = 0.5.

    0.5 is the largest classification error possible with two classes: a perfectly mixed node.

    (b) The Density split table. Density High covers records 1, 3 and 6; Density Low covers records 2, 4 and 5.

    How the Density split divides the six records
    Density Malignant Benign Records
    High211, 3 are Malignant; 6 is Benign
    Low125 is Malignant; 2, 4 are Benign

    (c) Impurity of the two Size children. The four conditional probabilities first:

    • p(Malignant | Size < 5) = 0/3 = 0
    • p(Benign | Size < 5) = 3/3 = 1
    • p(Malignant | Size ≥ 5) = 3/3 = 1
    • p(Benign | Size ≥ 5) = 0/3 = 0

    So E(Size < 5) = 1 − max(0, 1) = 0 and E(Size ≥ 5) = 1 − max(1, 0) = 0. Both children are pure.

    (d) Gain for both splits. Gain is the parent's impurity minus the weighted average of the children's, each weighted by the fraction of records it receives.

    Gain for the two candidate splits, using classification error
    Split Weighted child impurity Value Gain = 0.5 − that
    Size (3/6)(0) + (3/6)(0) 0.000 0.500
    Density (3/6)(1 − 2/3) + (3/6)(1 − 2/3) = (0.5)(1/3) + (0.5)(1/3) 0.333 0.167

    (e) Hunt's choice. Hunt's algorithm is greedy: at each node it takes the split with the largest gain and never revisits it. The Size split gains 0.5 against Density's 0.167, so split the root on Size, less than 5 versus 5 or more.

    Both children are then pure, so both become leaves — Size < 5 predicts Benign, Size ≥ 5 predicts Malignant — and the tree is finished after one split. Note that this outcome is luck of the data, not a guarantee: greedy tree construction gives no promise of the smallest or best tree. See the greedy gallery.

    2. (5 marks) Draw the dendrogram of the process, and be explicit about the distance at which each merge happens.

    • d({x3,x4}, x1) = min(8, 6) = 6
    • d({x3,x4}, x2) = min(5, 7) = 5
    • d({x3,x4}, x5) = min(5, 4) = 4

      x1 x2 {x3, x4} x5
    x10369
    x23057
    {x3, x4}6504
    x59740

    Merge 2, at distance 3. The smallest entry is now 3, between x1 and x2. Merge into {x1, x2}:

    • d({x1,x2}, {x3,x4}) = min(6, 5) = 5
    • d({x1,x2}, x5) = min(9, 7) = 7
    After merge 2: three clusters remain
      {x1, x2} {x3, x4} x5
    {x1, x2}057
    {x3, x4}504
    x5740

    Merge 3, at distance 4. The smallest entry is 4, between {x3, x4} and x5. Merge into {x3, x4, x5}:

    • d({x1,x2}, {x3,x4,x5}) = min(5, 7) = 5
    After merge 3: two clusters remain
      {x1, x2} {x3, x4, x5}
    {x1, x2}05
    {x3, x4, x5}50

    Merge 4, at distance 5. The last two clusters join, giving {x1, x2, x3, x4, x5}. The process is complete.

    (b) The dendrogram, as a table. A dendrogram is four merges at four heights; drawn or tabulated, the same four numbers are what is being marked.

    The dendrogram: which clusters join, and at what height
    Merge Clusters joined Height Resulting cluster
    1x3 and x42{x3, x4}

    To describe the drawing in words: five leaves along the bottom in the order x1, x2, x3, x4, x5. A bar joins x3 and x4 at height 2, and a bar joins x1 and x2 at height 3. The x3–x4 bar joins x5 at height 4. Finally the two remaining bars join at height 5, which is the root. Cutting the dendrogram anywhere between heights 4 and 5 gives the two-cluster solution {x1, x2} and {x3, x4, x5}.

    Common mistake

    Using the wrong linkage without noticing. Single linkage takes the minimum; complete linkage would take the maximum and would give different heights — 2, 3, 5 then 9 on this same matrix. Read the question and write down which rule you are using before you start.

    The question. Apply the Sobel operator below to the same 4 by 5 image as type 11. Show the computation for at least two pixels. Do not apply it to boundary pixels.

    The three by three Sobel kernel

    The kernel S, given in the question
    Kernel row Left Centre Right
    Top−1−2−1
    Middle000
    Bottom121

    Note

    The exam calls this “Sobel vertical edge detection”, but a kernel with zeros across the middle row differences the rows, so it responds to horizontal edges — it is the Gy operator. The instructor's own solution notes this. Answer with the kernel as printed and say in one line which edges it actually detects; that is worth more than silently transposing it.

    Show the worked solution for type 12, Sobel edge detection

    The response at a pixel is the sum of the nine neighbours each multiplied by the kernel entry sitting on it. Because the middle row is zero, only the row above and the row below contribute: the response is (row below, weighted 1 2 1) minus (row above, weighted 1 2 1).

    Worked pixel 1: row 2, column 3. The window is rows 1 to 3, columns 2 to 4:

    • row above: 4, 3, 5
    • row of the pixel: 0, 4, 15 — multiplied by zero, so ignored
    • row below: 3, 14, 2

    Response = [1(3) + 2(14) + 1(2)] − [1(4) + 2(3) + 1(5)] = [3 + 28 + 2] − [4 + 6 + 5] = 33 − 15 = +18.

    Worked pixel 2: row 3, column 4. The window is rows 2 to 4, columns 3 to 5:

    • row above: 4, 15, 3
    • row of the pixel: 14, 2, 4 — ignored
    • row below: 2, 4, 5

    Response = [1(2) + 2(4) + 1(5)] − [1(4) + 2(15) + 1(3)] = [2 + 8 + 5] − [4 + 30 + 3] = 15 − 37 = −22.

    All six interior pixels, for checking.

    Response of the given kernel at the six interior pixels. Large magnitude means a strong horizontal edge; the sign says which way the brightness steps.
    Pixel Response Magnitude
    row 2, col 2+99
    row 2, col 3+1818
    row 2, col 4+55

    row 3, col 3−1010

    The two largest magnitudes, 18 and 22, sit next to the noise spikes rather than next to any real structure — which is exactly why the median filter of type 11 is normally applied before edge detection, not after.

    Type 13 Morphology: dilation and erosion with a cross

    # Permalink to problem type 13, dilation and erosion
    • ★ Final, 10 marks
    • ◐ M4 topics 4.6.9–4.6.11 — assessed, but taught only in a supplementary deck

    The question. Below is a binary image, where 1 is foreground and 0 is background, and a 3 by 3 structuring element shaped like a cross.

    The binary image

    Binary image: 4 rows, 5 columns. Foreground pixels are at row 2 columns 2, 3 and 4, and row 3 column 3.
    Row Col 1 Col 2 Col 3 Col 4 Col 5
    100000
    201110
    300100
    400000

    The structuring element

    Structuring element S: a cross. Its centre and its four edge-neighbours are 1; its four corners are 0.
    SE row Left Centre Right
    Top010
    Middle111
    Bottom010
    1. (5 marks) Perform dilation of the image with S. Give the resulting binary image, explain at least one pixel in detail, and describe the effect of dilation.
    2. (5 marks) Perform erosion of the image with S. Give the resulting binary image, explain at least one pixel in detail, and describe the effect of erosion.
    Show the worked solution for type 13, dilation and erosion

    The two rules, in the form that makes them easy to apply by hand.

    • Dilation: centre the cross on a pixel; the output is 1 if any of the five cross positions covers a foreground pixel. Equivalently, mark every foreground pixel and each of its four edge-neighbours.
    • Erosion: centre the cross on a pixel; the output is 1 only if every one of the five cross positions covers a foreground pixel. A pixel survives only if it and all four of its edge-neighbours are foreground.

    The foreground is four pixels: (row 2, col 2), (row 2, col 3), (row 2, col 4) and (row 3, col 3).

    (a) Dilation. One pixel in detail: the output at (row 1, col 3). Centre the cross there. Its down position is (row 2, col 3), which is foreground. That single hit is enough, so the output is 1 — even though (row 1, col 3) is background in the input.

    After dilation: the cross has grown by one pixel in each of the four edge directions
    Row Col 1 Col 2 Col 3 Col 4 Col 5
    101110
    211111
    301110
    400100

    The object grew from 4 foreground pixels to 12. Effect of dilation: it thickens objects, closes small gaps and single-pixel holes, and joins components that were nearly touching. It also enlarges any noise speck by the same amount.

    (b) Erosion. One pixel in detail: the output at (row 2, col 3), the most promising candidate because it has the most foreground around it. The cross requires (row 2, col 3) itself — foreground, yes — plus (row 1, col 3) above it, which is background. One miss is enough, so the output is 0.

    After erosion: every pixel is 0, because the object is thinner than the structuring element
    Row Col 1 Col 2 Col 3 Col 4 Col 5
    100000
    200000
    300000
    400000

    The object vanishes entirely. Effect of erosion: it thins objects, removes isolated specks, and separates components joined by a thin bridge — but it deletes outright anything narrower than the structuring element, which is exactly what happened here. That is not a mistake in your working; state it as the result and say why.

    Key idea

    Dilation is “any”, erosion is “all”. If you can remember which quantifier goes with which name, you can derive both results at the exam desk without recalling any formula.
