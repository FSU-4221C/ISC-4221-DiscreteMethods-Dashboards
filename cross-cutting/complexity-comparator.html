    The ordering everything hangs on

    M1 ends with one boxed line, and the rest of the course quietly depends on it. Read it as: however large the constants, an algorithm further to the right in this chain eventually loses to one further to the left.

    Asymptotic ordering (M1 topic 1.4.5)

    n < n log n < n2 < n3 < 2n < n!

    n
    the problem size — see the next section, because it is a different thing in each module
    <
    read as “grows more slowly than, once n is large enough”, not as a comparison at one particular n

    The slides justify one link in that chain directly. Because log n divided by n tends to zero, the ratio of n log n to n2 tends to zero too, so n log n is genuinely the cheaper class — which is exactly why the Fast Fourier Transform replaced the direct Discrete Fourier Transform.

    Key idea

    Big-O is a statement about the shape of the cost curve, not about a number. Two algorithms in the same class can differ by a factor of a hundred and still be “the same” asymptotically; two algorithms in different classes swap places exactly once and then never swap back.

    Operation of interest, and what n means

    • ● Tutorial
    • ◐ Slides
    • ★ Midterm

    Before you can count anything you have to answer two questions, and the exam asks for both explicitly. First: what is the operation of interest — the one line whose executions you are going to count. Second: what is n — and this is where the three modules differ, because the same letter means a different thing in each.

    What n counts, per module

    The same letter, three different meanings
    Module n is Operation of interest
    M1 sorting and searching the number of entries in the list one comparison of two entries
    M3 graphs the number of nodes; m is the number of edges one distance comparison, or one cycle check
    M5 data mining the number of records; k is the number of clusters one distance evaluation between a record and a centre

    Common mistake

    Counting the wrong line. In a doubling loop, the operation of interest is the body, not the multiplication that advances the counter — but both run the same number of times, so the answer survives. In a nested loop whose inner bound is the outer index, the body runs n(n − 1) / 2 times, not n2 — half as often, and still O(n2).

    Note

    The Kruskal row assumes a complete graph, which is the worst case for the number of edges. On a sparse graph m is closer to n and Kruskal is much cheaper than the table suggests — that is the whole reason M3 spends a topic on space and time trade-offs between graph representations (topic 3.2.7).

    Constants lose in the end

    M1 makes the point with two invented cost formulas rather than two real algorithms, because the point is about arithmetic, not about sorting. Algorithm A costs 50n + 21 and algorithm B costs n2 + 10n + 5. B is cheaper for small n. Then, once and permanently, it is not.

    The two cost formulas (M1 topic 1.4.7)

    WA = 50n + 21,    WB = n2 + 10n + 5

    WA
    operations used by algorithm A on a problem of size n — linear growth
    WB
    operations used by algorithm B on a problem of size n — quadratic growth
    n
    problem size

    Common mistake

    The slide's closing sentence says B is superior for large n. It is the wrong way round: past the crossover, A — the linear one — is the cheap one, and the gap only widens. If your answer disagrees with the arithmetic, trust the arithmetic.

    How this is examined

    • ★ Midterm, Problem 3

    Midterm Problem 3 is worth 20 of the 100 marks and is four short code snippets, each scored three ways: name the operation of interest (1 mark), give the exact number of times it runs in terms of n (2 marks), and give the Big-O class (2 marks). Problem 1 part (b) asks for best-case and worst-case complexities of bubble and selection sort, which is the same skill applied to an algorithm you already know.
