    The pattern, in two sentences

    • ● Slides, M1
    • ● Tutorial

    Definition

    Greedy algorithm
    A solution built as a sequence of steps. At each step you make the best local choice among the feasible choices available at that step, and that choice is irrevocable — once made, it is never reconsidered.

    Reading a greedy algorithm therefore means answering exactly three questions. Every one of the four appearances below is just a different set of answers.

    1. What are the candidates? The set you choose from at each step.
    2. What does “best” mean? The single number you sort or minimise on.
    3. What makes a candidate feasible? The check that rules some out — and in two of the four cases, the check is what makes the whole thing correct.

    Key idea

    M1 offers the metaphor: scrabble versus chess. In scrabble, playing the highest-scoring word available is usually right. In chess, capturing the most valuable piece available usually is not. Greedy algorithms are scrabble algorithms; the question is always whether your problem is scrabble or chess.

    The gallery: four appearances

    The four greedy algorithms compared step by step

    The same three questions, answered four ways. The last column is the one that matters: two of these are provably optimal and two are not.
    Algorithm Where Candidates at each step “Best” means Feasibility check Optimal?
    Coin change M1 topic 1.3.3 the coin denominations the largest coin not bigger than what is left none Only for canonical systems. Fails for 30c with {1, 10, 25}
    Dijkstra M3 topics 3.5.5, 3.5.9 the nodes not yet connected the smallest tentative distance the distance must be finite Yes, provided no edge weight is negative
    Kruskal M3 topic 3.6.4 the edges not yet in the tree the shortest edge it must not close a cycle Yes. The cycle check is what makes it so
    Hunt's algorithm M5 topics 5.6.4, 5.6.5 the attribute splits available at this node the largest gain in purity the node must not already be pure No. Finding the optimal tree is exponentially hard, so the greedy tree is accepted as good enough

    Two patterns fall out of that table. First: the two provably optimal ones both have a real feasibility check, and the two that are not optimal have a weak check or none at all. Second: when greedy is not optimal, the course does not abandon it — it says so and uses it anyway, because the alternative is exponential.

    M1 — coin change, and where it breaks

    Where it works: 41 cents, United States coins

    Denominations 1c, 5c, 10c and 25c; make 41 cents with as few coins as possible. The greedy rule takes the largest coin that still fits, four times.

    Where it breaks: 30 cents with no nickel

    Now delete the 5c coin. Denominations are 1c, 10c and 25c; make 30 cents. The greedy rule still runs, still terminates, and still returns a correct amount — it is simply not the best answer.

    Greedy change for 30 cents when the 5 cent coin is missing

    Greedy change-making for 30c with denominations 1c, 10c and 25c — 6 coins, where 3 would do
    Step Operation Remaining
    Step 130c − (1) × 25c5c
    Step 25c − (5) × 1c0c

    Common mistake

    Greedy uses 6 coins here: one 25c and five 1c. The optimal answer is 3 coins: three 10c. Nothing went wrong in the execution — the first choice, the 25c, was locally best and permanently wrong. This is the counterexample the module is built around, and it is the reason “it terminated and gave an answer” is never evidence that a greedy algorithm is correct.

    M3 — Dijkstra: greedy, and provably right

    • ● Slides
    • ★ Midterm

    M3 states it plainly: Dijkstra is a greedy algorithm. At each step it takes the node that looks best — smallest tentative distance — with no regard for long-term strategy. Unlike coin change, that turns out to be safe, because once a node is fixed no later edge can shorten the route to it.

    The relaxation step (M3 topic 3.5.5)

    Dist(X) = min ( Dist(X), Dist(P) + Length(X, P) )

    P
    the node just connected — the greedy choice
    X
    an unconnected neighbour of P
    Length(X, P)
    the weight of the edge between them, infinite if there is no edge
    Dist(X)
    the shortest distance to X found so far

    The worked example from the slides has six nodes and eight edges. Its edge list is given in full below, so the trace can be checked without seeing the drawing.

    Note

    Two different slides print two different values for E at step 3 — one says 60, one says 65. The correct value is 60, because Dist(B) + Length(B, E) is 35 + 25. The final answer is unaffected: step 4 replaces it with 41 + 8 = 49 either way. If your working disagrees with a slide, redo the arithmetic before assuming you are wrong.

    Common mistake

    Dijkstra's greedy choice is only safe when no edge weight is negative. A negative edge could reduce a distance that has already been fixed, and fixed distances are never revisited — the irrevocability that makes it fast is exactly what makes it wrong there.

    M3 — Kruskal: the check is the proof

    • ● Slides
    • ▣ Lab 08

    Kruskal sorts every edge by length, then walks the sorted list adding any edge that does not close a cycle, until the tree has n − 1 edges. M3 classifies it as greedy in the same words it used for Dijkstra: take the edge that looks best, with the only check being that it cannot add a loop.

    Kruskal worked example, nine accepted edges and one rejected

    Kruskal on the M3 ten-node example. Nine edges are accepted and one, FG, is rejected because both endpoints were already in the tree. Total length 48.
    Step Edge Length Decision Running total
    1EF1accepted1
    2AF2accepted3
    3AB3accepted6
    4DI4accepted10
    5EH5accepted15
    6EG6accepted21
    —FG7rejected — closes a cycle21
    7CD8accepted29
    8IJ9accepted38
    9EI10accepted48

    The rejected row is the interesting one. FG is shorter than CD, IJ and EI, and greedy still refuses it — not because of any look-ahead, but because the feasibility test says no. That is the structural difference between Kruskal and coin change: Kruskal has a check that encodes what makes a partial solution extendable, and coin change has none.

    M5 — Hunt's algorithm: greedy on purpose, not by luck

    • ● Slides
    • ★ Final, Question 2

    M5 is unusually honest about this one. Many decision trees can be built from the same attributes; finding the best one is exponentially hard; so the course settles for a suboptimal result and builds the tree greedily. Hunt's algorithm recurses: if every record at a node has the same class, make it a leaf; otherwise pick an attribute test, split, and repeat on each child.

    “Best” here is the split that reduces impurity the most. Using classification error as the impurity measure, on the six-record data set from the final exam:

    Six training records with size, density and class

    The training set: six records, two attributes, two classes
    Record Size (cm) Density Class
    16HighMalignant
    23LowBenign
    37HighMalignant
    42LowBenign
    58LowMalignant
    64HighBenign
    Classification error as an impurity measure (M5 topic 5.6.8)

    E(t) = 1 − max1 ≤ i ≤ k p(i | t)

    t
    a node of the tree, holding some subset of the training records
    p(i | t)
    the fraction of records at node t whose class is i
    k
    the number of classes — two here, Malignant and Benign

    Impurity and gain for the two candidate splits

    The greedy choice at the root. The root holds 3 Malignant and 3 Benign, so its impurity is 0.5. Splitting on Size gains twice as much as splitting on Density, so Hunt's algorithm takes Size.
    Candidate split Left child E(left) Right child E(right) Weighted impurity Gain
    Size < 5 versus Size ≥ 5 records 2, 4, 6 — 0 Malignant, 3 Benign 0.000 records 1, 3, 5 — 3 Malignant, 0 Benign 0.000 0.000 0.500
    Density High versus Low records 1, 3, 6 — 2 Malignant, 1 Benign 0.333 records 2, 4, 5 — 1 Malignant, 2 Benign 0.333 0.333 0.167

    Both children of the Size split are pure, so Hunt's algorithm marks them as leaves and stops. Here the greedy choice happens to give a perfect tree — but nothing in the algorithm guaranteed that, and on a larger data set the first split that looks best often is not part of the smallest correct tree.

    Hunt's algorithm in M5 §5.6.5 · Impurity measures, §5.6.8 · Practise the full exam question

    So when is greedy safe?

    The course does not give a general theorem, and there is a reason for that: proving a greedy algorithm optimal is genuinely hard and is done per problem. What it does give you is a working habit.

    1. Write down the three answers — candidates, “best”, feasibility check.
    2. Look for the check. If there is no test that can reject a locally best candidate, be suspicious: coin change has none, and coin change is the one that fails.
    3. Try to break it with a small case. 30 cents with no nickel is four coins and a minute of arithmetic. A counterexample settles the question; a hundred successful runs do not.
    4. If it is not optimal, say so and use it anyway when the exact method is exponential. That is precisely M5's position on decision trees, and it is a legitimate engineering answer, not a failure.

    Key idea

    “It ran and produced an answer” is not evidence of correctness. Greedy coin change on 30c produces a perfectly valid set of coins totalling exactly 30c. It is just twice as many coins as necessary.
