# Dashboard Authoring Contract — ISC 4221C (2026)

**Read this before writing a single line of a module page.** Eight people are
building eight pages that have to look and behave like one product. This
document is the interface between them.

It is prescriptive on purpose. Where it says "copy this", copy it — do not
improve it. Where it explains *why*, that is so you can tell the difference
between a rule and a preference when you hit a case it does not cover.

**Source of truth for what to cover:** `../COURSE_TOPIC_MAP.md`.
**Source of truth for colour values:** `../standards/color-palette.md`.
**Source of truth for how colour and layout are applied:** `../standards/design-system.md`.
**Source of truth for describing a figure:** `../standards/alt-text-style-guide.md`.
**The gate you have to pass:** `../standards/artifact-checklist.md` §A10 and §D.

> §8.1 and §8.2 below carry the rules that came out of it; `REDESIGN-PLAN.md`
> is the record of what changed and why.

**To view your work:** open `index.html`. That is the whole instruction — no
server, no build step. `python3 tools/serve.py` exists and is worth using while

**Test by opening the file, every time.** That is how students will read it,
and it is the case a local server hides.

## 1. The nine rules

If you remember nothing else:

1. **Every figure has a non-visual equivalent.** A real `<table>` of the
   numbers, or a text summary in an `aria-live` region that updates when the
   figure updates. Not an `alt` string. Not a caption. The numbers.
2. **Every control has a programmatic label** — `<label for>` or `aria-label`.
   A placeholder is not a label. The 2025 apps had 76 visible labels and 0
   bindings; that is the single most repeated failure in this course.
3. **Colour is never the only encoding.** Every series, state, and verdict
   also carries a word, a shape, or a dash pattern.
4. **Never hardcode a colour or a font size.** Use the tokens in
   `assets/css/fsu-tokens.css`. If you type `#` followed by a hex digit in a
   CSS or JS file, you are doing something wrong.
5. **Nothing autoplays.** `demo.js` will not let it. Anything animated has
   Play/Pause and honours `prefers-reduced-motion`.
6. **One `<h1>` per page, no skipped levels.** h1 module → h2 group → h3 topic
   → h4 demo.
7. **No network requests, ever.** No CDN, no Google Fonts, no remote image,
   no `fetch()`. The dashboard must work from a USB stick with the Wi-Fi off.
8. **No framework, no bundler, no npm — and no ES modules.** Classic scripts
   publishing globals, loaded with `<script defer src>`. `type="module"` is
   banned outright: Chrome and Firefox refuse one from a `file://` address, so
   a single module script anywhere takes the whole runtime down for anyone who
   opened the folder. `build.py --check` fails on one. Data ships as a JS
   global for the same reason — `fetch()` is blocked under `file://` too.
9. **Python is a build tool, not a runtime.** Use it offline to generate SVGs,
   datasets, and precomputed traces. The browser never runs Python.

## 3. Page skeleton

### 3.1 Start from the template

Copy `_TEMPLATE.html`. It already contains the skip link, the site header, the
breadcrumb, both landmarks, the theme switch, the sidebar nav, the footer and
the script tags in the right order. Replace the `{{PLACEHOLDERS}}`, delete the
"SLOT" comment blocks you do not need, keep everything else.

### 3.2 The theme bootstrap is mandatory

Copy this into `<head>` verbatim, on every page:

```html
<script>
  (function () {
    try {
      var t = localStorage.getItem('isc4221c.theme');
      if (t === 'light' || t === 'dark') document.documentElement.setAttribute('data-theme', t);
    } catch (e) { /* storage unavailable; fall through to the OS preference */ }
  })();
</script>
```

ES modules are deferred, so `theme.js` runs *after* first paint. Without this
four-line bootstrap, a student who has chosen dark gets a white flash on every
navigation. It is the only inline script allowed anywhere in the dashboard.

### 3.3 Landmarks and headings

- Exactly one `<main id="main" tabindex="-1">`. The `tabindex="-1"` is what
  lets the skip link actually move focus.
- Exactly one `<h1>`, and it is the module title.
- Two `<nav>` elements: the primary one is `aria-label="Modules"`, the sidebar
  one is `aria-label="On this page"`. Two unlabelled navs on a page
  are indistinguishable in a screen reader's landmark list.
- Never `role="navigation"` on a `<nav>`, never `role="main"` on a `<main>`.
- Never label a landmark with its own type: `aria-label="Navigation"` on a
  `<nav>` announces "navigation navigation".

### 3.4 Page title

`<title>M3 Graphs — ISC 4221C Discrete Algorithms</title>`

Module first, because a screen-reader user hears the first few words of the
title when the page loads and needs to know where they landed.

## 4. Anchor id conventions — exact

Dots become dashes. Nothing else changes.

| Thing | Number | `id` | Example URL |
|---|---|---|---|
| Numbered group | 3.5 | `section-3-5` | `m3-graphs.html#section-3-5` |
| Numbered topic | 3.5.5 | `topic-3-5-5` | `m3-graphs.html#topic-3-5-5` |
| Demo | — | `demo-<slug>` | `m3-graphs.html#demo-dijkstra-trace` |
| Demo mount point | — | `demo-<slug>-mount` | (not linked) |
| Figure title | — | `fig-<slug>-title` | (not linked) |

Rules:

- **Every numbered topic in `COURSE_TOPIC_MAP.md` gets a section with its id**,
  even the ones with little to say. A missing anchor is a broken deep link from
  the slides, the labs, and the search index.
- Ids are unique across the page. `demo.js` derives every generated id from the
  demo's `id`, so a duplicate breaks every `for`/`aria-describedby` binding on
  the page at once — it validates this and refuses to render.
- The number also appears as **real text** inside the heading, in a
  `<span class="topic-section__number">`. Not a CSS `::before`: generated
  content is not reliably announced and cannot be selected or copied.

### 4.1 Topic section — copy this

```html
<section class="topic-section" id="topic-3-5-5" aria-labelledby="topic-3-5-5-title">

  <div class="topic-section__header">
    <h3 id="topic-3-5-5-title">
      <span class="topic-section__number">3.5.5</span>
      Dijkstra's algorithm
    </h3>
    <a class="topic-section__anchor" href="#topic-3-5-5">
      <span aria-hidden="true">#</span>
      <span class="visually-hidden">Permalink to topic 3.5.5, Dijkstra's algorithm</span>
    </a>
  </div>

  <ul class="pill-list">
    <li><span class="pill pill--full"><span class="pill__glyph" aria-hidden="true">●</span> Slides</span></li>
    <li><span class="pill pill--exam"><span class="pill__glyph" aria-hidden="true">★</span> Midterm</span></li>
  </ul>

  <div class="topic-section__body prose">
    <p>Fix the nearest unfixed node, relax every edge leaving it, and repeat
       until every node is fixed.</p>
  </div>

</section>
```

The permalink's accessible name is the whole phrase "Permalink to topic 3.5.5,
Dijkstra's algorithm" — not "#", and not "link". A screen-reader user listing
the links on the page has to be able to tell 55 of these apart (2.4.4).

## 5. The search index

`assets/js/search-index.js` already contains every module, every numbered
group, the threads and the standing pages. **You add your topic entries into
the block marked with your module number, and change nothing else in the file.**

### 5.1 The exact shape

```js
{
  id:          'topic-3-5-5',
  kind:        'topic',
  number:      '3.5.5',
  title:       "Dijkstra's algorithm",
  module:      'M3',
  moduleTitle: 'Graphs',
  url:         'm3-graphs.html#topic-3-5-5',
  summary:     'Fix the nearest unfixed node, relax its neighbours, repeat until every node is fixed',
  keywords:    ['dijkstra', 'shortest path', 'relaxation', 'greedy', 'priority queue', 'midterm']
}
```

Every field is required. None may be `null` or `''` except `number`, `module`
and `moduleTitle` on site-wide pages.

### 5.2 The rules the ranker depends on

- **`id` must equal the DOM `id`** the `url` fragment points at. Search results
  move keyboard focus to that element; a mismatch sends the user nowhere.
- `number` uses dots; `id` uses dashes. `search.js` normalises `3-5-5`,
  `3.5.5` and `topic 3.5.5` to the same thing, so students can type any of them.
- `summary` is one sentence a student would recognise, ≤ 160 characters. It is
  read aloud in the result list. Do not restate the title.
- `keywords` are the words a student would actually **type**, especially the
  ones not in the title: synonyms, the lecturer's phrasing, the lab number
  (`'lab08'`), the exam (`'midterm'`, `'final'`), and the old dashboard's name
  for the thing.
- Add a `kind: 'demo'` entry for every interactive demo, so a student can find
  the tool by name:

```js
{
  id:          'demo-dijkstra-trace',
  kind:        'demo',
  number:      '3.5.6',
  title:       'Dijkstra step-through',
  module:      'M3',
  moduleTitle: 'Graphs',
  url:         'm3-graphs.html#demo-dijkstra-trace',
  summary:     'Step through Dijkstra on a six-node graph and watch the working table fill in',
  keywords:    ['dijkstra', 'step through', 'trace', 'working table', 'interactive']
}
```

### 5.3 Check your work

From the browser console on any dashboard page:

```js
import('./assets/js/search-index.js').then(m => console.table(m.validateIndex()));
```

An empty table means the index is clean. The validator catches duplicate ids,
mismatched fragments, empty summaries, off-site URLs, and malformed topic
numbers.

## 6. Components — copy-pasteable markup

### 6.1 What to reach for

| You have | Use |
|---|---|
| A number, a state, a trace | **A data table.** Always. It is never wrong. |
| A picture that a table cannot express | A static figure **and** its table (§6.2) |
| Something the student should change and re-run | An interactive demo (§6.4) |
| A statement worth remembering | A callout (§6.5) |
| Maths | A formula block (§6.6) — never a raster |
| Code | A code block (§6.7) — never a screenshot |

### 6.2 Static figure with its data-table equivalent

Two elements, always together. The `<svg>` carries a short alt through
`<title>`; the table carries the numbers.

```html
<figure>
  <svg role="img" aria-labelledby="fig-dijkstra-ex-title" viewBox="0 0 480 300">
    <title id="fig-dijkstra-ex-title">Weighted graph with six nodes A to F; the
      shortest A-to-F path runs A, C, B, E, F and totals 165 kilometres.</title>
    <!-- shapes. Every node also carries a text label; no meaning is in colour alone. -->
  </svg>
  <figcaption>Figure 3.5.1. The worked example used throughout this section.</figcaption>
</figure>

<div class="table-scroll" role="region" tabindex="0" aria-labelledby="fig-dijkstra-ex-data">
  <p class="visually-hidden" id="fig-dijkstra-ex-data">Edge list for figure 3.5.1</p>
  <table class="data-table">
    <caption>Edge list for figure 3.5.1: six nodes, nine edges, weights in kilometres</caption>
    <thead>
      <tr>
        <th scope="col">From</th>
        <th scope="col">To</th>
        <th scope="col" class="is-numeric">Weight (km)</th>
      </tr>
    </thead>
    <tbody>
      <tr><th scope="row">A</th><td>B</td><td class="is-numeric">40</td></tr>
      <tr><th scope="row">A</th><td>C</td><td class="is-numeric">15</td></tr>
    </tbody>
  </table>
</div>
```

Non-negotiables:

- `role="img"` on the `<svg>` — without it, assistive tech walks the shape tree
  and announces nothing useful.
- `<title>` is the **first child** of the `<svg>` and states the **finding**,
  not the picture. "Weighted graph with nodes A to F" is a description of a
  drawing; "the shortest A-to-F path totals 165 km" is the information.
- Decorative SVG instead gets `aria-hidden="true" focusable="false"` and no
  `<title>`.
- The scroll wrapper is `role="region" tabindex="0"` with a label, so a
  keyboard-only user can reach the horizontal scrollbar (2.1.1, 1.4.10).
- `alt`/`<title>` and `<figcaption>` must not be the same string. The caption
  is the label; the alt is the finding.
- Text inside an SVG is real `<text>`, never a path. Baking text into an image
  fails 1.4.5.

### 6.3 A table on its own

Same as above without the figure. Requirements every time: a `<caption>`,
`<thead>` with `<th scope="col">`, `<th scope="row">` for the row key, units in
the header (`Weight (km)`) and not in every cell, and `class="is-numeric"` on
numeric columns so they right-align with tabular figures.

### 6.4 An interactive demo

The HTML is a mount containing a static fallback. `demo.js` replaces the
mount's children when it runs:

```html
<div id="demo-dijkstra-trace-mount">
  <div class="demo__fallback">
    <p><strong>Dijkstra step-through — interactive version not running.</strong>
       Either JavaScript is off, or this page was opened directly from a folder.
       The final state of the algorithm on the default graph is below.</p>
    <div class="table-scroll" role="region" tabindex="0"
         aria-label="Dijkstra working table, default graph, final state">
      <table class="data-table">
        <caption>Dijkstra on the default six-node graph, final state</caption>
        <thead>
          <tr><th scope="col">Node</th><th scope="col" class="is-numeric">Distance (km)</th><th scope="col">Predecessor</th></tr>
        </thead>
        <tbody>
          <tr><th scope="row">A</th><td class="is-numeric">0</td><td>—</td></tr>
        </tbody>
      </table>
    </div>
  </div>
</div>
```

The fallback is **not optional**, and it must be **inside the mount**, not in a
`<noscript>`. The two are not equivalent:

| Failure | `<noscript>` | in-mount fallback |
|---|---|---|
| Scripting disabled | fires | shows |
| A script that fails to load (missing, renamed, blocked) | **does not fire** | shows |

The second row is the one that bites, because `<noscript>` keys off the
*setting*, not off whether the script actually ran. A `<noscript>` twin leaves
a reader looking at an empty box; an in-mount fallback covers both failures
with one piece of markup.

Historically this row fired for everyone: the runtime was ES modules, and
Chrome and Firefox refuse one from a `file://` address, so opening the folder
meant every demo fell back. That cause is gone (rule 8), and the fallback now
covers only the ordinary cases. Keep writing it anyway — it is cheap, and it is
the only thing standing between a renamed file and a blank panel.

The same reasoning applies to the search box: the "search is not running" note
sits in the page as `<p class="search__nojs">` and `search.js` removes it once
it has wired itself up.

The JavaScript goes in `assets/js/demos/m3-graphs.js`:

```js
import { createDemo, svgEl, seededRandom, formatNumber } from '../demo.js';

createDemo('#demo-dijkstra-trace-mount', {
  id: 'demo-dijkstra-trace',
  title: 'Dijkstra step-through',
  description: 'Fix the nearest unfixed node, relax every edge leaving it, and repeat. ' +
               'Change the source and step through the working table.',
  headingLevel: 4,

  controls: [
    { type: 'select', name: 'source', label: 'Start node',
      options: [{ value: 'A', label: 'A' }, { value: 'B', label: 'B' }], value: 'A' },
    { type: 'range', name: 'weightAB', label: 'Weight of edge A to B',
      min: 5, max: 120, step: 5, value: 40, unit: 'km',
      valueText: (v) => `${v} kilometres`,
      help: 'Changing a weight re-runs the whole algorithm from step 1.' }
  ],

  compute(values) {
    // …return everything the figure, table and summary need, including the
    //    full step list. Pure function of `values`. No DOM access.
    return { steps: [...], nodes: [...], total: 165 };
  },

  steps: {
    count: (model) => model.steps.length,
    label: (model, i) => model.steps[i].description
  },

  figure(model, ctx) {
    const svg = svgEl('svg', { viewBox: '0 0 480 300' });
    // …build with svgEl(); never return a markup string.
    return svg;
  },

  // REQUIRED because figure() exists. The runtime writes this into the SVG's
  // <title> and wires aria-labelledby — you cannot forget it.
  figureAlt(model, ctx) {
    const s = model.steps[ctx.step];
    return `Step ${ctx.step + 1}: ${s.fixed} is fixed at ${s.distance} kilometres; ` +
           `${s.relaxed.length} neighbours were relaxed.`;
  },

  // REQUIRED, always.
  table(model, ctx) {
    return {
      caption: `Dijkstra working table after step ${ctx.step + 1} of ${ctx.stepCount}`,
      rowHeader: true,
      columns: [
        { label: 'Node' },
        { label: 'Distance', unit: 'km', numeric: true },
        { label: 'Predecessor' },
        { label: 'Status' }
      ],
      rows: model.steps[ctx.step].table.map((r) => ({
        cells: [r.node, r.distance === Infinity ? '∞' : r.distance, r.prev || '—', r.status],
        current: r.node === model.steps[ctx.step].fixed
      }))
    };
  },

  // REQUIRED, always. One string, or an array of paragraphs.
  summary(model, ctx) {
    const s = model.steps[ctx.step];
    return [
      `${s.fixedCount} of ${model.nodes.length} nodes are now fixed.`,
      `The shortest known distance to F is ${formatNumber(s.toF, 0)} kilometres.`
    ];
  }
});
```

What `demo.js` gives you for that, at no extra cost:

- labelled controls, with a slider **and** a typed number input for every range
- the figure **and** its data table, both always rendered, both always visible.
  There is no view toggle and there must not be one
- the toolbar in the right rail above the controls: "Copy data as CSV" and
  "Reset settings", which restores the dragged positions as well as the controls
- an `aria-live` summary that updates on every change and every step
- First / Previous / Play / Pause / Next / Last, a speed selector, and arrow-key
  operation when the figure has focus
- autoplay that is off and stays off until somebody presses Play
- `prefers-reduced-motion` handling, live-updated if the OS setting changes
- a "Copy data as CSV" button
- the live region dropping to `aria-live="off"` during playback and announcing
  the final state once when it stops

What it will refuse to do: render at all if `table()` or `summary()` is
missing, or if `figure()` exists without `figureAlt()`. You will get a red
panel naming the missing function and the criterion it fails.

**Demo rules:**

- `compute()` is pure. No DOM, no `Math.random()` without a seed control, no
  reading from the page.
- Anything random gets a `type:'seed'` control. Results have to be reproducible
  so a student can ask about *this* run in office hours.
- Every step description states the **delta** — what changed *this* step — not
  a restatement of the setup. "Step 3: C is fixed at 15 and relaxes B down from
  40 to 35" is right. "Dijkstra example" is not.
- `figureAlt` differs on every step. If the same sentence would describe steps
  2 and 3, the sentence is wrong.
- Do not set `id` to anything already on the page. `demo.js` checks.

### 6.4a A demo you can grab — `stage` instead of `figure`

`figure()` returns fresh SVG on every render. That is right for a picture, and
wrong for anything the reader should be able to hold: the node they are
dragging is destroyed by the next recompute. A `stage` demo builds one canvas
at mount, keeps it, and repaints.

**Use `stage` whenever a quantity in the demo has a position on screen.** A
slider says *this is a parameter*; a handle says *this is a thing*. Keep
sliders for quantities with no natural place in the picture — a noise level, an
iteration count, a sample size.

Read `assets/js/demos/m6-computational-geometry.js`, demo
`demo-line-parameter`, before writing one. It is the reference implementation
and it is commented as such.

```js
createDemo('#demo-thing-mount', {
  id: 'demo-thing',
  title: '…',
  caption: 'p and q are draggable. …',

  stage: {
    grab: 'drag p or q',              // REQUIRED. Three words naming the gesture.
    aspect: 0.62,                     // 0.50–0.65. Never past 0.72.
    world: { x: [-5, 13], y: [-3, 8] },
    state: { p: [1, 1], q: [4, 3] },  // persistent; handles own it

    handles: [                        // an array, or (model) => array
      { label: 'p', get: (m) => m.p, set: (x, y, m) => { m.state.p = [x, y]; } },
      { label: 'q', color: 'info', get: (m) => m.q,
        set: (x, y, m) => { m.state.q = [x, y]; },
        constrain: (x, y) => [x, Math.max(0, y)] }
    ],

    draw(g, m, ctx) { /* back to front, from state only */ }
  },

  compute(values, state) { … },        // second argument is the stage state
  figureAlt(model, ctx) { … },         // still REQUIRED
  table(model, ctx) { … },             // still REQUIRED
  summary(model, ctx) { … }            // still REQUIRED
});
```

**The rules, and why each one is here.**

| Rule | Why |
|---|---|
| Positions live in `stage.state`, never in `controls` | `values` is rebuilt on every recompute; a drag written there is discarded, and dragging appears not to work |
| `compute(values, state)` reads both | One model, one source of truth, whether the reader moved a slider or moved a point |
| `grab` is required | A reader who is not told the picture is draggable mostly will not find out. The runtime refuses to build a stage without it |
| Colours are token **keys** (`'ok'`, `'info'`, `'warn'`, `'accent'`), never hex | The light and dark ramps run in opposite directions; a hex value is correct on at most one canvas. `build.py --check` fails on a literal |
| `handles` may be a function of the model | For a figure whose point *count* the reader controls. It is re-derived per recompute, so adding a point adds a handle |
| Handles index `state`, not derived model fields | If the model reorders or relabels (a winding toggle, a sort), a handle writing through that mapping moves the wrong thing |
| One `Gfx.Stage` per demo | Two stages means two `ResizeObserver`s writing to the same grid row, and they fight. Multi-panel layouts offset world coordinates on one canvas |
| `draw` is pure with respect to state | It runs on every resize and every animation frame. A `draw` that mutates state produces a figure that drifts when the window moves |
| Guard the degenerate case in `compute` | `NaN` never throws. It reaches `lineTo(NaN, NaN)`, the canvas silently declines to draw, and you get a blank panel with a clean console — the hardest failure on this kind of page to find by looking at it |
| Name the degenerate state on screen | A collapsed triangle or a zero-length line is the most interesting part of the concept. Silence there reads as a broken demo |

**Draw order.** Back to front. Reordering this is the most common reason a
figure looks muddy:

1. grid — `C.lineSoft`, 1px
2. axes — `C.ink600`, 1px
3. reference geometry — dashed, alpha 0.3–0.5, the "before"
4. construction lines — dashed, the accent at alpha 0.5
5. primary geometry — full accent, 1.6–2.2px, the answer
6. markers — dots, squares, crosses
7. handles — drawn by the Stage, always on top
8. HUD text — `g.hud()`, pixel-positioned, never occluded

The rule underneath: **anything the reader is comparing against is dashed and
dimmed; the current state is solid and full strength.** Use `Gfx.alpha()` to
push something back, not a different colour — the colour carries meaning, and
swapping it silently changes what the mark says.

**Put the invariant on screen.** If the demo claims a quantity does not change,
compute it live and print it to four or more decimals. A reader dragging for
ten seconds while the number refuses to move is a stronger argument than any
sentence, and it fails loudly if the maths later rots. Show the residual
(`1.2e-13`), never a rounded zero — `≈ 0` could be hiding a bug.

**Keyboard is not optional and not your problem.** The runtime gives the canvas
one tab stop, moves the selected handle with the arrow keys (1% of the world
per press, 10% with Shift), cycles handles with Enter, draws a focus ring on
the selected handle, and announces selection through the live region. You get
that by declaring handles. Do not add a second tab stop per handle — twenty
demos with four handles each would put eighty stops between the reader and the
next paragraph.

### 6.5 Callouts

Four variants; each carries its word in `.callout__title`. The border style
differs per variant, so the distinction survives greyscale printing, colour
vision deficiency, and Windows High Contrast Mode.

```html
<div class="callout callout--key">
  <p class="callout__title">Key idea</p>
  <p>Dijkstra is greedy: once a node is fixed, its distance never changes again.</p>
</div>

<div class="callout callout--definition">
  <p class="callout__title">Definition</p>
  <dl>
    <dt>Relaxation</dt>
    <dd>Replacing the current best distance to a node with a shorter one found
        through a newly fixed neighbour.</dd>
  </dl>
</div>

<div class="callout callout--warning">
  <p class="callout__title">Common mistake</p>
  <p>Dijkstra fails on graphs with negative edge weights. The greedy choice is
     only safe when no later edge can reduce a fixed distance.</p>
</div>

<div class="callout callout--note">
  <p class="callout__title">Note</p>
  <p>The slides call this the "edge-length matrix"; the tutorial calls it the
     weight matrix. Same object.</p>
</div>
```

If you add an icon, it is `aria-hidden="true" focusable="false"` and the title
text still carries the whole meaning on its own.

### 6.6 Formulas

Real text, never a raster. `role="math"` plus an `aria-label` that spells the
expression out the way you would read it aloud, and a `<dl>` defining every
symbol — the "where" list is not optional.

```html
<div class="formula" role="math"
     aria-label="d of v is set to the minimum of d of v, and d of u plus w of u v">
  <span class="formula__label">Relaxation step</span>
  <p class="formula__expr">
    <var>d</var>(<var>v</var>) &larr; min&thinsp;(
      <var>d</var>(<var>v</var>),
      <var>d</var>(<var>u</var>) + <var>w</var>(<var>u</var>,&thinsp;<var>v</var>)
    )
  </p>
  <dl class="formula__where">
    <dt><var>u</var></dt><dd>the node just fixed</dd>
    <dt><var>v</var></dt><dd>a neighbour of <var>u</var> that is not yet fixed</dd>
    <dt><var>w</var>(<var>u</var>,&thinsp;<var>v</var>)</dt><dd>weight of the edge from u to v, in kilometres</dd>
    <dt><var>d</var>(<var>v</var>)</dt><dd>best distance to v found so far</dd>
  </dl>
</div>
```

- Variables go in `<var>`, not `<i>`.
- MathML is allowed and preferred for anything with a fraction, a radical, or a
  summation. Keep the `aria-label` fallback either way — MathML support is
  uneven and the label costs nothing.
- A table of numbers is never a formula and never an image. A simplex tableau
  is a `<table>`.

### 6.7 Code

```html
<div class="code-block">
  <div class="code-block__header">
    <span class="code-block__lang">Python</span>
    <span id="code-dijkstra-label">Dijkstra, main loop</span>
  </div>
  <pre tabindex="0" role="region" aria-labelledby="code-dijkstra-label"><code>while unfixed:
    u = min(unfixed, key=dist.get)
    unfixed.remove(u)
    for v, w in graph[u]:
        if dist[u] + w &lt; dist[v]:
            dist[v] = dist[u] + w
            prev[v] = u</code></pre>
</div>
```

- Real selectable text. Never a screenshot of an editor or a terminal (1.4.5).
- `<pre>` is `tabindex="0"` and labelled, because it scrolls horizontally.
- Escape `<`, `>` and `&` inside `<code>`.
- Syntax colour comes from the vendored local Prism copy in
  `assets/js/vendor/prism.js` plus `assets/js/highlight.js`. It reads the
  language from `.code-block__lang`. Do not add a CDN, an autoloader, or
  `language-*` classes by hand.
- Colour is never the only cue: keywords are also bold, comments are also
  italic, and the language label stays in the header. Token colours are FSU
  tokens, not Prism's default theme.

### 6.9 Links that leave the dashboard

The dashboard is offline-first. Any link that leaves it — a Markdown file in
the repo, a course resource on the web — says so in text:

```html
<a class="link-external" href="../ACCESSIBILITY_STATEMENT.md">
  Accessibility statement<span class="visually-hidden"> (Markdown file, opens outside the dashboard)</span>
</a>
```

The `↗` arrow that `.link-external` adds is decoration. The visually-hidden
span is what actually tells somebody. Do not use `target="_blank"` — opening a
new window without warning is a 3.2.5 problem, and the back button is how
students navigate.

## 7. The search block

Copy this wherever you want a search box. `search.js` finds every
`[data-search]` on the page and wires it independently.

```html
<section class="search" data-search data-search-limit="8" aria-label="Search the course">
  <form class="search__form" role="search">
    <div class="search__field">
      <label class="search__label" for="side-search">Search all topics</label>
      <input class="search__input" id="side-search" name="q" type="search"
             autocomplete="off" spellcheck="false" data-search-input>
    </div>
  </form>
  <p class="search__status" role="status" aria-live="polite" data-search-status></p>
  <ul class="search__results" data-search-results aria-label="Search results"></ul>
</section>
```

- The `id` on the input must be unique on the page — if you use two search

- The status paragraph must exist in the DOM **before** any result is written.
  A live region created together with its content announces nothing (4.1.3).
- `data-search-limit` is optional; the default is 25.

## 8. Colour and tokens

- **Every colour comes from `fsu-tokens.css`.** No hex, no `rgb()`, no named
  CSS colours in your files — not in CSS, not in JS, not in an inline
  `style=`, not in a generated SVG.
- Chart series use `--fsu-series-1` … `--fsu-series-6` **in that order**, so a
  chart with four or fewer series stays at least 70% FSU primary. Series 1–2,
  2–3 and 3–4 are distinguishable by luminance alone, which is what makes the
  sequence survive greyscale and colour vision deficiency.
- **Never dim text with `opacity` or a colour-mix.** That silently drops the
  measured ratio and there is no token for it. Use `--fsu-color-caption`
  (7.44:1 on white) when you want quieter text.
- Never lighten FSU Garnet and never darken FSU Gold. Warm surfaces come from
  the gold tint ramp (`--fsu-surface-warm`); darker states come from Plaza
  Brick (`--fsu-surface-brand-deep`).
- Never claim a contrast ratio that is not in `../standards/color-palette.md`.
  If you need a new pairing, it gets measured there first with
  `../tools/contrast.py`. Do not estimate.
- Interactive targets are at least 24×24 CSS px (2.5.8). Grow the hit area with
  padding or a pseudo-element; do not inflate the visible control.

### 8.1 How those colours are allowed to be used

`../standards/color-palette.md` says what the colours *are*.
`../standards/design-system.md` says where they may *appear*, and it is the
document that stops a page passing every contrast check and still looking like
a departmental flyer. The short version:

- **Garnet is ink, gold is a mark, white is the room.** No garnet fill larger
  than a button — the footer is the one exception. Gold at 2px or as a dot,
  never a 4px band, never twice in the same block.
- **A colour must mean something**: a state, a role, or a data series. Nothing
  is coloured for variety, and **modules are not colour-coded**.
- **One radius**, `--fsu-radius` (3px). `--fsu-radius-pill` is for status dots
  and count badges only. `--fsu-radius-sm` and `--fsu-radius-lg` are deprecated
  aliases; do not introduce new uses.
- **No shadows.** Depth is a step up the `--fsu-paper*` ramp, or a hairline
  (`--fsu-line-soft` / `--fsu-line` / `--fsu-line-strong`). The only permitted
  `box-shadow` is the focus-ring halo and a genuinely floating layer.
- **One `.btn--primary` per page.** A demo panel's Play button is the one
  exception, and `demo.js` creates it for you.
- Counts go in **one bordered strip divided by hairlines**, not a row of
  floating cards.

`build.py --check` audits all of these against the CSS and the markup. §11
below will fail you on them.

### 8.2 The two layout laws

Both are in `../standards/design-system.md` §6, both are already implemented in
`dashboard.css`, `demo.js` and `nav.js`, and neither is a preference.

**Law 1 — prose goes under the visualization, never beside it.** Anything you
would call a sentence goes in `.demo__explain`, full width, below the stage.
The control rail holds control labels and at most a 90-character hint bound to
one control. `demo.js` warns in the console when you exceed that; the warnings
are actionable, not noise.

**Law 2 — navigation gets its own row and cannot wrap.** Do not change
`flex-wrap: nowrap` or `justify-content: safe center` on `.chapter-nav__list`.
Plain `center` centres the overflow too, which puts the first item permanently
out of reach. Items carry two labels; the short one is `aria-hidden` and the
full one is only ever hidden *visually*, so the accessible name never
collapses.

Concretely, the header is:

- **Row 1** (`.site-header__bar`) — the wordmark, and the light/dark switch
  pushed to the right edge by an auto margin. Scrolls away.
- **Row 2** (`.chapter-nav`) — every chapter, at once, **sticky**. A chapter's
  sections are behind a dropdown rather than on the strip, which is what makes
  "all of them visible" and "one line" compatible.

Both rows are written by `tools/rebuild_header.py`; do not hand-edit a header.
The dropdown contents come from `assets/js/nav-map.js`, generated from the
pages by `tools/generate_nav_map.py` — **rerun it after adding or renaming a
topic group**, or the menu will point at an anchor that no longer exists.

Two things follow from the strip being sticky, and both are already handled —
do not undo them:

- `--fsu-sticky-offset` is set to the strip's height in `dashboard.css`, and
  every anchor target's `scroll-margin-block-start` reads it. Without that the
  browser scrolls a heading to the top of the viewport and the strip covers it
  (2.4.11 Focus Not Obscured).
- `.layout__sidebar`'s sticky offset clears the strip for the same reason.

## 9. Writing the words

Read `../standards/alt-text-style-guide.md` §4 for the genre recipes. The short
version, for the three things you will write most:

**Algorithm trace / step-through** (§4a): which algorithm and which step →
what changed *this* step → why → the resulting state, briefly. The first step
establishes the setup; every later one states the delta. The same image on five
slides gets five different descriptions.

**Graph diagram** (§4b): what the graph represents → its size (n nodes, m
edges) → the structural property being illustrated → where the edge list is.
Push the edge weights into a table rather than trying to fit six edges into 150
characters.

**Scatter / convergence plot** (§4c): what is plotted on each axis with units →
the trend → the number that matters. "Monte Carlo error falls as one over the
square root of n" is the finding; "a scatter plot with points" is not.

Phrases that are always wrong: "image of", "graph showing", "see figure",
"as shown above", a bare filename, and the same sentence used twice in a
sequence.

## 10. Python is a build tool

Generate offline, ship static. Your Python may:

- render SVG figures into `assets/figures/m<N>/`
- write datasets into `assets/data/m<N>/` as JSON or CSV
- precompute an algorithm trace so the browser only has to index into it

Your Python may **not** run in the browser, be fetched at runtime, or be
required to view the page. Every generator lives in `Dashboard/tools/`, is
deterministic (seeded), and records the command that produced each artefact.

**"Not required to view the page" is a hard test, and it is now enforced.**
The single measure of it: does the dashboard work when you double-click
`index.html`? For a long time the answer was no — not because of Python, but
because the runtime was written as ES modules, and Chrome and Firefox refuse a
module script from a `file://` address. Every interactive fell back to its
static table for any reader who opened the folder instead of a server, and the
README described that as acceptable. It was not.

So: **classic scripts publishing globals, never `<script type="module">`, and
never `fetch()`.** Data ships as a JavaScript global (`window.DATA_X = …`)
written by the generator, because `fetch()` is blocked under `file://` too.
`build.py --check` fails on a module script in any page. `tools/serve.py` still
exists and is still useful while editing — it disables caching — but it is a
convenience, not a prerequisite.

There is also a **prefer-live rule** that matters more than it looks: where the
algorithm is cheap enough to run in the browser, run it there rather than
replaying a precomputed trace. A demo that plays back a recording cannot answer
"what if", which is the only question worth building an interactive for. Reach
for a precomputed trace when the computation is genuinely too expensive for a
drag — and then use the stored result to cross-check the live one and show the
residual, which is a more honest thing to display than a rounded zero.

Generated SVG obeys the same rules as hand-written SVG: tokens for colour,
real `<text>` nodes, `role="img"`, a `<title>` first child, no baked-in text
images, and a data table shipped alongside.

## 11. Before you say you are finished

Work down this list on your actual page, in a browser.

**Structure**

- [ ] Exactly one `<h1>`; no heading level is skipped
- [ ] Every numbered topic from `COURSE_TOPIC_MAP.md` has a section with the
      right `id`
- [ ] Both `<nav>`s are labelled, and differently
- [ ] The skip link is the first thing in `<body>` and becomes visible on focus

**Keyboard**

- [ ] Tab from the address bar to the footer without a mouse. Every control is
      reachable, nothing is trapped, focus is always visible
- [ ] Every step-through works with Left/Right/Home/End when the figure has focus
- [ ] Every scrollable table and `<pre>` can be scrolled from the keyboard
- [ ] Escape closes the mobile nav and returns focus to its button

**Figures and data**

- [ ] Every figure has a data table or a live text summary. Count them: figures
      and equivalents should be the same number
- [ ] Every `<svg>` is either `role="img"` with a `<title>` first child, or
      `aria-hidden="true" focusable="false"`
- [ ] No meaning is carried by colour alone anywhere

**Motion**

- [ ] Nothing starts moving on load
- [ ] Every animation has Play/Pause, and playback stops when you change a control
- [ ] With `prefers-reduced-motion: reduce` set in the OS, the page is calm and
      the demo still works

**Layout**

- [ ] At a 320 px viewport width there is no horizontal page scroll (tables and
      code may scroll inside their own containers)
- [ ] Every button, tab stop and custom control is at least 24×24 CSS px.
      **Links inside a sentence are exempt** — 2.5.8 has an explicit "Inline"
      exception for targets whose size is constrained by the line-height of the
      surrounding text. An in-prose link measuring 22 px tall is not a defect;
      a 20 px icon button is
- [ ] At 400% zoom nothing overlaps or is clipped
- [ ] With the text-spacing bookmarklet applied (line-height 1.5, paragraph
      spacing 2×, letter-spacing 0.12×, word-spacing 0.16×) nothing is clipped

**Offline and tokens**

- [ ] `grep -rn "https\?://" your-page.html assets/js/demos/your-module.js`
      returns nothing but links to local files or `../*.md`
- [ ] `grep -nE "#[0-9a-fA-F]{3,8}\b" your files` returns nothing
- [ ] Open the page with the network disabled. It works.
- [ ] Open the page with JavaScript disabled. Every demo shows its fallback
      table and every one is readable — no empty boxes

**Automated**

- [ ] axe DevTools (or Pa11y) reports no critical or serious violations
- [ ] `validateIndex()` returns an empty array

## 12. What will get a page sent back

Not style preferences — these are the defects this project exists to fix.

1. A figure with no data table and no live text summary.
2. A control with no `<label for>` or `aria-label`.
3. A hardcoded colour, or a contrast ratio quoted that is not in
   `color-palette.md`.
4. Any external URL, `fetch()`, CDN link, or web font.
5. `outline: none` without a replacement indicator.
6. Anything that animates on load, or that cannot be paused.
7. A numbered topic from the topic map with no section on the page.
8. A second `<h1>`, or a skipped heading level.
9. A search-index entry whose `id` does not match its `url` fragment.
10. Text baked into an image — a formula, a tableau, a code sample, or a table
    shipped as a raster.
